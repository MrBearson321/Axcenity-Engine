# editor

The `axcenity-editor` binary: an eframe 0.32 (egui) app. Phase 15: select, insert, move/scale/rotate, edit, rename, duplicate, delete and reparent, undo/redo, save, Play/Stop, script tabs, LocalScripts, ModuleScripts, RemoteEvents and wrong-side warnings. Design notes: `docs/architecture.md` (Editor).

- `main.rs`: optional project folder argument, then `eframe::run_native` with the wgpu renderer (the viewport needs eframe's wgpu device).
- `app.rs`: `EditorApp` holds the `World`, project, `selected`, `history`, `tool`, `snap` and the panels. **Every world change goes through `change(id, key, label, edits)`** (from `apply` for Properties, `apply_gizmo` for handles), which records it in `history`. Unsaved = `!history.is_saved()`. `shortcuts(ctx)` reads undo/redo/tool keys and is testable with a bare `egui::Context`. Panel order in `update`: menu, toolbar, right side (Properties under Explorer), Output, viewport; at the end the open undo step is sealed unless a pointer or text box is busy.
- `play.rs`: `Session` (a cloned `World` + `ScriptRuntime` + `Physics`): `start`, `frame(seconds, keys, camera)` (frame steps 1-4, returns a script's camera move), `world()`. `GameKeys::read` turns egui key events into `KeyEvent`s. Every call is wrapped in `guard` (`catch_unwind`), so a panic becomes a `Crash` and the app drops the session. `read_scripts` re-reads script files at Play. In `app.rs`: `play`/`stop`/`play_frame`/`crashed`, and `shown(&world, &play)` picks the world panels draw (a free function so it borrows only those two fields). While playing, `change`, `act`, `undo`/`redo` return early, and panels get `editable = false` (viewport: `tool = None`). Tests that press Play after an edit must use `copy_of_example`: Play autosaves.
- `app/files.rs` (more `impl EditorApp`): `save` (world + unsaved tabs), script insert/open/rename/delete (file operations, never undo steps), `check_disk`/`disk_changed` (outside changes, compared by text so own saves do nothing; paused during Play). Tests drive `disk_changed` directly; app test helpers are `pub(super)` for them.
- `side_warnings.rs`: `side_warnings(source, class)` and `WarningCache`; the app fills `explorer.warnings` and `tabs.warnings` each frame (`update_warnings`). Scripts are Script, LocalScript *or* ModuleScript: test with `class.is_script()`, never `== Script`. ModuleScripts live in ReplicatedStorage, a saved service, so `sort_scripts` puts scripts after the saved children.
- `scripts.rs`: `ScriptTabs`/`ScriptTab` keyed by file path (`saved` = file text, `Disk` = changed/deleted elsewhere), tab bar, code editor (gutter + `TextEdit`, no wrapping). `lua_syntax.rs`: tokenizer + colors; add new engine globals to `BUILTINS`. `watcher.rs`: polling thread (0.5 s), wakes egui via `wake(ctx)`.
- `history.rs`: `History` of `Step`s: `Fields` (before/after values per `Field`, from `snapshot`) or `Tree` (`Move`s: `Place` before/after, `None` = out of the tree). Deleting only detaches, so IDs stay valid for undo; `push` destroys Instances of undone inserts when redo is cleared. `record` merges into the open step for the same Instance and field; `seal` ends the gesture. `mark_saved`/`is_saved` compare step numbers, so saving never clears undo.
- `gizmo.rs`: `Tool`, `Snap`, `Handle`, `Pose`; `shapes` (handles in screen points), `hovered`, `paint`; `Drag::start/update` turns mouse rays into new property values. Pure math, tested with rays.
- `placing.rs`: `PlaceDrag::start(world, part, grabbed)` / `update(world, ray, snap)` → new Position resting on the surface under the mouse (world-grid snapping). Pure math, tested with rays.
- `screen.rs`: `Screen` = camera + viewport rect: `ray(pos)`, `line(a, b)`, `studs_per_point(at)`.
- `viewport.rs`: draws with `render::TextureRenderer`, camera input, picking, selection box, handles. `drag: Option<Dragging>` is a handle (`Drag`, grabbed on press) or a body (`PlaceDrag`, only after egui's drag threshold, so clicks still select). Returns `ViewportOutput { clicked, drag: DragEdit, drag_released }`; the app applies edits after it draws (`apply_drag`), then requests a repaint.
- `tree.rs`: the tree-editing rules: `Insertable`, `create`, `insert_parent`, `unique_name`, `check_editable`, `check_move`. Tree changes go through `EditorApp::act(Action)` → `insert`/`delete`/`duplicate`/`move_into` → `place`, which records the `Move`.
- `explorer.rs`: `show` returns `ExplorerOutput { clicked, action }`; right-click menu, F2 rename text box, drag a row onto a row (egui `dnd_*` with a `DraggedRow` payload). Tests drive real mouse drags through `egui::Context::run` using the row rects in `drawn` (test builds only).
- `properties.rs` (`show` returns an `Edit`, never mutates; `MIN_SIZE`; `can_rename_here` is false for Scripts), `output.rs` (Error lines starting `path.lua:N:` get a `Location`; `show` returns the clicked one).
- **Deadlock trap:** `ui.input(|i| ...)` / `ctx.input` hold egui's context lock while the closure runs. Never call `Response` or `Context` methods inside it.
- egui's `consume_shortcut(Ctrl+Z)` also matches Ctrl+Shift+Z: consume the Shift version first.
- A `TopBottomPanel` sizes itself to its first frame's content: keep a `ScrollArea::auto_shrink(false)` in it even when empty. egui only repaints on input, so animations must `request_repaint()`.
- eframe, egui-wgpu and `render` must use the same wgpu major. Native textures for egui must be `Rgba8Unorm` with sRGB-encoded bytes.
