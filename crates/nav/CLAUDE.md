# `nav`

- The navigation mesh (`lib.rs`: walkable cells, links, regions, from `physics::solids`), paths across it (`path.rs`), and `Agents`, which steps NavigationAgents and steers them round new obstacles (`agents.rs`), then has them see and hear the player character (`perception.rs`); agents with a `BehaviorTree` run it first (`behavior.rs`: checks and runs `.behaviortree.json` files). Behavior: `docs/architecture/navigation.md`. Tests: `src/tests.rs` (mesh), `src/agent_tests.rs` (paths, agents), `src/perception_tests.rs`, `src/behavior_tests.rs`.
- May depend on `core`, `assets`, `physics` and `character` (to leave out character bodies, and `body_parts`). `physics` and `character` must never depend on this crate. The player and editor Play each own an `Agents`.
- Building reads the world and never writes it. Agents only move their own body, and write `Destination` (while `Velocity` drives them, or their tree sets it), `Status`, `SeesPlayer` and `HearsPlayer`. `BEHAVIOR_NODE_KINDS` must match `blocks::behavior_tree::BEHAVIOR_NODES` (an editor test compares them). Keep `fingerprint` in step with what `build` reads, or the editor overlay won't rebuild after a change.
