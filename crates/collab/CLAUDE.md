# `collab`

- Collaborate, called Team Create before (TC1–TC6 of `docs/research/team-create.md`, ADR-0020; next phases C1–C12 of `docs/research/collaborate.md`, ADR-0021). Sync core: operations (`op.rs`), applying them with the conflict rules and exact inverses (`apply.rs`), journal to ops (`capture.rs`), ID blocks, roles, messages, `host.rs`, `client.rs`. Network: `wire.rs` (bytes), `identity.rs` (device keys), `access.rs` (members, invite links), `handshake.rs`, `socket.rs` (WebSocket over TLS, pinned certificate), `session.rs` (`HostSession`, `Remote`), `tailscale.rs` (the installed Tailscale's state through its CLI, behind `Runner`; invites name the Tailscale host; never used for permissions). Who's in the session and what they're doing: `presence.rs` (roster, presence, text cursors and chat, not part of the World). Live scripts and stylesheets: `live.rs` (`yrs` documents, C7; the host checks updates, writes settled typing back to the file and keeps each document in `.axcenity/teamcreate/live`). Files: `files.rs` (hashes, manifest, which paths sync, the host's `FileStore`), `mirror.rs` (a member's folder kept in step, conflict copies). Reliability: `journal.rs` (the host's snapshot and accepted transactions in `.axcenity/teamcreate`, `recover`; `handled`, each member's newest handled transaction across host runs, so re-sent edits don't apply twice; a member's unsent edits, `save_unsent`). Checkpoints and restores (C9): `history.rs` (storage by file hash, `restore_ops`), `host/history.rs` (when, who may, applying a restore). Hardening (C10, design §6.1): `limits.rs` (per-member budgets per message kind, connection and handshake caps; a new kind that makes the host send a lot, write to disk or use up something shared gets a budget), `audit.rs` (the host's audit log, beside the members file). Each host run has an epoch: a copy from another run gets a snapshot and re-sends its edits with remapped IDs. `hosted.rs`: what the hosting editor and `collab-server` share (session ID, members file, session World). Projects that outlive sessions (Collaborate 2.0, `docs/research/collaborate-persistent.md`): `project.rs` (project ID, the members list sent to whoever may host, each computer's records, session states).
- No UI or scripts. Members, keys and certificates never go in the project folder (the repo may be public).
- The client works on the editor's own World (passed to every call), which records edits; `Client::capture` sends each undo step. Synced Instances use IDs from the writer's blocks; every world here is in replica mode.
- Tests: `tests.rs` (each conflict rule), `capture_tests.rs`, `convergence_tests.rs` (random edits over a simulated network whose messages go through `wire`) and `presence_tests.rs`, `files_tests.rs` (saves, locks, mirrors in temp folders), `journal_tests.rs` (recovery), `live_tests.rs` and `live_session_tests.rs` (live documents), `rejoin_tests.rs` (restarted editors and hosts, the host ending), `net_tests.rs` (real sockets on 127.0.0.1: handshake refusals and replays, drops, a cut network, addresses turned away), `security_tests.rs` (every message kind from a Viewer and a removed member, each budget; add a new `ToHost` kind to `every_message`), `wire_fuzz_tests.rs` (decoders and the handshake fed bad bytes). Keep the conflict table in the design doc and the tests in step.
