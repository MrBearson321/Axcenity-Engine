# `collab`

- Collaborate, called Team Create before (TC1–TC6 of `docs/research/team-create.md`, ADR-0020; next phases C1–C12 of `docs/research/collaborate.md`, ADR-0021). Sync core: operations (`op.rs`), applying them with the conflict rules and exact inverses (`apply.rs`), journal to ops (`capture.rs`), ID blocks, roles, messages, `host.rs`, `client.rs`. Network: `wire.rs` (bytes), `identity.rs` (device keys), `access.rs` (members, invite links), `handshake.rs`, `socket.rs` (WebSocket over TLS, pinned certificate), `session.rs` (`HostSession`, `Remote`). Who's in the session and what they're doing: `presence.rs` (roster and presence, not part of the World). Files: `files.rs` (hashes, manifest, which paths sync, the host's `FileStore`), `mirror.rs` (a member's folder kept in step, conflict copies). Reliability: `journal.rs` (the host's snapshot and accepted transactions in `.axcenity/teamcreate`, `recover`; a member's unsent edits, `save_unsent`). Each host run has an epoch: a copy from another run gets a snapshot and re-sends its edits with remapped IDs. `hosted.rs`: what the hosting editor and `collab-server` share (session ID, members file, session World).
- No UI or scripts. Members, keys and certificates never go in the project folder (the repo may be public).
- The client works on the editor's own World (passed to every call), which records edits; `Client::capture` sends each undo step. Synced Instances use IDs from the writer's blocks; every world here is in replica mode.
- Tests: `tests.rs` (each conflict rule), `capture_tests.rs`, `convergence_tests.rs` (random edits over a simulated network whose messages go through `wire`) and `presence_tests.rs`, `files_tests.rs` (saves, locks, mirrors in temp folders), `journal_tests.rs` (recovery), `rejoin_tests.rs` (restarted editors and hosts, the host ending), `net_tests.rs` (real sockets on 127.0.0.1: handshake refusals, drops, a cut network). Keep the conflict table in the design doc and the tests in step.
