# `testing`

- The game test runner (Phase 53): `Runner` lists and runs a project's `tests/**/*.spec.lua`, each `it` in a fresh headless `TestGame` (`game.rs`, the player's frame steps 1-4 at a fixed 1/60 s); `runner.lua` is `describe`/`it`/`expect`/`Test`, started by `ScriptRuntime::start_spec`. The `axcenity-test` binary is `main.rs`; JUnit XML `junit.rs`. Behavior: `docs/project/game-tests.md`.
- Never write the project's files: saves go to a temporary folder, and an older project isn't upgraded. The editor's Tests panel and the binary must both run through `Runner` so their results match.
- `TestGame::frame` runs the shared `axcenity_sim` schedule; its order lives there, not here. The player never depends on this crate.
- Benchmarks (roadmap I1): `s10k.rs` writes the S10k measurement scene (`--make-s10k`), `crowd.rs` the crowd scene (`--make-crowd`, Phase 93), `streaming_world.rs` the 4 × 4 km streaming world (`--make-streaming`, Phase 80) and `showcase.rs` the feature benchmark from the owner's Overgrown Carriage (`--make-showcase --from`, read only); `--bench <frames>` runs the start level through `Runner::bench` and `TestGame::laps`. `axcenity-bench-check` (`bench_check.rs`) reruns `benchmarks/baselines.json`'s scenes against this machine's numbers. Keep stage names in step with the other hosts: `docs/benchmarks.md`.
