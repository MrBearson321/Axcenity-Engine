# `net`

- Multiplayer (Milestone 14): `transport.rs` (renet channels over UDP or the in-memory loopback, one interface), `handshake.rs` (join request, version checks, refusals worded for both ends), `session.rs` (`Host`, `Join`, MP2 rejoin keys; `game.rs` rejoins a lost connection for 60 s), `limits.rs` (MP3: each player's budgets; a new message kind from players gets one, and drops flag the player), `secure.rs` (MP4: the token port over TLS, certificates, fingerprints and join links; `Server::listen_secure`, `Client::join`), `discovery.rs` (LAN broadcast), `wire.rs` (values and remote messages, Instances as network IDs; postcard on the wire, so no skipped fields or `#[serde(tag)]`), `replicate.rs` (Phase 64: the join snapshot and each frame's changes, found by comparing with what was sent), `motion.rs` (Phase 65: parts' quantized motion within each player's budget, and smoothing on their device), `ownership.rs` (Phase 66: a device's own character and owned assemblies, the server's `CharacterCheck` and corrections; MP3b's wall and flight checks and strikes are `movement.rs`), `streaming.rs` (Phase 80: each player's share of the world while streaming; `docs/architecture/streaming.md`), `replay.rs` (Phase 81: `Recorder`, the `.replay` file and `Playback`; raise `REPLAY_VERSION` when `Replay` changes), `game.rs` (`Network`: `NetworkService` requests, `Players`, sending the world, and remote messages; a joined device follows the server through `ScriptRuntime::become_client`). Docs: `docs/architecture/networking.md`.
- Hosts call `Network::receive` first in the frame and `send` before drawing; keep both in the frame order.
- Keep `Message::Hello` and `Refused` readable by later versions (they stay JSON, `handshake::Greeting`), so a newer engine can still say why it refuses. Raise `PROTOCOL_VERSION` when a message or a class default changes (creates carry only non-default properties).
- Never block: sockets are non-blocking and every wait is counted in frame time (the token port and token fetches run on threads of their own). Keys and certificates never go in a project.
- Nothing in ServerScriptService or ServerStorage (`World::is_server_only`) goes to a player: not in replication, not as a message's Instance. A player's message is theirs whatever it says (the connection decides its Player).
- Faces' live state (expressions, overrides, layers, lip sync) is replicated by `face_sync.rs` (F7b), beside `replicate.rs`.
