# `project`

- Loads and saves project folders, including CSS source files. Open one file from the map in `docs/project-and-export.md`.
- `lib.rs` is the manifest, load and save; `scripts.rs`, `stylesheets.rs` and `templates.rs` hold those (re-exported from `lib.rs`). `build.rs` embeds the repository's `templates/` (the genre templates, `docs/project/templates.md`). `ui_graphs.rs` compiles `ui/*.uigraph.json` to LocalScripts under their ScreenGuis. `world_file.rs` is `world.json`; `levels.rs` the other levels, `levels/<name>.world.json` (Workspace only; `load_with_level`, `save_level`, `set_start_level`; `docs/project/levels.md`); `strings.rs` the string table, `strings.json`. `migrate.rs` upgrades an older manifest and keeps the previous files (`migrate_animation.rs` is the 2 → 3 step: one clip format, state machines). `terrain_files.rs` is Terrains' data folders (codecs in `terrain::files`). `packed.rs` packs a game; `package.rs` is asset packages (`.axpkg`, `docs/project/packages.md`). `versions.rs` keeps save history (pins, checkpoints, restores); `versions/changes.rs` is its change view (Instance diff by path, line diff); `backup.rs` is Back Up Project (`docs/project/export.md`). `validate.rs` is the editor's asset check (`check_assets`); it must not write the project. `asset_fix.rs` plans its fixes (`plan_fix`) without writing; only the ignored list (`.axcenity/asset-check.json`) is written there. `asset_refs.rs` finds every reference to an asset, the unused ones, and plans a rename (`find_references`, `unused_assets`, `plan_rename`), also without writing. `object_scripts.rs` loads scripts inside objects (`SourceFile`) and merges the start order (`docs/project/world.md`). `prefabs.rs` reads prefab files and keeps placed copies, nested prefabs and variants up to date (`Prefabs::refresh`, run by every load; format in `docs/project/world.md`). `watch.rs` is the file watcher (`Watcher`, `Watched`): `notify` events trigger the stat-diff look, polling where events fail (live reload, `docs/editor/scripts.md`).
- Keep serialization deterministic and report damaged files through the existing `Project::problems`/error paths. Bump `FORMAT_VERSION` only with a migration plan.
- When core properties or enums change, update both project parsing and writing, and keep the example-project tests passing.
