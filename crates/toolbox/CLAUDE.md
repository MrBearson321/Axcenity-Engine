# `toolbox`

- The Axcenity Toolbox: the editor's one way to find and fetch assets online. Sources implement `AssetSource` (`source.rs`) and return `AssetRecord`s (`record.rs`, the shared `asset-source` record): `ambientcg.rs` (v3 API), `polyhaven.rs`, `openverse.rs`. Downloads go into the central asset directory (`directory.rs`) through `download.rs` (`Fetcher`: `.part`, size and MD5 checks, unpacking) and are recorded in `metadata.db` (`db.rs`, SQLite, schema versioned; Python reads it too). Under them: `http` (`Http`, `Client`, `Fixture`), `guard`, `files`, `license`, `variants` (choosing a package), `SourceError`. Get texture (`editor/src/ambient_cg.rs`) is the editor's user so far. Design and plan: `docs/research/asset-sources/` (open `provider-interface.md`).
- Editor only: `player`, `server`, `sim` and `testing` must never depend on it (`scripts/check-platform.*` checks the player).
- Unit tests never reach the network (`http::Fixture`) or the real asset directory (use a temp folder). `tests/live.rs` reaches the real sources and is ignored; run it by hand after changing a source (`--run-ignored only`).
- `SourceError` messages must be safe to show. Every request sends `http::USER_AGENT`. Never offer `.blend` files; check every file's URL with `SourceInfo::allows_download_from`. Change the database schema only through a new version in `db.rs` (never edit `SCHEMA_V1`), and never delete `assets` rows.
