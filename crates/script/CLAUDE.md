# `script`

- Luau runtime over `core` (`luau0-src` is pinned to match `mlua`; see `docs/scripting/language.md`). Open one file from the map in `docs/scripting.md` (API, sandbox, scheduler, or client/server). `workspace:Raycast` uses `physics`; hosts call `ScriptRuntime::set_assets`. TweenService (`tween.rs`) eases with `anim::ease` and steps in `Context::step`. `reload_script` reruns a changed script in Play; coroutines and handlers are owned by a script via `scheduler::resume_as`, so route new resumes through it. SaveService (`save.rs`, over the `save` crate) is shared by both sides; hosts call `set_save_folder`. GuiService (`gui_service.rs`) and the SaveService settings `UI/…` are the world's game UI settings. UserGameSettings (`user_settings.rs`, LocalScripts only) holds `render-types`' `GraphicsSettings` (never depend on `render` or `audio`: the dedicated server links `script`); hosts call `set_graphics` and `take_graphics_change` (`docs/rendering/settings.md`). Input (`input.rs`: UserInputService, InputObject, ContextActionService; `docs/scripting/client-server.md`): hosts call `set_input_map`, `input_events`, `input_map` and `mouse`; a rebind is the SaveService setting `Input/<action>`. `workspace.CurrentCamera` is `camera.rs` (app data, not an Instance): hosts call `set_viewport_size`, `set_camera`, `take_camera_move` and `step_camera`; `Camera` Instances are only viewpoints.
- `edit.rs` (Phase 54): `EditRuntime`, a long-lived edit-mode interpreter for the editor's plugins (`Destroy` only detaches tree Instances; `add_service` extends `GetService`). `spec.rs` (Phase 53): `start_spec` runs a game test's spec with the `testing` crate's runner Lua and a `host` table; hosts apply `take_test_requests` next frame and read `take_test_reports`.
- `CFrame` (`cframe.rs`) is never stored: `Part.CFrame`, `GetPivot` and `PivotTo` read and write `Position` and `Orientation` through `LuaCFrame::write_to`, which keeps unchanged values exactly. `Random` (`random.rs`) is integer-only PCG32 so seeds match across platforms.
- `definitions.rs` writes the luau-lsp file `definitions/axcenity.d.luau` from `definitions/tables.rs` (Luau type syntax) and `definitions/docs.rs`; the same writer yields `api_reference()` for the editor's API Reference page.
- Tree methods (`Clone`, `Destroy`, `WaitForChild`, `IsA`, ...) are `tree.rs`; `Destroy` fires its own events before the IDs go stale. The runtime starts cloned scripts and stops destroyed ones in `fire_changes`. Attributes, tags and `CollectionService` are `collection.rs` (tag signals diff each watched tag after a change round). Phase 32: `bindable.rs` (BindableEvent, BindableFunction, the `OnInvoke`/`OnServerInvoke` callbacks), RemoteFunction calls in `remote.rs` (`MessageKind`), `run_service.rs` (Stepped, render step; hosts call `stepped`, `render_step`, `set_studio`), `debris.rs`, `http.rs` (JSON with `serde_json`). `DataService` (`data.rs`) reads data tables from the `Assets` in app data, read-only. `physical.rs`: `PhysicalProperties`, impulses (they add to the velocity properties through `physics::Mass`, by assembly mass), the read-only mass fields, `GetConnectedParts` and `GetRootPart` (`physics::assembly`). `query.rs` (Phase 38): RaycastParams, OverlapParams, the Workspace's casts and overlap queries, and PhysicsService; hosts call `fire_touch_ended` after `fire_touched`. `health.rs` (Phase 43): Health's `TakeDamage`/`Heal`/`Health` writes queue `HealthEvents` that `fire_changes` fires on both sides; hosts call `fire_landed` and `step_health` (DamageZones, regeneration, ProgressBars bound by an ObjectValue named `Health`). `prompt.rs` and `click.rs` (Phase 44): ProximityPrompts and ClickDetectors, stepped by `step_prompts` after `input_events` from the client's input (`input::prompt_input`) and camera; hosts draw `shown_prompts` and show `click_cursor`. `tool.rs` (Phase 45): Tools and Inventories; scripts' calls note Inventories in `ToolChanges` and `Tools::sync` fires `Equipped`/`Unequipped` from `fire_changes`; hosts call `step_tools` after `step_prompts`, `place_tools` with the Animators' poses, and draw `ui::hotbar_items` for `player_inventory`. `humanoid.rs` (Phase 46): a Humanoid's fields are its pieces' (`instance::get`/`set` route `CONTROLLER_FIELDS` and `HEALTH_FIELDS`); MoveTo paths use `nav`, on the mesh the host shares with `share_nav_mesh` (`Sim::new` does) or else one of its own; hosts call `step_humanoids` with the `Controllers` after `fire_landed`, and a Health's `Died` kills its Humanoid in `fire_health_events`. `players.rs` (Phase 47): joining, teams, `LoadCharacter` (copies the StarterCharacter onto a SpawnLocation; `Spawned` events fire from `fire_changes`), respawns and spawn ForceFields; hosts call `step_players` after `step_humanoids` and draw `ui::leaderboard_items` while `leaderboard_shown`. `levels.rs` (Phase 48): LevelService; hosts call `set_levels` before scripts start and `take_level_loads` to show the loading screen again, and `LoadSlot` goes to a slot's levels (`levels::go_to_saved`) before restoring. `sequence.rs` (Phase 51): Sequence Instances, shared by both sides and stepped at the end of `step` (camera, Sounds, levels, events); hosts zero controller input while `input_locked` and `input_events` lets only releases through, the Menu action skips (`docs/project/sequences.md`). `csg.rs` (Phase 50): `UnionAsync`, `SubtractAsync` and `IntersectAsync` run `mesh_edit::combine` on a thread and resume the script from `Context::step` (`docs/architecture/solid-modeling.md`); behind the default `csg` feature, and without it `csg_off.rs` makes the methods raise an error. `network.rs` (Phase 63): `NetworkService` queues `NetworkRequest`s; hosts call `take_network_requests`, `finish_lan_search`, `fire_connection_failed`, `add_remote_player`, `remove_player` (fires `PlayerRemoving`) and `rename_local_player` (`docs/architecture/networking.md`). Phase 64: messages for other devices go to `take_remote_messages` and come in through `receive_remote_messages`; `InvokeClient`/`OnClientInvoke` in `remote.rs`; `set_dedicated` (no player), `become_client` (only LocalScripts, on a replica) and `add_replicated_player`; `set_user_id`. Phase 66: `ownership.rs` (`SetNetworkOwner` and friends; hosts ask `owned_parts`). Phase 67: `chat.rs` (TextChatService; hosts call `take_chat_sends`, `filter_chat`, `receive_chat`, `take_system_messages`, `chat_lines`), `take_kicks`, and SaveService's per-player data and slots (`Saves::player_value`, `for_player`). `attachment.rs`: an Attachment's world fields (its stored Position/Orientation are relative to its part, so `PivotTo` skips Attachments). Joints' read-only `Current*` come from `physics::joints::current`; a property holding an `EnumItem` (`ActuatorType`, movers' `RelativeTo` and `Mode`) is set through `types::enum_item_from_lua`, which checks the enum.
- `spline.rs` (Phase 73): Spline's `Length` and methods, `NavigationAgent:Patrol`, and `Followers`, which moves SplineFollowers on the server in `ScriptRuntime::step` and fires `Reached` (`docs/architecture/splines.md`). Phase 74: `step` first runs `procedural::Generators::update` on every device. Phase 76: `ability.rs`, Abilities and Effects (`SharedAbilities` on both sides; activation requests are `MessageKind::Activate`; hosts call `step_abilities` after `step_tools` and draw `ability_bar`; the server step is in `step_health`; `docs/scripting/api-abilities.md`). Phase 77: `dialogue.rs` (`.dialogue.json` checked and run, `DialogueService`; `step_prompts` runs its keys and starts prompts' `Dialogue`; hosts lock movement with `movement_locked` and draw `dialogue_view`) and `quest.rs` (`QuestService` over data tables, state in `Saves` player data; hosts draw `quest_tracker`; `docs/scripting/api-dialogue.md`). Phase 75: `decals.rs` is `workspace:SpawnDecal`, its fade and the Workspace's `MaxSpawnedDecals`, stepped in `Context::step` after Debris (`docs/rendering/decals.md`).
- Build each script environment from the sandbox allowlist; never expose `lua.globals()`. Follow existing World handoff patterns and release borrows before re-entering Lua. For API changes, update descriptions and regenerate with `cargo run -p axcenity-script --bin lua-definitions`. New events also need core declarations and a host firing path.
- `debugger.rs` holds the workspace's only `unsafe` code (Luau's step hook and `read_frames`; `unsafe_code = "deny"`); keep new code safe. Every resume goes through `scheduler::resume`, so the debugger can hold it.
