# script

Runs Lua 5.4 (mlua 0.12, vendored) against the `core` World. Depends only on `core`. API rules: `docs/scripting.md`.

- `lib.rs`: `ScriptRuntime` owns two `Context`s (`context.rs`, one `mlua::Lua` each: server and client, so no shared globals) and a `Box<dyn Transport>`. `start_script` picks the side from the Instance's class (LocalScript = client; the player joins first); `input` (step 1), `step` (step 2: deliver messages, then resume), `fire_touched` (both sides), `set_camera` / `take_camera_move`, `take_output`. After every call into a side, `collect` moves its output and outbox. The World is **moved into Lua app data** (`with_world`) while scripts run and moved back after, because Lua callbacks can't hold a `&mut World`. Callbacks use `instance::world` / `world_mut`; drop the guard before calling back into Lua.
- `sides.rs`: `Side` (also in app data, for `sides::check`) and `SIDE_ONLY_APIS` with their wrong-side messages. A new side-only API needs a line there (the editor's badges use it too). `remote.rs`: `RemoteValue`, `Message`, `Transport`, `Loopback`, `Outbox`, the RemoteEvent methods, `deliver`. `client.rs`: `UserInputService`, `InputObject`, `Camera`, `HeldKeys`, `LocalPlayer`. Tests: `client_server_tests.rs`.
- `sandbox.rs`: each script's environment is a fresh table built from an **allowlist** (`SAFE_FUNCTIONS`, copied library tables, clock-only `os`). Add new globals there or in `api.rs`; never expose `lua.globals()`. `Shared` (app data) holds the engine's `pcall`/`xpcall`, `setmetatable` (no `__gc`), `require`, `collectgarbage` ("count" only) and `coroutine` functions. The string metatable is locked (`lock_string_metatable`). Escape attempts: `sandbox_tests.rs`.
- `modules.rs`: `require` (Lua wrapper, so modules can `task.wait`, around Rust `begin`/`finish`). `Modules` (app data, per side): sources from `start_script` on a ModuleScript, and `Loading(thread)`/`Loaded(value)` states.
- `watchdog.rs`: global count hook (every 1000 instructions). `enter`/`leave` around every `scheduler::resume` set the budget (`DEFAULT_LIMIT` 3 s). Over budget: **yield** the coroutine for good (`paused_by_watchdog` reports it); if it can't yield, raise (and `pcall` rethrows via `stopped`). Never raise from the hook when a yield works: Lua leaves hooks off in a coroutine an error from a hook ended. Tests: `watchdog_tests.rs` (limit 100 ms).
- `api.rs`: `print`, `game`, `workspace`, `script`, `Instance`, `Vector3`, `Color3`, `Enum`. Created per script, so one script can't break another's.
- `instance.rs`: `LuaInstance(InstanceId)`. `__index` order: mlua checks methods first, then `Name`/`ClassName`/`Parent`, properties, class members (`class_member`: `ClassMethods` from app data such as `FireServer`/`GetService`, and fields such as `CurrentCamera`), events, children by name.
- `types.rs`: newtypes (orphan rule) for `Vector3`, `Color3`, enum items (`EnumType`: Material, PartType, KeyCode); `value_from_lua` converts by the property's existing kind. Use `f32_to_lua` so `0.1f32` reads as `0.1`. Enum items are new userdata on every read, so they can't be table keys: use `.Name`.
- `errors.rs`: messages start `path:line:`. Rust callback errors take the location from mlua's traceback, skipping `[C]`, `[engine]` and `__mlua*` frames. `pcall`/`xpcall` are Lua wrappers (so yields still work) that turn mlua error objects into plain strings.
- `definitions.rs`: generates `definitions/axcenity.lua` for Lua Language Server. **Any API change** needs its description there (new properties: `PROPERTY_DOCS`), then `cargo run -p axcenity-script --bin lua-definitions`. Tests catch anything missed.
- Gotchas: mlua's `Value::type_name` says `integer` for whole numbers; show `number`. Lua's `tostring(1.0)` is `1.0`, and `print` uses the real `tostring` to match.
- `scheduler.rs`: `Scheduler` (in Lua app data) holds waiting coroutines with a due time and an order number; `step` resumes due ones, `resume` reports errors. Drop the `scheduler_mut` guard before resuming anything.
- `task.rs`: `task.wait` is Lua (only Lua can yield; mlua Rust functions can't) calling a Rust `schedule`; `spawn`/`delay` are Rust.
- `events.rs`: `LuaSignal` (`part.Touched`), `LuaConnection`, and `Connections` (app data: handlers per `(Owner, event)` in connect order; `Owner` is an Instance or `UserInputService`). `fire` copies the handler list first, then runs each as a new thread via `scheduler::resume`. Host entry point: `ScriptRuntime::fire_touched(world, pairs)`. New events need a name in `core`'s `ClassName::events()`, an `EVENT_DOCS` line, and a host-side `fire_*`.
- Not yet: `:Once`/`:Wait` (Phase 16).
- The editor's Output turns errors starting `path:line:` into links to the script; keep that prefix.
