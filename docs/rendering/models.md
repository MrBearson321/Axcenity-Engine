# Imported models

glTF and FBX meshes, texture maps, and SurfaceAppearance.

- **Draw list:** `Shape::Mesh(Arc<dyn MeshSource>)` is a mesh the caller owns (positions, normals, optional texture coordinates, `u32` indices), and `Material::base_color_texture` an `Arc<dyn TextureSource>` (sRGB RGBA8). They're traits so `scene` hands over the loaded model's data without copying it each frame. The renderer uploads each on first sight, keyed by `key()`, and frees what hasn't been drawn for 600 frames. Broken data (an index past the last corner, the wrong number of pixels) is logged once and not drawn.
- **Vertices** gained texture coordinates (location 12). Built-in shapes carry real ones: a box face runs 0–1 along its edges, a cylinder's side goes once around its circumference, and a sphere covers its surface. Tangents go with them. Textures are bound as group 1 with a repeating, mipmapped linear sampler; an item with no texture binds a 1×1 white texture. Mipmaps are made on the CPU at upload by 2×2 averaging (in sRGB, slightly off but not visibly). Levels bigger than the GPU allows are left out, so huge textures show less sharp instead of failing.
- **Model space:** `assets` fits every model into the 1×1×1 cube centered on the origin, like the built-ins, so `Size` stretches its box. It walks the default scene's node tree (or every mesh, if there's no scene), applying node transforms (mirrored nodes get their triangles flipped back); missing normals are made smooth from the triangles. Only triangle lists are drawn; points, lines, strips and fans are skipped.
- **FBX** files are read by `ufbx`, which converts them to glTF's space (Y up, right-handed, meters) whatever axes and units they were saved in, and triangulates polygons. Every visible node with a mesh is drawn, at its world transform (pivots and geometry offsets included), one draw item per material it uses. Normals the file lacks are made by `ufbx`. Materials become metallic-roughness: `ufbx` maps Lambert/Phong and other FBX shading models (and Blender's Principled BSDF) to PBR values; base color × factor, opacity (below 1 is `BLEND`; an opacity map makes it `MASK` at 0.5), metalness (default 0), roughness (default 1, Phong shininess converted), emission × factor, and the base color texture with V flipped to the engine's top-left origin. Their other maps are read too (see Texture maps). Skeletons, skin weights and takes are read too (see Animation). Not yet: per-UV-set texture choice (the first UV set is used).
- **Materials:** each glTF primitive is one draw item with its metallic-roughness material: base color factor × base color texture, metalness, roughness, emissive (converted from glTF's linear light to the draw list's sRGB). Alpha mode `OPAQUE` is solid, `MASK` cuts out pixels below its cutoff (`Material::alpha_cutoff`, a `discard` in the shader), `BLEND` is drawn see-through (opacity capped just below 1 so it always takes the see-through path). Solid items always write alpha 1. Its metallic-roughness, normal, occlusion and emissive textures are used (see Texture maps). Skins are read (see Rig in [animation.md](animation.md)). Not yet: vertex colors, `KHR_materials_emissive_strength`, animation.
- **Material files** (graphics Phase 7; `assets/src/material.rs`, `scene/src/material.rs`): a `*.material.json` file (the editor saves them in `assets/materials`) holds one standard material: `color` and `emissiveColor` (sRGB, 0 to 1, like a Part's `Color`), `metalness`, `roughness`, `emissiveStrength` (the glow is `emissiveColor` times it), `opacity` (below 1 is see-through), `alphaCutoff` (above 0, cut out below it), `maps` (`color`, `normal`, `metalness`, `roughness`, `occlusion`, `emissive`, `opacity`, `specular`, each `{ "path", "channel", "invert", "strength", "directX" }`: `channel` is `"Red"`…`"Alpha"` for the one-channel maps, `invert` reads a glossiness or inverted-opacity map, `strength` is the normal map's scale and the occlusion's strength, `directX` flips a normal map's green), `tiling` and `offset` (`[u, v]`, as a SurfaceAppearance's `Tiling` and `Offset`), `doubleSided`, `sway` (how much what's drawn with it sways in the wind, 0 for still: [wind.md](wind.md)), `shader` (WGSL code; see Surface shaders below; `""` takes away the base's), `parameters` (values the shader reads by name, see Surface shaders) and `graph` (the editor's material graph the shader was made from; see Material graphs below). A metalness or roughness map multiplies its value, as glTF's do; an opacity map shows only with an `opacity` below 1 or an `alphaCutoff`. A file names only what it sets (`MaterialFile`, every value an `Option`). `base` names another material file by its project path: each value the file leaves out comes from the base (and its base), so an instance overrides some values and follows its base for the rest. A map is merged value by value, so an instance can change a map's strength and keep its image, and `"path": ""` takes away a map the base has. What no file sets is the default material (`StandardMaterial::default`: white plastic, roughness 0.5, no glow, no maps). `Assets::material` reads a file and its bases once and keeps the result (`StandardMaterial`); `Assets::forget` of any file in the chain rereads it, and `forget_failures` retries one whose base was missing. `Assets::put_material_file` uses a file's edited contents in place of the file (the editor's Material tab hands each edit over; `None` reads the file again), forgetting every material built on it, and `Assets::material_chain` gives a file's chain of bases and their values put together. A material file that can't be read is reported once ("Could not load the material `…`: …") and the part draws as if it had none. A missing base, or bases that lead back around (`a → b → a`, or a file naming itself), is reported once and the default material stands in for that base; the files already read still apply. A Part's or MeshPart's **`MaterialVariant`** (a string, empty for none) names the file. On a Part it replaces the `Material` preset and its `Metalness`, `Roughness` and `Emission`; its `Color` tints the material (multiplies its color), `Transparency` still fades it and `TileSize` still sets the studs per repeat when it has maps. On a MeshPart it replaces every material of the model. A SurfaceAppearance wins over it: a Part with one ignores its `MaterialVariant`, and in a MeshPart the appearance's material keeps the appearance. Material files are new optional files, so the project format doesn't change; an exported game carries them with the rest of `assets`, and the player reads them (and their maps) when it first draws. The editor's loading screen reads them ahead (`AssetFile::Material`). `scene::part_material_file` makes a file from a Part's look (its preset, properties and SurfaceAppearance; a Neon part's glow is saved at the bloom boost; a part already using a material file gets an instance of it, overriding the color by its tint), for the editor's Save as Material (`docs/editor/assets.md`).
- **Surface shaders** (graphics Phase 22; `render/src/renderer/surface_shaders.rs`): a material file's `shader` is WGSL code with a `fn surface(input: SurfaceInput) -> Surface` that works out each pixel's surface in place of the standard one. `SurfaceInput` has `uv` (after the material's tiling and offset), `world_position`, `normal` (the mesh's, unit length, facing the camera, before the normal map), `tangent` (along U, `w` the side V is on), `time` (seconds, `DrawList::time`: the player counts the frames run, the editor the seconds since it started, in the viewport, Play and the Material tab's preview), and the item's own `color`, `opacity`, `metalness`, `roughness` and `emissive` before its maps. `Surface` is `base_color`, `metalness`, `roughness`, `normal` (world space), `emissive` (added after lighting) and `opacity` (below the cutoff cuts the pixel out; an item is see-through only when its material's opacity is below 1). Colors are linear light: `srgb(color)` turns a color picked as sRGB into it. `parameter(i)` reads the material's `parameters` (graphics Phase 23): named numbers (`"Amount": 0.5`, in `x`) or colors and vectors (`"Tint": [1, 0.5, 0]`, sRGB, in `xyz`), `i` counting from 0 in name order, up to 8 (`SURFACE_PARAMETERS`). The file with the shader names them; an instance sets their values (merged name by name, like maps), and a value for a name the shader's file doesn't have is left out, so the others keep their places. They reach the shader in the material's uniform (`Material::surface_parameters`, `MapsUniform::params`), not its code, so materials that differ only in them share one pipeline. `standard_surface(input)` is the material's own look at `input.uv`, so a shader usually changes its input or its result (examples/hello-shader scrolls its conveyor's chevrons: `moved.uv = input.uv - vec2<f32>(input.time * 0.5, 0.0)`). The ambient occlusion and specular maps stay at the mesh's coordinates. The code may define other functions and constants, but must sample textures (`standard_surface` does) where every pixel runs together, not inside a branch, as WGSL requires. `scene` hands it over as `Material::surface_shader` (`SurfaceShader`, named by the material file the code is in, so an instance's error is on its base's lines). The renderer puts it after the scene shader's template (`SCENE_TEMPLATE`: sky, lighting and shader.wgsl; the standard surface is surface.wgsl in the same place), so its line *n* is always the template's line count plus *n*. It's checked with `naga` (from `wgpu`) first, then compiled into its own scene and prepass pipelines inside wgpu error scopes, once per distinct code (`SurfaceShader::key`, a hash, so materials with the same code share them), compiled again when the samples per pixel change, and freed after 600 undrawn frames. Shadows use the standard pipelines. A shader that doesn't compile is logged and handed over once (`TextureRenderer::take_shader_errors`, `Renderer::take_shader_errors`: `ShaderError` with the material, the line of its code and the message, naga's `[n]` expression numbers replaced by their code), and its items draw with surface_error.wgsl's glowing magenta and black checks; everything else draws as usual. The player prints them as errors, the editor shows them in the Output window, and the every-example test fails on any.
- **Material graphs** (graphics Phase 23; `editor/src/material_graph.rs`): the editor's Material tab can build a material's surface from nodes (`docs/editor/assets.md`). The graph is kept in the file's `graph` (a node graph, as the UI Event Graph's are kept) and is compiled in the editor to the file's `shader`, `parameters` and maps, which are written beside it: the player reads only those, never the graph, and has no graph code. Graphs never become Lua, and gameplay graphs never become WGSL. Nodes: Material Output (Base Color, Metalness, Roughness, Normal, Emissive and Opacity; an unwired input keeps the material's own value, without maps), Material Input (the part's color times the material's, and its values), UV, Tiling and Offset, World Position, Normal, Time, Texture Sample (an image, read as Color, so linear light, or Data, as it is), Number, Color (sRGB, as picked), Make Vector2/3, Split, Add, Subtract, Multiply, Divide, Power, Minimum, Maximum, Mix, One Minus, Sine, Absolute, Fraction, Clamp 0 to 1, Smooth Step, Blend (Mix, Multiply, Screen, Overlay, Add), Hue Shift, Contrast, Noise (Perlin, Value, Voronoi; 0 to 1 over UV) and Number and Color Parameters (each a `parameters` entry by its Name). Values are numbers, Vector2s and Vector3s; math nodes take any of them and give back what they're given, and a number fills a vector. A graph's images go in the map slots its shader reads them from: colors in the color and glow slots (sRGB views), then the metalness, roughness, opacity and normal slots (read as they are, so a color there is turned into linear light in the shader), up to 6. Its maps replace the file's, but for the occlusion and specular maps, which still light it as usual; an instance's graph empties the slots it leaves free of its base's maps. An instance of a graph material can change the parameters, and swap an image by setting that slot's map. `compile` reports errors by node: no Material Output (on the graph), a second one, an output with nothing wired in, an input that needs a value, a type mismatch (on the node where the types meet: `A is a Vector2 but B is a Vector3`, `Base Color needs a Vector3, but is given a Vector2`), a value that doesn't read, an image not picked, too many images or parameters, two parameters with one name, and a value depending on itself. examples/hello-material-graph mixes stone and moss by Perlin noise, with the moss tinted by a Color Parameter that its second material (an instance) overrides.
- **Texture placement and sides** (graphics Phase 6): `Material::uv_scale`, `uv_rotation` (radians) and `uv_offset` place every map of an item. The vertex shader applies them after `DrawItem::uv_tile`: scale, then turn (counter-clockwise in a texture whose V runs down, as glTF's `KHR_texture_transform`), then offset. They're in `MapsUniform` (`uv_matrix`, `uv_offset`), so items that differ in them get their own material binding; untextured items ignore them. `Material::double_sided` draws an item with pipelines that don't cull back faces (a solid and a see-through one); the fragment shader turns the normal, and the normal map's frame, to face the camera on a back face (`front_facing`), so a back is lit as a front. Batches are split by sidedness. Shadows already draw both sides. glTF reads `doubleSided` and `KHR_texture_transform` (offset, rotation, scale) from the first of the base color, metallic-roughness and emissive textures that has one; one transform places all of a primitive's maps, and a transform that moves its texture to another coordinate set (`texCoord`) is left out. FBX reads the base color map's (else the normal map's) placement from `ufbx`'s `uv_to_texture`: its scale and translation (the inverse of the texture's own `Scaling` and `Translation`), with V flipped to the engine's top-left origin; rotation is left out, and FBX has no double-sided flag.
- **Texture maps** (Phase 19): `Material::maps` (`TextureMaps`) adds a normal map (`NormalMap`: scale, and `flip_green` for DirectX-style maps), metalness, roughness, ambient occlusion and opacity maps (`ChannelMap`: one channel of a texture, optionally inverted, so a glossiness or smoothness map works as roughness and one packed texture can serve several maps), an emission map and a specular map. A map multiplies its value (metalness, roughness, emissive); the opacity map replaces the base texture's alpha; occlusion darkens only ambient light, by `occlusion_strength`. A specular map scales how strongly non-metals reflect: plain 0.5 is the usual 4%, 0 none, 1 twice that (older Phong materials' specular maps, rather than a guessed metalness). A built-in shape uses those maps when its material has any.
- **Levels of detail** (graphics Phase 13; `assets/src/model/lod.rs`): each primitive has `lods`, simpler copies with the same material, each with fewer triangles than the one before. A file's own copies win: objects named like the full one with `_LOD1` and `_LOD2` on the end (any case; `_LOD0` is the full one, and everything inside an `_LOD1` node belongs to that copy; FBX copies are read even when hidden, since a LOD group hides all but one), matched to the full primitives by material name (or to the only one); a pick of the full object (`file.glb#Rock`) brings its copies with it. They don't size the model or add to its hull, and are fitted with the full model's transform. Without them, a primitive of 256 triangles or more is simplified with meshoptimizer (`meshopt`) at load to half, then a quarter, of its triangles (normals and texture coordinates weighed so creases and seams stay, the surface moving at most 2% and 5% of its size), keeping only the corners each copy uses; a copy that doesn't save a fifth on the level before is dropped. The copies are cached with the model in `Assets`, not saved. `scene` hands them over through `MeshSource::lod_count` and `MeshSource::lod`, and the renderer picks one (see LOD in [pipeline.md](pipeline.md)). A posed model's copies are posed too: `Model::pose` only stores the joint matrices, and `Posed::primitive(model, index, level)` skins that primitive at that level the first time it's asked for, so a far character poses only its simpler copy.
- **Texture quality** (a graphics setting, [settings.md](settings.md)) leaves out a texture's largest mip levels at upload, and so does a GPU whose textures can't be that big. Past the texture memory budget, the least recently drawn textures lose more; see [shadows.md](shadows.md).
- **Binding:** each texture is uploaded once as plain `Rgba8Unorm` with an sRGB view as well: base color and emission are read through the sRGB view (so samples are linear light), the other maps as plain values. Each distinct set of textures and map settings gets one bind group (group 1: 8 textures, the sampler and a small `MapsUniform` with each map's channel mask, inversions, normal scale and green sign, occlusion strength and which maps are present); maps an item lacks bind the 1×1 white texture. Items are batched by mesh and that set.
- **Tangents:** normal maps need them. `assets` works them out after fitting, for primitives with a normal map, from the triangles' texture coordinates (area-weighted, made perpendicular to each normal; `w` is the side the texture's "up" is on). File tangents are ignored, so seams on maps baked with MikkTSpace can show slightly. Vertices carry them at location 13; the shader turns them by the model matrix and builds the tangent frame per pixel.
- **glTF:** base color, metallic-roughness (roughness in green, metalness in blue), normal (with `scale`), occlusion (red, with `strength`; often the same image as metallic-roughness) and emissive textures. All of a primitive's textures must use the same texture coordinate set as its first one; others are left out. A primitive whose material has no texture keeps its first set (`TEXCOORD_0`) anyway, so the Model Studio reads back the uvs it unwrapped (Phase 58); an FBX mesh's uvs are only read when its material has a texture.
- **FBX:** what `ufbx` maps to PBR, plus the FBX material's own slots: normal map (or a bump map that looks like a normal map: mostly blue, red and green near half; a grey height map is left out), metalness, roughness (inverted for a glossiness map, and for Lambert/Phong, whose shininess map is glossiness), ambient occlusion, emission (a map with no emission color glows in its own colors), opacity (its own map, or the base texture's alpha when it's the same image; alpha if the map has any, else red; any opacity map cuts out at 0.5) and, for Lambert/Phong, specular. A value with a map takes the map's value alone (factor 1), as FBX programs do.
- **Texture roles by name** (Phase 20, FBX; `model/maps.rs`): every texture a material links is also judged by its file name, the last telling word deciding (`Bench_BaseColor_4K`, `T_Bench_N`, `rock_ORM`; words split at `_ - .`, spaces and lowercase-to-capital, sizes such as `4K` and numbers skipped; one-letter suffixes such as `_N`, `_R`, `_M` only at the end). Channel-packed names are split into their channels: ORM/ARM (occlusion, roughness, metalness in R, G, B), RMA, MRA, metallic-roughness (G, B), Unity's metallic-smoothness (metalness R, smoothness A, inverted), HDRP's mask map (metalness R, occlusion G, smoothness A), specular-smoothness (specular RGB, smoothness A) and albedo-transparency (base color, opacity A, cut out). `_NormalDX` maps flip green (a glTF file's normal texture too, when its file is named so: the Model Studio's DirectX bakes, Phase 61). A packed name always wins over the slot the texture is linked to; for Lambert/Phong, whose few slots exporters misuse (Unity puts metallic-smoothness in specular), any name wins; for PBR materials a single-map name only fills slots the links left empty. A texture linked to a property the engine doesn't read is used for its name's role, or noted as unknown ("has a texture `wood.png` it doesn't know the use of…") and left out; height maps (by name, or linked as bump/displacement and not normal-looking) are noted as unused.
- **Unlinked textures** (FBX): textures no material links, often embedded ones, go to the file's only material, or the material whose name (without words such as `mat` and `shader`) is the longest part of the texture's name, and fill only empty maps.
- **SurfaceAppearance** (Phase 21, `scene`): a SurfaceAppearance inside a Part replaces that part's flat color with its maps (the part's `Color` still tints the color map; a metalness or roughness map uses factor 1). `TileSize` on the Part (studs per repeat, default 8; 0 leaves the coordinates unscaled) scales each face by that edge's world length divided by `TileSize`, so a long part repeats the texture instead of stretching it once. Imported models keep their own coordinates. Inside a MeshPart, a SurfaceAppearance replaces the maps of the model's material named its `MaterialName` (others keep the file's). It decides every map: an empty one is no map, so deleting the SurfaceAppearance is the way back to the part's Color and Material, or the file's own. Its `Color` multiplies the material's color. A metalness or roughness map gives the value alone (factor 1); without one, the material's own value is used. `MetalnessChannel`, `RoughnessChannel`, `AmbientOcclusionChannel` and `OpacityChannel` pick channels (`Enum.TextureChannel`), `InvertRoughness` reads a glossiness map, `InvertOpacity` an opacity map that's white where see-through, `NormalStrength` and `NormalMapDirectX` set the normal map, `AmbientOcclusionStrength` the occlusion, and `EmissiveStrength` multiplies the glow (an emission map on a material that doesn't glow glows in the map's colors). `Tiling` (a Vector2, default 1, 1) repeats its maps that many times as often across and down, and `Offset` (a Vector2, default 0, 0) then shifts them, in copies of the texture; on a Part they apply after `TileSize`, and on a MeshPart they replace the file's own texture transform for that material. An opacity map on a solid material cuts it out at 0.5. Map files are read through the project's `Assets` (`Assets::texture`), decoded once, and a file that can't be loaded is reported once ("Could not load the texture `…`: …") and left out. The editor calls `Assets::load_textures_in_background`: a texture not read yet is then left out (drawn as if it had no map) while up to four worker threads decode it, and each one finished wakes the editor to draw again; `Assets::texture_progress` says how many are done. The player keeps reading them before its first frame, on the loading screen. Debug builds optimize dependencies and `render` (`[profile.dev.package]` in the workspace `Cargo.toml`), since unoptimized JPEG decoding and mipmapping take seconds per 4K map.
