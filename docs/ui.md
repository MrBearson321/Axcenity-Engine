# Game UI

Read this for in-game UI. The editor's own windows are [editor/shell.md](editor/shell.md).

## Model

- UI elements are **Instances**: `ScreenGui`, `Frame`, `TextLabel`, `TextButton` (toolbar name Button), `ImageLabel`, `TextBox`, `PageLayout`, `Table`, `ScrollingFrame`, the widgets `Slider`, `Toggle`, `Dropdown` and `ProgressBar`, and `BillboardGui`.
- A `ScreenGui` is a layer. Several can be enabled at once (a HUD and a menu). A page is a `Frame` inside a `PageLayout`, named by `Name`. `CurrentPage` is that name; empty shows the first child Frame. A script that sets a name with no matching Frame is rejected and the last page stays. Hide a whole layer with `ScreenGui.Enabled`.
- `TextButton` has `Text` and `Image`. Empty means unused; both filled is an icon plus a label. `ImageLabel` stays a picture that is not clicked. Saved worlds still use the class name `TextButton`.
- `TextBox` is one line unless `MultiLine` is on. Enter finishes a one-line box. In a multi-line box Enter is a newline and clicking away (or Escape) finishes. Either finish fires `FocusLost` in LocalScripts. Placeholder text shows while `Text` is empty.
- `Table` lays its children out as equal cells, left to right then top to bottom, with an 8 pixel gap. `Columns` (default 2) is how many share a row. A child's CSS width does not change the column size.
- `BillboardGui` is parented to a Part or MeshPart. It is drawn with the screen UI, at the parent position plus `StudsOffset` (world studs, not rotated). `Size` is scale of the viewport plus pixels. `MaxDistance` 0 means no limit.
- **The hotbar** (Phase 45) is drawn over the game UI, under ProximityPrompts (`ui::hotbar_items`, for the runtime's `player_inventory`), unless the Inventory's `HotbarEnabled` is off or it has no Tools: a row of slots centred at the bottom of the screen, one per Tool in order, each with its number (1–9, then 0) at the top left and its `TextureId` image, or its Name with none, and the ToolTip of the Tool in hand over the bar. `Inventory` rules style the bar (`background-color`, `padding`, `gap` between slots (8px), `margin-bottom` from the screen's edge (16px), and the tooltip's `color` and `font-size`); `Tool` rules each slot (`width` and `height` (64px), `background-color`, `color`, `border`, `border-radius`, `font-size` for the name), `Tool:checked` the one in hand, and `Tool::key` the number. A Tool's own `Class` and `Id` pick one slot out. Defaults: translucent near-black slots with white text, the one in hand near-white with dark text. The game UI text scale scales its text. `examples/hello-tools/tools.css` restyles it.
- **The dialogue box and quest tracker** (Phase 77, `ui::dialogue_box_items`, `ui::quest_tracker_items`) are drawn over the game UI while a dialogue runs and while quests are active, styled by the widget type names `DialogueBox` (`::key`, `::option`, `::option:focus`) and `QuestTracker` (`::key`, `::check`): see [scripting/api-dialogue.md](scripting/api-dialogue.md).
- **The leaderboard** (Phase 47) is drawn over the game UI with the hotbar (`ui::leaderboard_items`) while `ScriptRuntime::leaderboard_shown` (Tab toggles it), unless `Players.LeaderboardEnabled` is off or no Player has a `leaderstats` child holding an IntValue, NumberValue, StringValue or BoolValue: a table at the top right with a "Player" column of names and a right-aligned column per stat (by name, in the order first seen), rows sorted by the first stat, highest first. `Players` rules style the board (`background-color`, `color`, `font-size` (14px), `padding` (8px), `border-radius`, `margin-top` and `margin-right` from the screen's edges (16px)), `Players::key` the header row, and `Player` rules each row (`height`, `background-color`, `color`, `font-size`); a Player's own `Class` and `Id` pick one row out. Defaults: a translucent near-black board with white text. The game UI text scale scales its text.
- **The chat window** (Phase 67, `ui::chat_items`) is drawn over the game UI at the bottom left: the newest 8 messages (`CHAT_SHOWN`), each "Name:" then the text (a system message has no name), and, while the player types, a `> line|` under them. `/` opens it (in the player and editor Play, unless a TextBox is being typed in), Enter sends the line (`ScriptRuntime::send_chat`), Esc closes it, and the character stands still meanwhile. Nothing is drawn with `TextChatService.ChatEnabled` off, or with no messages and the chat closed. `TextChatService` rules style the window (`background-color`, `color`, `font-size` (14px), `padding` (8px), `border-radius`, `width` (380px), `margin-left` and `margin-bottom` (16px)), and `TextChatService::key` the names (bold, light blue). The chat itself: [architecture/networking.md](architecture/networking.md).
- **ProximityPrompts** (Phase 44) draw their own UI over everything else, centred over the prompt (`ui::prompt_items`, from the runtime's `shown_prompts`): a box with a round key cap showing the bound key or controller button, the hold ring round it (filled clockwise from the top as the action is held), and `ActionText · ObjectText` on one line. `ProximityPrompt` rules style the box and its text (`background-color`, `color`, `font-*`, `padding`, `border`, `border-radius`, `opacity`); `ProximityPrompt::key` the cap and its letter (`width`, `height`, `font-size` too; it's a circle, or a pill for a long name such as Shift); `ProximityPrompt::ring` the ring: `color` is the held part, `background-color` the rest, `width` the line's thickness. Defaults: white text on translucent near-black, a white cap with dark letters, a white ring. Prompts have no `Id` or `Class`, so every prompt shares the rules. The game UI text scale scales it. `examples/hello-prompt/prompt.css` restyles it.
- **Health bars** (Phase 43). A ProgressBar with an ObjectValue named `Health` inside it whose `Value` is a Health shows that Health: each frame in Play (`ScriptRuntime::step_health`, `script::health::bind_bars`) its `MinValue` becomes 0, `MaxValue` the Health's MaxHealth and `Value` its Health, with no script. Insert ▸ UI ▸ Health bar (the Explorer's Insert menu and the UI tab's Health Bar) binds two to the nearest Health (in or around the selection, else the Workspace's nearest the camera's focus; `editor::tree::health_bar`): a `HealthBillboard` BillboardGui 4 studs over the first part of that Health's Model, holding a 120×14 bar, and a `HealthHud` ScreenGui with a 260×22 bar at the top left. Both bars have the class `health-bar`; when no stylesheet has a `.health-bar` rule it also makes `health-bar.css` (a dark rounded track, a green `::fill`). The Instances and the stylesheet are one undo step. With no Health anywhere only the HUD is made, bound to nothing, and Output says so.
- Each styled element has `Class` (space-separated class names) and `Id` properties, used by CSS selectors. `BillboardGui` has them so descendant rules can target it.
- **Layer order**: **`ZIndex`** (every element but ScreenGui and BillboardGui; default 1) orders siblings and the elements inside them: lower is drawn first, higher on top, and equal ones keep their tree order. CSS `z-index` (a number) wins over it. **`DisplayOrder`** (ScreenGui; default 0) orders the enabled ScreenGuis the same way, before the BillboardGuis and the loading screen. Hit testing, `:hover`, `MouseEnter` and clicks take the topmost element in that same order. Older worlds load with the defaults.
- **`Rotation`** (every element but ScreenGui and BillboardGui; degrees clockwise, default 0; `ui/src/turn.rs`) turns an element and everything in it around its middle, in drawing and hit testing. Layout doesn't change: `Position` and `Size` are the upright box's, and siblings and flex layout don't move. Each `UiElement` keeps the turn on it (`UiElement::turn`, a `UiTurn`: its own `Rotation` and its parents', added up), so `hit`, `:hover`, clicks and scroll bars turn the pointer back into the upright box. The draw list carries the turn as each item's `rotation_degrees`, around its own middle, and a clip's (`UiClip::rotation_degrees`), so a turned element with `overflow: hidden` cuts its children to its turned box; inside a clip turned another way, the smaller of the two clips is kept. `render` turns rectangles and images in their quads, and draws turned text upright onto a sheet first, then turned (`render/src/renderer/turned_text.rs`). CSS `transform` still applies, before the turn.
- **Transparency**: `BackgroundTransparency` (the background), **`TextTransparency`** (TextLabel, TextButton and TextBox; the letters, their outline and their shadows) and `ImageTransparency` (ImageLabel and a TextButton's `Image`) each fade only their own part, from 0 (solid) to 1 (invisible). CSS `opacity` still fades the whole element and its children. Older worlds load with 0.
- **`ScreenInsets`** (ScreenGui; `None` by default, or `DeviceSafeInsets`): with `DeviceSafeInsets`, the ScreenGui is laid out on the screen less the device's unsafe edges (a phone's notch, camera and home bar), as if the safe area were the whole screen (Fit and Scale scale to it). The desktop player's screen has none, so it's the whole screen there. Hosts pass a screen's insets (`SafeInsets`: top, right, bottom, left) in `ArtboardView::safe_insets`; `layout_ui` uses none. `safe_screen_mapping` says where design pixel 0, 0 lands and how big the area is.
- **`ScrollingFrame`** (`ui/src/scroll.rs`) is a Frame whose children sit on a canvas: `CanvasSize` (UDim2 of the frame's own size; default 2 scale down, never smaller than the frame), `CanvasPosition` (a `Vector2`, pixels from the canvas's top left, kept between 0 and as far as the canvas goes), `ScrollingDirection` (`X`, `Y` or `XY`), `ScrollBarThickness` (pixels; 0 hides the bars) and `AutomaticCanvasSize` (`None`, `X`, `Y` or `XY`: the canvas grows that way to reach its children). It always clips its children to its inside. A scroll bar sits over the content, inside the border, on each way the canvas is bigger than the frame; its thumb is as long as the frame is of the canvas (at least 16 pixels). Style them with `ScrollingFrame::scrollbar` (the track; clear unless styled) and `::thumb` (a grey pill unless styled) rules: `background-color`, `border-radius`, `opacity`, `border` and `box-shadow` (`-webkit-scrollbar` and `-webkit-scrollbar-thumb` read the same). A pseudo-element ends its selector (`#list:hover::thumb`, not `#list::thumb:hover`), and those rules don't style the frame itself.
- **Widgets** (`ui/src/widget.rs`): each is one Instance whose parts are drawn, not child Instances, and each has a `Value` that fires **`ValueChanged`** (both sides, with the new value) whenever it changes: by the pointer, a script, a block or a tween. Like other elements they have `Class`, `Id`, `Position`, `Size`, the background, `Visible`, `Interactable`, `Tooltip`, `ZIndex` and `Rotation`, and the Phase 9d states, transitions, `MouseEnter` and `MouseLeave`; `Interactable` off stops the pointer changing them (a script still can). Older worlds have none, so nothing changes for them.
  - **Slider**: `Value` (number), `MinValue`, `MaxValue`, `Step` (dragging picks whole steps from MinValue; 0 is any number) and `Orientation` (`Horizontal`, or `Vertical` with MinValue at the bottom). A press anywhere on it jumps the thumb to the pointer and it follows until the button goes up. A track across the middle (6 pixels thick unless `::track` sets `height`, or `width` when vertical), a `::fill` up to the thumb, and a round `::thumb` (as tall as the slider, at most 20, unless `::thumb` sets `width`/`height`). The thumb's middle stays inside the slider, so its ends are MinValue and MaxValue. `UiElement::track` says where it runs.
  - **Toggle**: `Value` (true or false), flipped by a click (down and up on it), and `Style`: `Switch` (a pill `::track`, grey off and blue on, with a white `::thumb` knob at the left or right) or `Checkbox` (a square `::track` at the left, ticked by a `::check` mark while on). **`:checked`** matches a Toggle that's on, so `#t:checked::track` styles the on track.
  - **Dropdown**: `Options` (one per line), `Value` (the chosen option's text, or any text a script sets; empty shows `Placeholder` faintly), `TextColor3` and `TextSize`. It draws its value and a caret. A click opens its list just below it (above when there's more room there), as wide as it, showing up to six rows (`DROPDOWN_ROWS`, each as tall as the dropdown unless `::option` sets `height`) that the wheel scrolls; the chosen row is tinted blue and the one under the pointer grey. The list is drawn after all other UI (tooltips aside) and takes the pointer first: what's under it isn't hovered or clicked. A click on a row picks it and closes the list; a click anywhere else, the dropdown included, closes it and does nothing else. It closes too if the dropdown is hidden, removed or made not `Interactable`. `::list` styles the box and `::option` each row; rows take the dropdown's text styles (`color`, `font-*`, `letter-spacing`, `text-transform`) unless `::option` sets its own.
  - **ProgressBar**: `Value`, `MinValue`, `MaxValue` and `Orientation` (fills from the left, or the bottom when vertical); display only. Its `::fill` sits inside its border with the inner corner radius, and can be a `linear-gradient`.
  - A part's CSS is read like a ScrollingFrame's parts: `background-color` or a gradient, `border-radius`, `border`, `box-shadow`, `opacity`, and the sizes above. What it leaves out comes from defaults written as CSS (`with_defaults`), so a rule changes only what it names.
- **String table** (`strings.json`; `core/src/strings.rs`, `project/src/strings.rs`): the project's languages, in order, and keys (such as `menu.play`) with a text per language. It's its own optional file, so `FORMAT_VERSION` doesn't change; a damaged one is reported and the table is empty. The `World` keeps it (`World::strings`, `set_strings`) with the active **language** (`World::language`: the one last set, else the table's first). A **`TextKey`** (TextLabel and TextButton; empty by default) names a key: the element shows that key's text in the active language (`axcenity_ui::shown_text`, used by drawing, `text_style` and `TextScaled`), and its own `Text`, the source text, when the key or that language has no text or the language is none. `Text` stays as typed, so scripts read and set the source text. Scripts use `game:GetService("LocalizationService")`: `Language` (set it to one of the table's languages; any other is an error and changes nothing), `Languages` and `GetString(key)` (nil when there's no text); the Looks block "set language to …" is `LocalizationService.Language = …`. A game starts in the first language. Built games and version history include `strings.json`. `examples/hello-strings` switches language from Lua and from blocks.
- **Game UI settings** (`core/src/ui_settings.rs`, `World::ui_settings`; drawing in `ui/src/accessibility.rs`): the player's **text scale** (0.5 to 3, default 1), **higher contrast** and **reduced motion**, separate from the editor's own Appearance settings. They change HUDs and menus in Play, the player and the UI Designer, never the 3D world: text scale multiplies each text's size (its spans', letter spacing and line height too, and `UiElement::font_size` for typing) but not text with `TextScaled` on, and boxes keep their size, so leave text room to grow; higher contrast draws text black or white, whichever is nearer its colour (alpha kept), and any background or part fill that shows at all solid (shadows stay soft). Both are applied to the draw items after layout, so clicks and focus land where they did. Reduced motion makes cosmetic UI motion happen at once: CSS transitions snap (one under way ends), a tween of a GUI Instance (`ClassName::is_gui`) ends as soon as its delay is over (`Completed` fires), and on a GUI Instance an Animation or AnimationTrack that doesn't loop jumps to its end (its markers, then `Completed` or `Stopped`) while a looping one holds where it is; fades are instant. Scripts use `game:GetService("GuiService")`: `TextScale`, `HighContrast` and `ReducedMotion` (both sides share them; a wrong value is an error and changes nothing). A save slot keeps them as the SaveService settings `UI/TextScale`, `UI/HighContrast` and `UI/ReducedMotion` (`SetSetting`/`GetSetting` with those names reach the same values), and loading puts them back; a slot without them leaves them as they are. A game starts with the defaults; they aren't project data. `examples/hello-accessibility` is a settings menu for them.
- **`AccessibleName`** (every element but ScreenGui and BillboardGui; empty by default): what navigation and scripts call a control, as a screen reader would say it. Empty means its `Name` (`Instance::accessible_name`), and a script reading `AccessibleName` gets the name in use. Hosts read the focused element's with `UiInteraction::selected_name`; focus order doesn't change.
- Scripts and blocks change UI through normal properties and events (`Text`, `RichText`, `Visible`, `Interactable`, `ZIndex`, `Rotation`, `TextTransparency`, `CanvasPosition`, `Value`, `Activated`, `MouseEnter`, `MouseLeave`, `ValueChanged`, `CurrentPage`, `FocusLost`). The Looks block "show page" sets `PageLayout.CurrentPage` and "scroll *frame* to x … y …" sets `CanvasPosition = Vector2.new(x, y)`, and "set value of *widget* to …" sets `Value`; the Events blocks "when mouse enters" and "when mouse leaves" connect `MouseEnter` and `MouseLeave`, and "when *widget* value changes" connects `ValueChanged` (its body reads the widget's `Value`).
- **`Interactable`** (every element but ScreenGui and BillboardGui; default on) off turns an element off: it matches `:disabled`, takes no hover (so no `MouseEnter`), a button doesn't fire `Activated` and a text box can't be focused. What's under it doesn't take the click either.
- **`Tooltip`** (the same elements; empty for none) shows a small box near the pointer after it rests on the element for half a second (`TOOLTIP_DELAY`), kept on screen. Style it with a `Tooltip` rule: a type name for the box, styled as a child of its element (`#play Tooltip { background-color: #111 }`); it reads `background-color`, `color`, `font-size`, `font-family`, `font-weight`, `padding`, `border`, `border-radius`, `box-shadow` and `opacity`. Its size is worked out from the text's length, wrapping past 320 pixels.
- **`HoverSound`** and **`ClickSound`** (TextButton; project paths, empty for none) play once through the game's audio when the pointer comes onto the button and when it's activated (`SoundAction::PlayOnce`, not a Sound Instance).
- **`MouseEnter`** and **`MouseLeave`** (LocalScripts only) fire when the pointer comes onto and goes off an element, following the same topmost, visible, interactable hit test as `:hover`, so only the element on top fires and a parent doesn't when the pointer moves onto its child.
- **Keyboard and controller focus** (`ui/src/interact/focus.rs`, `ui/src/gamepad.rs`): one element at a time can have focus, an interactable element of the last layout whose **`Selectable`** is on (every element but ScreenGui and BillboardGui has it; on by default for TextButton, TextBox, Slider, Toggle and Dropdown, off for the rest). Hosts turn keys and controller buttons into `NavKey`s and hand them to `UiInteraction::navigate`, which returns a `UiNavigated` (what to set, a button `activated`, a `text_box` to type in):
  - **The order.** Tab focuses the next element in the tree's order (depth first, as the Explorer lists them) and wraps round; Shift+Tab the one before. The arrow keys, the d-pad and the left stick (past halfway) move to the nearest selectable element that way: its middle must be further that way, and it scores lowest on the gap between the two that way plus twice how far apart they are across it (0 when they overlap), then on how far apart their middles are; nothing that way leaves focus where it is. **`NextSelectionUp`**, **`NextSelectionDown`**, **`NextSelectionLeft`** and **`NextSelectionRight`** (strings, empty by default) override an arrow with the `Id` of the element to go to; one that names nothing focusable (hidden, turned off, or no such `Id`) falls back to the nearest. A held d-pad or stick repeats after 0.4 s, every 0.12 s. With nothing focused, Tab, an arrow or a controller direction focuses the first element (Shift+Tab the last).
  - **The keys** are the input map's UI actions (`UINavigate`, `UIConfirm`, `UIBack`, `UINext`, `UIPrevious`; `ui::nav_key`), so rebinding them changes navigation. By default the keyboard: Tab, Shift+Tab, the arrows, **Enter** (confirm) and **Escape** (back). A controller: the d-pad and left stick, **South** (A, Cross: confirm), **East** (B, Circle: back) and the shoulder buttons (previous and next). In the player and editor Play, Tab is the UI's only when there's something to focus, and the arrows, Enter and Escape only while something is focused (`UiInteraction::takes`); otherwise they go to scripts and movement as before. A controller input only the UI uses (the d-pad, the shoulders) always goes to it; one the game also uses (A for Jump, the left stick for Move) only while the UI takes it (`PadNavigation`). A key or button the UI takes still reaches scripts, with `gameProcessedEvent` true. The editor takes them before egui sees them (`raw_input_hook`), and not while one of its own widgets has the keyboard.
  - **Confirm** does what a click does: a TextButton fires `Activated` (and plays its `ClickSound`), a TextBox starts typing, a Toggle flips and a Dropdown opens its list on its chosen option (else the first), where up and down move through the rows (the lit row follows, and the list scrolls to show it), Confirm picks one and Back closes it; Tab closes it and moves on. **Back** with nothing open lets go of focus. A focused **Slider** moves with left and right (up and down when it's vertical) instead of moving focus: a twentieth of its range a press, in whole `Step`s and at least one.
  - **Typing.** A text box focused by Confirm takes the keyboard like a clicked one; Enter on one line, Escape, or a controller's South or East finishes it and fires the same `FocusLost` a click away does, and focus stays on it, so the arrows carry on from there.
  - **Seeing it.** The focused element matches CSS **`:focus`** (and `:focus-visible`, read the same), which also matches a TextBox being typed in. When no `:focus` rule styles it, a 3-pixel ring in `FOCUS_RING_COLOR` is drawn 2 pixels outside its rounded box, over the UI but under an open list, turned and clipped with it; a text box being typed in keeps its old ring in its text colour unless a `:focus` rule styles it.
  - **Scrolling.** Focus moving onto an element inside a ScrollingFrame scrolls the innermost one (its `CanvasPosition`) just enough to show it (its start, when it's bigger than the frame).
  - A mouse press drops focus. Focus goes when its element is hidden, removed or turned off. A layout that's never navigated draws, hits and scales exactly as before, and nothing is drawn for focus. Older worlds load with the defaults.

## Styling: a CSS subset (plain CSS, not SCSS)

- Plain `.css` files anywhere in the project folder are loaded in path order.
- Selectors: type (`TextLabel`), `.class`, `#id`, comma lists, and descendant selectors, with `:hover`, `:active`, `:disabled`, `:checked` (a Toggle that's on, or a Tool in its Inventory's hand) and `:focus` (keyboard or controller focus, or a TextBox being typed in), and a pseudo-element at the end for a part: `::scrollbar` and `::thumb` (ScrollingFrame), `::track`, `::fill`, `::thumb` (Slider), `::track`, `::thumb`, `::check` (Toggle), `::list`, `::option` (Dropdown), `::fill` (ProgressBar), `::key` and `::ring` (ProximityPrompt), `::key` (a Tool's hotbar number), and `::key` (the leaderboard's header, on `Players`), and `::key` (the chat's names, on `TextChatService`). Specificity and later-source order follow CSS cascade rules.
- Properties: flex layout (`display`, `flex-direction`, `justify-content`, `align-items`, `gap`, `flex-grow`), `width`/`height` (px and %), `padding`, `margin`, `background-color`, `color`, `border`, `border-radius`, `font-family`, `font-size`, the text styles below, `opacity`, CSS variables (`--name` / `var()` with fallbacks), `background-image: linear-gradient(...)` (vertical; a leading `to …` direction is ignored), `box-shadow`, the border properties and `border-image` below. Corners, borders, padding, list layout, shadows and gradients stay CSS. There are no UICorner, UIPadding, UIListLayout, UIShadow or UIGradient objects.
- **`box-shadow`** (`ui/src/css.rs` reads it, `paint.rs` places it, `render/src/ui.wgsl` draws it): shadows separated by commas, the first on top, each `[inset] x y [blur [spread]] [colour]` in px (black when the colour is left out). An outer shadow is the element's rounded box moved, grown by the spread and faded over the blur, behind the element. An `inset` shadow is drawn inside the border and its rounded corners, over the background: everything but a hole, the box moved and shrunk by the spread. Outer and inset shadows mix in one list.
- **Borders**: `border` (`width style colour`), `border-width` and `border-color` (one to four values, top, right, bottom, left), `border-style`, and each side's `border-top` (and so on), `border-top-width` and `border-top-color`; the more specific win. Widths are px, a bare number, `thin`, `medium` or `thick`. The style defaults to `solid`, so a width alone draws a border, and the colour to black. `none` and `hidden` draw none; `dashed`, `dotted` and `double` draw solid. `inset`, `outset`, `ridge` and `groove` take their light and dark edges from the border colour (lit is halfway to white, shaded is half as bright): `inset` shades the top and left and lights the bottom and right, `outset` the other way, and `ridge` and `groove` split each side into an outer and an inner half the opposite ways. Sides meet on the diagonal, and the inside of the border is rounded by `border-radius` less the widest side.
- **`border-image`** (Frame, TextButton and ImageLabel): `url(path) <slices> [fill] [stretch | repeat]`, with one to four slices (top, right, bottom, left) in the picture's pixels; `round` and `space` repeat too, and `none` is none. The picture is cut into nine pieces: the corners are drawn as many design pixels big as their slices (scaled with Fit and Scale, and shrunk together when they don't fit), the edges and middle stretch, or repeat from the top left at the corners' scale with the last tile cut short. The middle is drawn only with `fill`. It's drawn over the background and inset shadows, instead of the CSS border. Each piece is sampled half a pixel inside its cut so smoothing doesn't bleed its neighbour in.
- **Text styles** (`ui/src/css.rs` reads them, `render/src/renderer/text.rs` draws them): `font-weight` (`normal`, `bold`, 100–900), `font-style` (`normal`, `italic`), `text-decoration` (`underline`, `line-through`, both, `none`), `text-transform` (`uppercase`, `lowercase`, `capitalize`; applied to the text in the draw list), `-webkit-text-stroke` or `text-stroke` (`2px #000`: drawn as copies of the letters around them), `text-shadow` (`x y [blur] color`, several separated by commas, the first on top; a blur is nine faint copies spread over it), `letter-spacing` (px or em), `line-height` (a number times the font size, px, em or %; `normal` is 1.2), `text-align`, `vertical-align` (`top`, `middle`, `bottom`: where the lines sit in the box; a button's text defaults to `middle`, a label's to `top`) and `white-space: nowrap` (text wraps by default). They aren't inherited from parents. A ScreenGui in Fit or Scale scales their lengths with everything else.
- **`TextScaled`** (TextLabel, TextButton and TextBox; off by default) draws the text at the largest size that fits its box, up to `font-size` (or `TextSize`), shrinking a long string and growing a short one back to that size. Words aren't broken to fit. The renderer works the size out and keeps it until the text, box or style changes.
- **Rich text** (`ui/src/rich.rs`): with **`RichText`** on (TextLabel, TextButton and TextBox; off by default), tags in `Text` style parts of it, with Roblox-familiar names: `<b>`, `<i>`, `<u>`, `<s>`, `<font color="#rrggbb" size="24" face="Bebas Neue" weight="bold" transparency="0.5">` (`color` takes any CSS colour; `weight` a name or 100–900), `<stroke color="#000" thickness="2" transparency="0">`, `<uc>` (or `<uppercase>`) and `<br/>`. Write `&lt;`, `&gt;`, `&amp;`, `&quot;` and `&apos;` for those characters. Tags nest and change only what they name: the rest (size, colour, font, weight, the outline) comes from the element's own style, and `text-transform`, alignment, spacing, line height, wrapping, shadows and `TextScaled` apply to the whole text. A tag rich text doesn't know, one left open, a stray `</…>`, tags closed in the wrong order or a bad attribute draws the whole `Text` as typed, and Output (or the player's log) warns once with the element's name and what's wrong. The draw list carries the pieces as `UiText::spans`, and `render` shapes them as one paragraph, each in its own face, size and colour, with its own outline, underline and faux bold. Text set from scripts and blocks is read the same way, since it's read when it's drawn.
- **`aspect-ratio`**: width over height (`16 / 9`, `1`, `1.5`; `auto 4 / 3` reads as `4 / 3`, and `auto` alone is none) keeps an element's shape: its width (`Size` or CSS `width`) decides its height, and its `Size` height and CSS `height` are ignored. Taffy lays it out (`Style::aspect_ratio`), so it keeps its shape on any screen. In the editor, every resize handle of such an element changes its width (a top or bottom handle by the height asked for, times the ratio), and the height follows. Table cells keep their own size.
- **`overflow`**: `hidden` (and `clip`, `scroll` and `auto`, which don't scroll; use a ScrollingFrame) cuts the element's children to its inside: its box less its border, rounded by `border-radius` less the widest border side. A clip inside a clip keeps what's in both. What's cut away isn't drawn and doesn't take the pointer. The draw list carries it as each item's `clip` (`UiClip`): rectangles and images are cut to its rounded corners in `ui.wgsl`, text to its box. `visible` (the default) doesn't clip.
- `Visible = false` removes an element from flex layout and hit testing. `:hover` follows the topmost visible element under the pointer (none when that element's `Interactable` is off); `:active` applies to the visible button being held while the pointer remains over it, and `:hover` still applies then; `:disabled` applies while `Interactable` is off. Unsupported properties produce a warning in Output, never a crash.
- **`transform`**: `scale(s)`, `scale(x, y)`, `scaleX`, `scaleY`, `translate(x[, y])`, `translateX` and `translateY` (px, or % of the element's own size), applied right to left as in CSS, around the element's centre. It moves and scales what the element and its children draw, not their layout: clicks, hover and the editor's handles use the laid-out box. Negative scales count as positive.
- **`transition`** (`ui/src/transition.rs`): `<property | all> <duration> [<timing>] [<delay>]`, several separated by commas (later ones win), `none` for none. When an element's styles change (hovered, pressed, disabled, its class changed by a script) `background-color`, `color`, `border-color`, `opacity`, `width`, `height`, `transform`, `box-shadow` and `text-shadow` ease from where they are to the new value. The timing functions are CSS's (`linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, `cubic-bezier(…)`), drawn with `anim::cubic_bezier`, the curve Bezier keys use. Values blend number by number once colours are written as `rgba()`, so two values of different shapes (`auto` and `40px`, or two different transform lists) snap; `none` blends from `scale(1)`/`translate(0)` for `transform` and from a clear, zero-sized shadow. A property no CSS sets blends from the element's own `BackgroundColor3` and `BackgroundTransparency`, `TextColor3`, or `Size` in pixels; a change between two such values (a script setting `BackgroundColor3`) doesn't transition. A transition starts on the frame that first sees the change. It needs time, so only layouts made through a host's `UiInteraction` (the player, the editor's viewport) animate; `layout_ui` and the artboard show the end values.
- **`cursor`**: `pointer`, `text`, `not-allowed` or `default` sets the OS cursor over the element in Play and the player. A button that's interactable shows a hand and a text box an I-beam unless CSS says otherwise.
- Specificity and cascade follow normal CSS rules for the supported subset.

## Layout and drawing

- Layout is computed by **`taffy`** (frame order step 5). Text is shaped with `cosmic-text` or `glyphon`.
- `ui` resolves styles and produces UI draw data, and `render` draws it as an overlay, in order: later items cover earlier ones, text included. Siblings are laid out in tree order (so flex order doesn't change) and drawn in layer order. Enabled ScreenGuis are drawn by `DisplayOrder`, then BillboardGuis, then `UiInput::on_top` (the game's loading screen, `loading.rs`'s `LoadingGui`; see [project/export.md](project/export.md)), which also takes the pointer first. The editor viewport previews UI while editing as well as during Play; edit-mode scripts do not run.
- **Cost per frame** (roadmap M14): `UiInteraction::layout` lays the UI out twice, once with nothing hovered to find what the pointer is over and once with that element's `:hover` and `:active`. Both passes share a `StyleCache` (`style.rs`): each element's rules are matched once and it inherits its parent's custom properties, and the second pass matches again only the hovered and pressed elements and what's inside them. Transitions ease an element's styles once a frame however often they're read. The first pass isn't painted. A host that hit-tests clicks before laying out (the editor's viewport) calls `UiInteraction::hit_layout`, which `layout` reuses as its first pass. Nothing is kept between frames, so any change to the world shows on the next one. `cargo test -p axcenity-ui --release --test bench_inventory_ui -- --ignored --nocapture` times a 500-element inventory ([benchmarks](benchmarks.md#ui-layout-m14)).
- `TextButton.Activated` fires on release after a press that began and ended over the same visible, interactable button. Only LocalScripts receive it.
- **Hosts** keep one `axcenity_ui::UiInteraction` for a game and lay the UI out through it each frame with the pointer, held button, focused text box and the frame's length (`UiInput`): it resolves hover and press, runs the transitions, draws the tooltip on top, says which cursor to show (`UiLayout::cursor`) and whether to keep drawing (`UiLayout::animating`), and queues `UiEvent`s (`MouseEnter`, `MouseLeave`, `PlaySound`). `UiInteraction::activate` says whether a clicked button fires and queues its `ClickSound`. **Scrolling** goes through it too, by the last layout: `wheel` (the wheel over a ScrollingFrame scrolls the innermost one that can move that way, and a frame that only scrolls across takes up and down; the host doesn't zoom its camera while it's over one), `press` (on a scroll bar it drags the thumb, a press on the track jumping it there first, and the press presses no button), `drag` (each frame the button is held; dragging the content scrolls it once the pointer has moved 6 pixels, `SCROLL_DRAG_SLOP`, and then the button it went down on doesn't fire) and `release`. Each returns a `UiScrolled`: whether it took the input, the `CanvasPosition` to set, and a widget's new `Value`, which `UiScrolled::apply` sets (the editor's viewport hands both to the Play world). The **widgets** go through it too: `press` on an interactable Slider starts its drag (and `drag` carries it on, needing the world for its range), on a Toggle or Dropdown waits for `release(world, pointer)`, which flips the Toggle or opens the list if it's let go over the same one, and while a list is open `press` and `release` pick from it or close it. A taken press presses no button and focuses no text box. `UiInteraction::open_dropdown` says which list is open. The UI Designer's artboard uses `press_scroll_bar`, which takes only scroll bars, so widgets there are selected and moved, not used. The player passes the events on at the start of the next frame, before input; the editor's viewport hands them to the Play session, which drops them while editing. `ImageLabel.Image` and `TextButton.Image` are project-relative asset paths and are drawn.
- **Fonts**: `font-family` names a family. Built in (`render/src/fonts.rs`, all SIL OFL): Montserrat (the default and `sans-serif`), Inter, Roboto, Poppins, Nunito, Oswald, Bebas Neue, Bangers, Lobster, Press Start 2P, Lora (`serif`) and JetBrains Mono (`monospace`). A project's own `.ttf` and `.otf` files, anywhere in its folder, work by their family name too: `Assets::fonts` reads them, the draw list carries them, and the renderer loads each the first time it's seen. Built games include them. Quote names with spaces (`font-family: "Bebas Neue"`).
- **Weights and italics**: the draw list carries each text's weight and style, and `render` picks the family's face (`pick_face`): its italic faces when it has any, then the nearest weight. Montserrat, Inter, Poppins and JetBrains Mono have real Bold, Italic and Bold Italic files; Roboto, Nunito and Lora have a real italic (their variable files draw at the regular weight). A project's own files join a family by the name inside them, so `MyFont-Bold.ttf` is MyFont's bold wherever it is, and built games include every `.ttf` and `.otf`. A weight of 600 or more that the family has nothing bold for is drawn faux bold (each copy of the letters three times, a little apart), and italic with no italic face is slanted.

## Editing UI in the editor

- The toolbar's UI group inserts a ScreenGui, Frame, TextLabel (Text), TextButton (Button), ImageLabel (Image), TextBox, PageLayout (Pages), a page Frame (Page), Table, ScrollingFrame (Scroll), Slider, Toggle, Dropdown, ProgressBar (Progress) or BillboardGui, or the ready-made **Controls** menu (a ScreenGui and its LocalScript; see `docs/scripting/client-server.md`). A screen element goes into the selected ScreenGui, Frame, PageLayout, Table or ScrollingFrame, else the ScreenGui around the selection or the Workspace's first; with no ScreenGui at all, one is inserted first. Page inserts a Frame named Page into the selected PageLayout, creating a PageLayout (and a ScreenGui) when there isn't one. BillboardGui goes into the selected part.
- Like Roblox Studio, the selected element gets handles in the viewport: drag its body to move it and a square to resize it (see `ui_handles.rs`). The drag snaps when an edge or center comes within 8 points of an edge or center of another element, or of the screen, and a magenta guide line shows the alignment. A flex child is not snapped, because the layout places it. Where CSS sets `width` or `height`, resizing rewrites that CSS value (in its own units) instead of `Size`.
- While those handles are showing, a label under the element gives its size in screen pixels and how far it sits from the left, right, top and bottom of the screen. A child of a Frame, Table or other element also shows those distances to its parent, in magenta, and still uses the same handles. BillboardGui children keep those handles in the world view.
- A ScreenGui's `ScaleMode` is `Fixed` (the class default: positions and sizes are as authored, in screen pixels), `Fit` or `Scale`. Both Fit and Scale scale it evenly by how the screen compares to `DesignWidth` by `DesignHeight` (default 1920×1080), by as much as fits. Fit lays it out on the design rectangle and centres that, leaving empty bars on another aspect ratio. Scale lays it out over the whole screen, measured in design pixels, so what's pinned to an edge stays against it (like Unity's Scale With Screen Size). ScreenGuis inserted in the editor start in Scale; ones made by scripts or saved before keep their mode. Dragging a handle still edits the design-pixel `Position`, `Size` or CSS length. Set the design size to the resolution you laid the UI out at.
- **Anchors** are written in `Position` and `Size`: a `UDim2`'s scale is where in the parent it's measured from and its offset the distance. Pinned to the right means `Position.X` scale 1 with a negative offset; centred, scale 0.5; stretched, `Position` scale 0 and `Size` scale 1 with the margins in the offsets. Nothing else is saved, so Play and the player need nothing new.
- **Add a style** autocompletes property names and, for the supported ones, their values (flex, colors, lengths and so on). Tab takes the first match; clicking a suggestion fills it in. The same suggestions appear on a value that is already set, while that box is focused.
- Unlike Studio, the Properties panel also has a **Style (CSS)** section, like a browser's style inspector: the declarations that apply to the element, grouped by rule with a link to the rule's line, each value editable in place (colours with a swatch). Edits rewrite the stylesheet's text in its tab (unsaved until Ctrl+S) and restyle the viewport at once. **Add a style** puts `property: value` into the element's own `#Id` rule: an element without an `Id` gets one from its name, the rule is made at the end of the first stylesheet if it doesn't exist, and a project with no stylesheet gets `ui.css`.
- Style edits and handle drags are undo steps like any other: the stylesheet's text before and after goes in the step (one step per drag or per value typed), and undoing the style that made `ui.css` deletes it again.
- **UI Designer** (a dock tab beside the Scene View; `ui_designer.rs` and `ui_designer/`): the selected ScreenGui (or the one around the selected element, else the Workspace's first) on an artboard. With no ScreenGui at all it says what one is (a layer of 2D interface drawn over the game) and offers **New ScreenGui**. The toolbar picks the ScreenGui, its scale mode (Fixed, Fit, Scale; each says on hover what it does), its design size (typed, or ▾ for common screens), the screen to **Preview** on (the design size, a preset from 4:3 and 16:9 desktops to ultrawide, tablet and phones, or a custom size; this isn't saved), and the zoom; Fit fits the artboard into view. Right- or middle-drag and the wheel pan, Ctrl + wheel zooms. The artboard is `axcenity_ui::layout_artboard`: the same layout a screen of that size gets in Play (shown even when `Enabled` is off), drawn by the game's renderer over a grey backdrop. A note offers **Use Scale** when a ScreenGui is Fixed or Fit, and says when it's disabled.
- **Rulers** along the top and left are in design pixels, with the selected element's extent marked. Drag down from the top ruler or right from the left one for a **guide**; elements snap to guides as they do to other elements' edges. Drag a guide to move it, or back onto a ruler to remove it. Guides are kept per ScreenGui while the editor runs and aren't saved. The selected element shows the viewport's size and distances to the screen and its parent, in design pixels, and diamonds where it's anchored.
- The inspector's **Anchor** grid (4×4, like Unity's presets: left, centre, right or stretched across; top, middle, bottom or stretched down) pins the selected element without moving it at the design size (`ui_designer/anchors.rs`). A flex child has no anchor. An anchor is the `UDim2` scales of `Position` and `Size`: on each axis the element's start is pinned at `Position`'s scale and its end at that plus `Size`'s scale, so apart means stretched. **Font** picks the text's `font-family` (into the element's own `#Id` rule) from the built-in fonts and the project's own; **Look again** rereads the project's font files after one is added.
- **Text toolbar** (`ui_designer/text_toolbar.rs`), under Font for an element with text: **B**, **I**, **U** and **S** toggles, an **Aa** case menu (`text-transform`), alignment across and up and down, Size, colour, **Outline** (width and colour), **Shadow** (x, y, blur and colour; edits the first shadow), letter spacing, line height (times the size), **Wrap** and **Text Scaled**. Each control writes one property into the element's own `#Id` rule (changed in place if it's there, else added), except Text Scaled, which is the property. It shows what the element's styles make of it, from whichever rule (`axcenity_ui::text_style`). Each click is one undo step, and a dragged value is one step. Ctrl+B, Ctrl+I and Ctrl+U toggle bold, italic and underline on the selected element while nothing is being typed in.
- **Anchor diamonds** (`ui_designer/anchor_handles.rs`): the selected element has one at each corner of its anchor, pointing at it, so a joined anchor shows four round one point. Press the point itself to drag them all; press one diamond to drag its own ends, which splits the anchor and stretches the element on that axis (dragging an end past its pair pushes the pair along). A dragged anchor snaps to the parent's edges, middle and its pair (rejoining it), with the magenta line; Alt drags freely, in whole percent. A label shows the anchor in percent of the parent. The offsets are rewritten so the element doesn't move at the design size. **Reset** under the grid, or **Reset anchor** on a diamond's right-click menu, anchors it back at the top left, unstretched, without moving it. One drag or one reset is one undo step.
- **States editor** (`ui_designer/states.rs`), in the inspector of a TextButton or TextBox, or of any element with its own `#Id:hover`, `#Id:active` or `#Id:disabled` rule: **Normal**, **Hover**, **Pressed** and **Disabled** tabs (they wrap onto two lines in a narrow column). In a tab, Background (a swatch), Scale (`transform: scale`) and Opacity, and the text toolbar above (headed "Text · Hover"), show the element in that state and write into that state's rule, made at the end of the first stylesheet if it isn't there, so no CSS is typed; Normal is the element's own `#Id`. A value that rule already has is changed in place. Ctrl+B, Ctrl+I and Ctrl+U follow the tab too. **Transition** (on, a duration and a timing function) writes `transition: all 0.15s ease` into `#Id` (`none` when off), and **Interactable** is the property. The eye beside the tabs, and the "Showing Hover" chip it puts on the artboard's top left corner, show the selected element in that state on the artboard (`axcenity_ui::layout_artboard_in_state`) whatever the pointer does; it's on until clicked off. Each edit is one undo step, and a dragged value is one.
- **Bevel** (`ui_designer/bevel.rs`), in the inspector of every element but the ScreenGui: **None**, **Raised** or **Sunken**, then **Depth**, **Softness** (the blur) and **Light** (the angle the light comes from: 0 the right, 90 the top, 135 the top left). It writes two inset shadows into `box-shadow` in the element's own `#Id` rule: `rgba(255, 255, 255, 0.6)` along the edges facing the light and `rgba(0, 0, 0, 0.45)` opposite (the other way round when sunken). White first means Raised and black first Sunken, which is how the inspector reads a bevel back. On a TextButton it also writes the flipped pair into `#Id:active`, so it looks pushed in while held. Editing the bevel rewrites only that pair; the element's other shadows stay, in order. Each edit (both rules) is one undo step, and a dragged value is one.
- **Slice** (`ui_designer/slice.rs`), for a Frame, TextButton or ImageLabel: type the picture's project path into **Image** (written when the box is left; a new picture is cut a quarter of the way in, middle filled). The picture is shown with its four cuts as lines: drag one to move that cut, in whole picture pixels, kept short of the opposite cut. **Top**, **Right**, **Bottom** and **Left** set them as numbers, with **Fill middle**, **Stretch** or **Repeat**, and **Remove** (`border-image: none`). Each writes `border-image` into the element's own `#Id` rule, one undo step per edit or drag.
- **Double-click** text on the artboard (or its row in the hierarchy) to type over it, at the size it's drawn (CSS `font-size`, else `TextSize`); Enter or clicking away finishes, Escape puts it back. Clicks and drags in the box place the caret and select text; they don't select or move what's under it. The typing is one undo step. A click that doesn't move doesn't snap or move anything. With `RichText` on, the box shows the source in its tags' styles (bold, italic, underline, strikethrough, colour and size, with the tags small and faint; a one-line box scrolls rather than wraps), and a bar over it has **B**, **I**, **U**, **S** and eight colours (`ui_designer/rich_text.rs`). Ctrl+B, Ctrl+I, Ctrl+U or the bar wraps the selection in `<b>`, `<i>`, `<u>`, `<s>` or `<font color>`; the same again on a selection wrapped in just that tag takes it off (another colour changes the colour). Tags inside the selection stay where they are and the text between them is wrapped piece by piece, so tags stay nested. Wrapping is part of the typing's one undo step, and typing carries on after the bar is used. With nothing selected, or `RichText` off, Ctrl+B, Ctrl+I and Ctrl+U change the element's own style, as outside the box. The inspector's Text field shows the tagged source.
- **Rotate knobs** (`ui_designer/rotate.rs`): the selected element has a small round knob just outside each corner. Drag one around the element's middle to set its `Rotation`, in tenths of a degree; hold Shift to snap to 15° steps. A label by the pointer says the angle. One drag is one undo step. A turned element's outline, handles and knobs turn with it (`ui_handles.rs`): a resize is measured along its own axes and a move along its parent's, and it doesn't snap to edges or guides.
- **Look** (`ui_designer/panels.rs`), in the inspector of every element but the ScreenGui: **Rotation** in degrees, and **Background**, **Text** and **Image** transparency as 0–100% sliders, for the parts the element has. Properties shows the same three sliders, `Rotation` in degrees and `ScreenInsets` as a choice.
- **Safe area on the artboard**: the Phone portrait (390 × 844) and Phone landscape (844 × 390) screens have a notch and home bar (`ui_designer::safe_insets`: 47 at the top and 34 at the bottom in portrait; 47 at each side and 21 at the bottom in landscape), hatched in orange over the artboard whatever the ScreenGui's `ScreenInsets`. A ScreenGui with `DeviceSafeInsets` is laid out inside them, and the rulers, guides and drops measure from its safe corner. Other screens have none.
- **Layer order** (`ui_designer/order.rs`): right-click an element in the hierarchy, or on the artboard, for **Bring to Front**, **Bring Forward**, **Send Backward** and **Send to Back** among its siblings (each greyed out when it's already there). It changes the element's own `ZIndex` to the whole number that puts it there, and raises the ones above it only when no number fits between its new neighbours; an element CSS places gets `z-index` in its own `#Id` rule instead. The tree order doesn't change, so a flex layout doesn't move. One menu pick is one undo step.
- **Scrolling on the artboard**: the wheel over a ScrollingFrame scrolls it (instead of panning), and its bars can be dragged. The designer keeps those positions itself (`ArtboardView::scrolled`, while the editor runs), so the saved `CanvasPosition` doesn't change and nothing is an undo step; dragging its content still moves elements.
- **Widget** (`ui_designer/widget_section.rs`), in the inspector of a Slider, Toggle, Dropdown or ProgressBar: a Slider's **Value**, **Min**, **Max** and **Step** and a ProgressBar's first three, with **Horizontal**/**Vertical**; a Toggle's **On** and **Switch**/**Checkbox**; a Dropdown's **Options** (one per line), **Chosen** (picked from them, or none) and **Placeholder**. Each edit is the property, one undo step (a dragged number is one). Properties shows `Orientation` and `Style` as choices and `Options` as several lines. The parts are styled in CSS.
- **Several elements** (`ui_designer/selection.rs`, `group.rs`, `arrange.rs`; applied in `app/ui_selection.rs`): Shift-click and Ctrl-click (Cmd on macOS) on the artboard or in the hierarchy add to the selection (Ctrl takes a selected one away; Shift in the hierarchy adds the rows between), and a drag that starts on empty artboard draws a box that selects the elements wholly inside it whose parent isn't (Shift or Ctrl keeps what was selected). Several selected elements get one dashed box of handles around them all instead of their own handles, anchors and knobs: drag inside it to move them all (it snaps like one element) and a square to resize them, each keeping its share of the box (a flex child is resized but not moved; a CSS `width` or `height` is rewritten as one element's is). One drag is one undo step. The **arrange bar** under the toolbar aligns the selection's left, centre or right edges, or top, middle or bottom, with each other (one element: with its parent), distributes three or more evenly across or up and down (the outer two stay, the gaps become equal), and has **Copy style** (the element's own `#Id` declarations), **Paste style** (written into each selected element's own `#Id` rule, changed in place where it has them; one without an `Id` gets one) and **Duplicate**; the right-click menus have the last three too, then **Rename** (selects the element and puts the keyboard in the inspector's Name, all selected, so typing replaces it) and **Delete** (what the Delete key does: the selection, or the right-clicked element when it isn't in it, as one undo step). Arrow keys nudge the selection 1 design pixel and Shift+arrows 10. **Ctrl+C** copies the selected elements (as prefab text, also put on the system clipboard) and **Ctrl+V** pastes them into the container around the selection, in any ScreenGui; pasted and duplicated elements get fresh `Id`s and copies of their own rules. Each is one undo step, and none of these keys do anything while a text field is being typed in.
- Around the artboard: **Elements** (Frame, Text, Button, Image, TextBox, Pages, Page, Table, Scroll, Slider, Toggle, Dropdown, Progress) to drag onto it, where they go into the Frame, PageLayout, Table or ScrollingFrame under the pointer (else the ScreenGui) with their top left at the drop point; a click adds one to the selected container instead. The **Hierarchy** lists the ScreenGui's elements; a click selects. The inspector edits the selected element's Name and Text, then shows the same **Style (CSS)** section as Properties. On the artboard a click selects an element and a drag moves it; the selected element has the viewport's handles and snapping (`ui_handles.rs`). Every designer edit goes through `EditorApp::change`, the tree edits or the stylesheet tabs, so it undoes, shows in the Scene View, and plays the same. Below 640 points wide the artboard goes on top with the panels under it.
- **Focus arrows** (`ui_designer/navigation.rs`): a selected element whose `Selectable` is on has a small arrow just outside the middle of each edge, beyond its resize handles. One whose `NextSelection…` that way names an element is filled, with a line to it. Drag an arrow onto another selectable element (or anything inside one) to point it there: the property is set to that element's `Id`, and an element without an `Id` gets one from its name in the same undo step. Let go over nothing to clear it. An arrow that sits over another element gives way to it, so a click there selects that element. Properties lists `Selectable` and the four `NextSelection…` with the other UI properties.
- **Strings** (the designer's third tab; `ui_designer/strings.rs`): the string table. **Languages** lists them, each with × to remove it and its text; type a name and **Add language** (or Enter). Type a key and **Add key**. Each key is listed with a box per language and a bin to delete it. Each add, remove or delete is one undo step, and typing in one box is one (`History::record_strings`, which keeps the table before and after). Saving the project writes `strings.json` (none is made while the table is empty). The toolbar's language picker (beside the tabs, when the table has languages) picks the language the artboard and Scene View show bound text in; it isn't saved or an undo step, and Play starts in it (during Play it changes the game's). The inspector's **Key**, under Text for a TextLabel or TextButton, binds the element to a key (or **None**) as one undo step, and says whether it shows its text in the shown language or its own Text. Properties shows `TextKey` with the other UI properties. A world file reloaded after an outside change keeps the table.
- **Game UI settings menu** (the person icon at the end of the arrange bar, under the toolbar; `ui_designer/accessibility.rs`): text scale, higher contrast and reduced motion, as a player would set them, so the artboard and Scene View show the UI that way. Like the language picker it isn't saved or an undo step, Play starts with them (during Play it changes the game's), and it never changes the editor's theme.
- **Eyes** (`ui_designer/pages.rs`): each Hierarchy row but the ScreenGui's has an eye at its right end. On a page (a Frame in a PageLayout) it picks the page the artboard shows, so several pages can be worked on in turn whatever `CurrentPage` says; on anything else it hides the element and what's in it on the artboard. Rows not drawn on the artboard are dimmed. Selecting an element on another page (anywhere: the Hierarchy, the Explorer) shows that page. None of it is saved or an undo step, and it changes nothing in the world: Play, the Live Preview, the Scene View and the Pages tab show the game's `Visible` and `CurrentPage`. The artboard gets it through `axcenity_ui::DesignerOverrides` (`hidden`, `pages`) on `ArtboardView`.
- **Pages** (the designer's fourth tab; `ui_designer/pages.rs`): every ScreenGui in the Workspace as a card (how it looks, its name and how many pages it has), in a column at the left, or a row on top below 640 points wide. Clicking one picks it (it becomes the designer's ScreenGui, selected; `UiDesigner::pick_screen`); double-clicking opens it in the Design tab. The picked ScreenGui's pages (`pages::screen_slides`: one per Frame of each of its PageLayouts, at any depth and in tree order, or one for a ScreenGui without pages) are drawn as the game draws them at its design size, by the game's renderer: one large, with ◀ and ▶ (or ← and →) and its title (`Menu › Settings`, with the PageLayout's name when a ScreenGui has several), then each PageLayout (`pages::page_layouts`) with its name, its page count and the page the game starts on, and its pages as thumbnails, that start page flagged, ending in **+ Page** (adds a page to it). A click on a thumbnail shows it large; **Edit page**, or a double-click on it or the large one, opens it in the Design tab with that page shown (its eye) and selected; a thumbnail's right-click menu has **Edit page** and **Start on this page** (the PageLayout's `CurrentPage`, one undo step). A ScreenGui without pages says so and has **Add pages**: a Page dropped or added in the designer goes into the PageLayout it's aimed at, or the one around it, else into a new PageLayout in that container, never into another ScreenGui's (`designer_insert`).
- **Styles** (`ui_designer/style_sets.rs`), in the inspector of every element but the ScreenGui: ready-made looks as tiles drawn in their colours, for the element's kind (`style_sets::BUILT_IN`: eight for buttons, seven for frames, scrolling frames, tables and images, eight for text labels, three for text boxes, sliders and toggles, four for progress bars and two for dropdowns), and **Import**, a menu of the project's stylesheets' rule sets (`axcenity_ui::rule_sets`: each simple selector such as `.card`, `#play` or `TextButton` with its states and parts, `.card:hover`, `.card::thumb`; descendant and comma selectors are left out) and **From a .css file…**, which reads any stylesheet on this computer: one rule set is applied at once, several are shown as tiles under the built-in ones until put away (×). Picking one copies every declaration into the element's own rule for that state or part (`#play`, `#play:hover`, `#play:checked::track`), changed in place where it has one (`EditorApp::apply_style_set`, which Paste style uses too), as one undo step named "Style Play as Primary"; an element without an `Id` gets one, and with several selected each gets it. The copy is the element's own CSS, so the Style (CSS) section, the states editor and the text toolbar edit it like any other, and nothing links it to where it came from. The built-in sets are CSS written for `.set`; within a kind each names the same properties in the same states (a test checks), so picking another replaces the whole look. The tile of the set the element's own rules already match is outlined.
- **Code & animation** (`ui_designer/links.rs`, applied in `app/ui_links.rs`), in the inspector of every element but the ScreenGui: its Lua path (`workspace.Menu.Panel.Play`, `["…"]` for a name that isn't a Lua name) with a copy button; **When**, a button per event its class fires (`ClassName::events`: `Activated`, `FocusLost`, `ValueChanged`, `MouseEnter`, `MouseLeave`), which writes `path.Event:Connect(function() end)` (`function(value)` for `ValueChanged`) at the end of the ScreenGui's LocalScript and opens it with the cursor inside: the first Lua LocalScript that names the ScreenGui's path, as an unsaved change in its tab, else a new `scripts/<ScreenGui>.client.lua`; on a TextButton, **Play on click** lists the Animations in its ScreenGui and writes the same with `animation:Play()` in it; **In scripts**, each line of a Lua script (its tab's text when open) that names the element after a `.` or alone in quotes, outside comments, up to eight, each opening that script on that line; the element's Animations (its own and its Animator's), each opening its clip in the Animation tab; and **Animate <name>** (**New animation** once it has one), which is `EditorApp::animate`.
- **Image** (`ui_designer/image.rs`), in the inspector of an element with an `Image` (ImageLabel, TextButton): a thumbnail and the picture's name, which opens a grid of the project's images and textures (`AssetBrowser::pictures`; global assets aren't listed) to pick from; ⇪ **Upload** asks for a picture on this computer and copies it into `assets/images` (`Edit::PickTexture("Image")`); × shows none. An image or texture dragged from the Assets panel onto the row is used too. Each is one undo step. Properties' `Image` row has the same upload button and drop, beside the typed path.
- **Colours in stylesheet tabs** (`scripts.rs`, `css_syntax::colors`): like Roblox Studio's script editor, each colour in a value (`#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()` or a name) has a swatch in a gap before it (see-through ones over a checker). Clicking one opens a colour picker beside it; picking rewrites that colour in the text (`#rrggbb`, or `rgba()` when it's see-through, as the Style section writes it), which restyles at once like typing. Escape or a click elsewhere closes it.
- **Event Graph** (the designer's second tab) and **Live Preview**: what the ScreenGui's buttons and text boxes do, as nodes compiled to a LocalScript under it, tried on the artboard without Play. See [scripting/ui-graphs.md](scripting/ui-graphs.md).
- Stylesheets edited in another program (VS Code) restyle the viewport when saved there, unless the editor has unsaved changes to them, which are kept.
