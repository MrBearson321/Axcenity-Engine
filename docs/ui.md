# Game UI

Read this for in-game UI. The editor's own windows are [editor/shell.md](editor/shell.md).

## Model

- UI elements are **Instances**: `ScreenGui`, `Frame`, `TextLabel`, `TextButton` (toolbar name Button), `ImageLabel`, `TextBox`, `PageLayout`, `Table`, `BillboardGui`.
- A `ScreenGui` is a layer. Several can be enabled at once (a HUD and a menu). A page is a `Frame` inside a `PageLayout`, named by `Name`. `CurrentPage` is that name; empty shows the first child Frame. A script that sets a name with no matching Frame is rejected and the last page stays. Hide a whole layer with `ScreenGui.Enabled`.
- `TextButton` has `Text` and `Image`. Empty means unused; both filled is an icon plus a label. `ImageLabel` stays a picture that is not clicked. Saved worlds still use the class name `TextButton`.
- `TextBox` is one line unless `MultiLine` is on. Enter finishes a one-line box. In a multi-line box Enter is a newline and clicking away (or Escape) finishes. Either finish fires `FocusLost` in LocalScripts. Placeholder text shows while `Text` is empty.
- `Table` lays its children out as equal cells, left to right then top to bottom, with an 8 pixel gap. `Columns` (default 2) is how many share a row. A child's CSS width does not change the column size.
- `BillboardGui` is parented to a Part or MeshPart. It is drawn with the screen UI, at the parent position plus `StudsOffset` (world studs, not rotated). `Size` is scale of the viewport plus pixels. `MaxDistance` 0 means no limit.
- Each styled element has `Class` (space-separated class names) and `Id` properties, used by CSS selectors. `BillboardGui` has them so descendant rules can target it.
- Scripts and blocks change UI through normal properties and events (`Text`, `RichText`, `Visible`, `Activated`, `CurrentPage`, `FocusLost`). The Looks block "show page" sets `PageLayout.CurrentPage`.

## Styling: a CSS subset (plain CSS, not SCSS)

- Plain `.css` files anywhere in the project folder are loaded in path order.
- Selectors: type (`TextLabel`), `.class`, `#id`, comma lists, and descendant selectors. Specificity and later-source order follow CSS cascade rules.
- Properties: flex layout (`display`, `flex-direction`, `justify-content`, `align-items`, `gap`, `flex-grow`), `width`/`height` (px and %), `padding`, `margin`, `background-color`, `color`, `border`, `border-radius`, `font-family`, `font-size`, the text styles below, `opacity`, CSS variables (`--name` / `var()` with fallbacks), `background-image: linear-gradient(...)` (vertical; a leading `to …` direction is ignored) and `box-shadow` (drawn as a larger, softer rectangle behind the element). Corners, borders, padding, list layout, shadows and gradients stay CSS. There are no UICorner, UIPadding, UIListLayout, UIShadow or UIGradient objects.
- **Text styles** (`ui/src/css.rs` reads them, `render/src/renderer/text.rs` draws them): `font-weight` (`normal`, `bold`, 100–900), `font-style` (`normal`, `italic`), `text-decoration` (`underline`, `line-through`, both, `none`), `text-transform` (`uppercase`, `lowercase`, `capitalize`; applied to the text in the draw list), `-webkit-text-stroke` or `text-stroke` (`2px #000`: drawn as copies of the letters around them), `text-shadow` (`x y [blur] color`, several separated by commas, the first on top; a blur is nine faint copies spread over it), `letter-spacing` (px or em), `line-height` (a number times the font size, px, em or %; `normal` is 1.2), `text-align`, `vertical-align` (`top`, `middle`, `bottom`: where the lines sit in the box; a button's text defaults to `middle`, a label's to `top`) and `white-space: nowrap` (text wraps by default). They aren't inherited from parents. A ScreenGui in Fit or Scale scales their lengths with everything else.
- **`TextScaled`** (TextLabel, TextButton and TextBox; off by default) draws the text at the largest size that fits its box, up to `font-size` (or `TextSize`), shrinking a long string and growing a short one back to that size. Words aren't broken to fit. The renderer works the size out and keeps it until the text, box or style changes.
- **Rich text** (`ui/src/rich.rs`): with **`RichText`** on (TextLabel, TextButton and TextBox; off by default), tags in `Text` style parts of it, with Roblox-familiar names: `<b>`, `<i>`, `<u>`, `<s>`, `<font color="#rrggbb" size="24" face="Bebas Neue" weight="bold" transparency="0.5">` (`color` takes any CSS colour; `weight` a name or 100–900), `<stroke color="#000" thickness="2" transparency="0">`, `<uc>` (or `<uppercase>`) and `<br/>`. Write `&lt;`, `&gt;`, `&amp;`, `&quot;` and `&apos;` for those characters. Tags nest and change only what they name: the rest (size, colour, font, weight, the outline) comes from the element's own style, and `text-transform`, alignment, spacing, line height, wrapping, shadows and `TextScaled` apply to the whole text. A tag rich text doesn't know, one left open, a stray `</…>`, tags closed in the wrong order or a bad attribute draws the whole `Text` as typed, and Output (or the player's log) warns once with the element's name and what's wrong. The draw list carries the pieces as `UiText::spans`, and `render` shapes them as one paragraph, each in its own face, size and colour, with its own outline, underline and faux bold. Text set from scripts and blocks is read the same way, since it's read when it's drawn.
- `Visible = false` removes an element from flex layout and hit testing. `:hover` follows the topmost visible element under the pointer; `:active` applies to the visible button being held while the pointer remains over it. Unsupported properties produce a warning in Output, never a crash.
- Specificity and cascade follow normal CSS rules for the supported subset.

## Layout and drawing

- Layout is computed by **`taffy`** (frame order step 5). Text is shaped with `cosmic-text` or `glyphon`.
- `ui` resolves styles and produces UI draw data, and `render` draws it as an overlay. The editor viewport previews UI while editing as well as during Play; edit-mode scripts do not run.
- `TextButton.Activated` fires on release after a press that began and ended over the same visible button. Only LocalScripts receive it. `ImageLabel.Image` and `TextButton.Image` are project-relative asset paths and are drawn.
- **Fonts**: `font-family` names a family. Built in (`render/src/fonts.rs`, all SIL OFL): Montserrat (the default and `sans-serif`), Inter, Roboto, Poppins, Nunito, Oswald, Bebas Neue, Bangers, Lobster, Press Start 2P, Lora (`serif`) and JetBrains Mono (`monospace`). A project's own `.ttf` and `.otf` files, anywhere in its folder, work by their family name too: `Assets::fonts` reads them, the draw list carries them, and the renderer loads each the first time it's seen. Built games include them. Quote names with spaces (`font-family: "Bebas Neue"`).
- **Weights and italics**: the draw list carries each text's weight and style, and `render` picks the family's face (`pick_face`): its italic faces when it has any, then the nearest weight. Montserrat, Inter, Poppins and JetBrains Mono have real Bold, Italic and Bold Italic files; Roboto, Nunito and Lora have a real italic (their variable files draw at the regular weight). A project's own files join a family by the name inside them, so `MyFont-Bold.ttf` is MyFont's bold wherever it is, and built games include every `.ttf` and `.otf`. A weight of 600 or more that the family has nothing bold for is drawn faux bold (each copy of the letters three times, a little apart), and italic with no italic face is slanted.

## Editing UI in the editor

- The toolbar's UI group inserts a ScreenGui, Frame, TextLabel (Text), TextButton (Button), ImageLabel (Image), TextBox, PageLayout (Pages), a page Frame (Page), Table or BillboardGui. A screen element goes into the selected ScreenGui, Frame, PageLayout or Table, else the ScreenGui around the selection or the Workspace's first; with no ScreenGui at all, one is inserted first. Page inserts a Frame named Page into the selected PageLayout, creating a PageLayout (and a ScreenGui) when there isn't one. BillboardGui goes into the selected part.
- Like Roblox Studio, the selected element gets handles in the viewport: drag its body to move it and a square to resize it (see `ui_handles.rs`). The drag snaps when an edge or center comes within 8 points of an edge or center of another element, or of the screen, and a magenta guide line shows the alignment. A flex child is not snapped, because the layout places it. Where CSS sets `width` or `height`, resizing rewrites that CSS value (in its own units) instead of `Size`.
- While those handles are showing, a label under the element gives its size in screen pixels and how far it sits from the left, right, top and bottom of the screen. A child of a Frame, Table or other element also shows those distances to its parent, in magenta, and still uses the same handles. BillboardGui children keep those handles in the world view.
- A ScreenGui's `ScaleMode` is `Fixed` (the class default: positions and sizes are as authored, in screen pixels), `Fit` or `Scale`. Both Fit and Scale scale it evenly by how the screen compares to `DesignWidth` by `DesignHeight` (default 1920×1080), by as much as fits. Fit lays it out on the design rectangle and centres that, leaving empty bars on another aspect ratio. Scale lays it out over the whole screen, measured in design pixels, so what's pinned to an edge stays against it (like Unity's Scale With Screen Size). ScreenGuis inserted in the editor start in Scale; ones made by scripts or saved before keep their mode. Dragging a handle still edits the design-pixel `Position`, `Size` or CSS length. Set the design size to the resolution you laid the UI out at.
- **Anchors** are written in `Position` and `Size`: a `UDim2`'s scale is where in the parent it's measured from and its offset the distance. Pinned to the right means `Position.X` scale 1 with a negative offset; centred, scale 0.5; stretched, `Position` scale 0 and `Size` scale 1 with the margins in the offsets. Nothing else is saved, so Play and the player need nothing new.
- **Add a style** autocompletes property names and, for the supported ones, their values (flex, colors, lengths and so on). Tab takes the first match; clicking a suggestion fills it in. The same suggestions appear on a value that is already set, while that box is focused.
- Unlike Studio, the Properties panel also has a **Style (CSS)** section, like a browser's style inspector: the declarations that apply to the element, grouped by rule with a link to the rule's line, each value editable in place (colours with a swatch). Edits rewrite the stylesheet's text in its tab (unsaved until Ctrl+S) and restyle the viewport at once. **Add a style** puts `property: value` into the element's own `#Id` rule: an element without an `Id` gets one from its name, the rule is made at the end of the first stylesheet if it doesn't exist, and a project with no stylesheet gets `ui.css`.
- Style edits and handle drags are undo steps like any other: the stylesheet's text before and after goes in the step (one step per drag or per value typed), and undoing the style that made `ui.css` deletes it again.
- **UI Designer** (a dock tab beside the Scene View; `ui_designer.rs` and `ui_designer/`): the selected ScreenGui (or the one around the selected element, else the Workspace's first) on an artboard. The toolbar picks the ScreenGui, its scale mode (Fixed, Fit, Scale), its design size (typed, or ▾ for common screens), the screen to **Preview** on (the design size, a preset from 4:3 and 16:9 desktops to ultrawide, tablet and phones, or a custom size; this isn't saved), and the zoom; Fit fits the artboard into view. Right- or middle-drag and the wheel pan, Ctrl + wheel zooms. The artboard is `axcenity_ui::layout_artboard`: the same layout a screen of that size gets in Play (shown even when `Enabled` is off), drawn by the game's renderer over a grey backdrop. A note offers **Use Scale** when a ScreenGui is Fixed or Fit, and says when it's disabled.
- **Rulers** along the top and left are in design pixels, with the selected element's extent marked. Drag down from the top ruler or right from the left one for a **guide**; elements snap to guides as they do to other elements' edges. Drag a guide to move it, or back onto a ruler to remove it. Guides are kept per ScreenGui while the editor runs and aren't saved. The selected element shows the viewport's size and distances to the screen and its parent, in design pixels, and diamonds where it's anchored.
- The inspector's **Anchor** grid (4×4, like Unity's presets: left, centre, right or stretched across; top, middle, bottom or stretched down) pins the selected element without moving it at the design size (`ui_designer/anchors.rs`). A flex child has no anchor. An anchor is the `UDim2` scales of `Position` and `Size`: on each axis the element's start is pinned at `Position`'s scale and its end at that plus `Size`'s scale, so apart means stretched. **Font** picks the text's `font-family` (into the element's own `#Id` rule) from the built-in fonts and the project's own; **Look again** rereads the project's font files after one is added.
- **Text toolbar** (`ui_designer/text_toolbar.rs`), under Font for an element with text: **B**, **I**, **U** and **S** toggles, an **Aa** case menu (`text-transform`), alignment across and up and down, Size, colour, **Outline** (width and colour), **Shadow** (x, y, blur and colour; edits the first shadow), letter spacing, line height (times the size), **Wrap** and **Text Scaled**. Each control writes one property into the element's own `#Id` rule (changed in place if it's there, else added), except Text Scaled, which is the property. It shows what the element's styles make of it, from whichever rule (`axcenity_ui::text_style`). Each click is one undo step, and a dragged value is one step. Ctrl+B, Ctrl+I and Ctrl+U toggle bold, italic and underline on the selected element while nothing is being typed in.
- **Anchor diamonds** (`ui_designer/anchor_handles.rs`): the selected element has one at each corner of its anchor, pointing at it, so a joined anchor shows four round one point. Press the point itself to drag them all; press one diamond to drag its own ends, which splits the anchor and stretches the element on that axis (dragging an end past its pair pushes the pair along). A dragged anchor snaps to the parent's edges, middle and its pair (rejoining it), with the magenta line; Alt drags freely, in whole percent. A label shows the anchor in percent of the parent. The offsets are rewritten so the element doesn't move at the design size. **Reset** under the grid, or **Reset anchor** on a diamond's right-click menu, anchors it back at the top left, unstretched, without moving it. One drag or one reset is one undo step.
- **Double-click** text on the artboard (or its row in the hierarchy) to type over it, at the size it's drawn (CSS `font-size`, else `TextSize`); Enter or clicking away finishes, Escape puts it back. Clicks and drags in the box place the caret and select text; they don't select or move what's under it. The typing is one undo step. A click that doesn't move doesn't snap or move anything. With `RichText` on, the box shows the source in its tags' styles (bold, italic, underline, strikethrough, colour and size, with the tags small and faint; a one-line box scrolls rather than wraps), and a bar over it has **B**, **I**, **U**, **S** and eight colours (`ui_designer/rich_text.rs`). Ctrl+B, Ctrl+I, Ctrl+U or the bar wraps the selection in `<b>`, `<i>`, `<u>`, `<s>` or `<font color>`; the same again on a selection wrapped in just that tag takes it off (another colour changes the colour). Tags inside the selection stay where they are and the text between them is wrapped piece by piece, so tags stay nested. Wrapping is part of the typing's one undo step, and typing carries on after the bar is used. With nothing selected, or `RichText` off, Ctrl+B, Ctrl+I and Ctrl+U change the element's own style, as outside the box. The inspector's Text field shows the tagged source.
- Around the artboard: **Elements** (Frame, Text, Button, Image, TextBox, Pages, Page, Table) to drag onto it, where they go into the Frame, PageLayout or Table under the pointer (else the ScreenGui) with their top left at the drop point; a click adds one to the selected container instead. The **Hierarchy** lists the ScreenGui's elements; a click selects. The inspector edits the selected element's Name and Text, then shows the same **Style (CSS)** section as Properties. On the artboard a click selects an element and a drag moves it; the selected element has the viewport's handles and snapping (`ui_handles.rs`). Every designer edit goes through `EditorApp::change`, the tree edits or the stylesheet tabs, so it undoes, shows in the Scene View, and plays the same. Below 640 points wide the artboard goes on top with the panels under it.
- Stylesheets edited in another program (VS Code) restyle the viewport when saved there, unless the editor has unsaved changes to them, which are kept.
