# Data tables

Rows of typed values a game's scripts read, such as each weapon's damage and icon (unified Phase 33). They're the engine's answer to ScriptableObjects and Resources. The example is `examples/hello-data`.

- **The file** (`assets::DataTable`, `crates/assets/src/data_table.rs`): `assets/data/<name>.data.json`. The table's name is its path in `assets/data` without the suffix (`weapons`, or `enemies/bosses`). The file holds `columns` (each `{ "name", "type", … }`) and `rows` (each `{ "key", "cells": { column: value } }`), and every key is unique. Column types: `number`, `integer`, `string`, `boolean`, `vector3` and `color3` (`[x, y, z]`, `[r, g, b]` from 0 to 1), `enum` with `options`, `asset` with an `asset` kind (`model`, `texture`, `audio`, `material`, `prefab`, `clip`; the cell is a project path), and `reference` with a `table` (the cell is a row key of that table, `""` for none). A cell the file leaves out has its column's default (0, `""`, false, white, the first option). Writing (`to_json`) writes every cell, in name order, so the same table is always the same text. Reading refuses two rows with one key, a row with none, two columns with one name, a value of the wrong type, and an enum value that isn't one of its options, saying which row and column.
- **Loading** (`Assets::data_table(name)`): read once, then kept; a missing or bad table is an error with the reason, and scripts show it. `Assets::put_data_table` puts an edited table in place without the file; `Assets::reload` reads a changed file again and keeps the last good table if the new one is bad (live reload, the editor and `--watch`).
- **The Data Table tab** (`editor/src/data_table.rs`, app side `app/data_tables.rs`; starts closed): a table picker, a name box with **New table**, a search box, a column filter (*column* has *text*), then the grid. Clicking a header sorts by it (up, down, then the file's order); sorting, search and filter only change the view. A column's **⋯** menu renames, moves left or right, or removes it; **+ Column** adds one (name, type, and the type's options, asset kind or table). Cells use the control for their type: number boxes, a checkbox, X/Y/Z boxes, a colour button, an enum's options, a picker of the project's files of an asset column's kind (from the Assets panel's scan), and the keys of a reference column's table; a missing asset or row shows a warning. A row's key is edited in place (renamed when the box loses focus); each row ends with duplicate (a new key: `sword` → `sword2`) and remove; **Add row** adds one at the end. Each edit (`TableEdit`) is one step of the table's own undo, used while the pointer is over the grid; dragging a number or typing in a cell is one step however long it takes. Tables are written with the project's Save (and count as unsaved changes). Each edit is also given to the shared `Assets` (`EditorApp::hand_over_tables`), so tables can be edited during Play and the game reads the change at its next call. A table rewritten on disk (another program, an Asset Check fix or its undo) is read again in its tab unless the tab has unsaved changes. Double-clicking a table in the Assets panel opens it.
- **AI clients** (MCP, full profile): `data_edit` lists, shows, creates and changes tables through the same file reader, saved at once and one undo step each; a table with unsaved changes in the tab is left alone ([../editor/mcp.md](../editor/mcp.md)).
- **Lua** (`script/src/data.rs`): `DataService:GetTable("weapons")` (also `game.DataService`) errors when the table can't be read and otherwise returns a handle on the table by name, so each call reads the version in use now. `t:Get(key)` is a row or nil, `t:GetAll()` a new table of every row by key, `t:Keys()` a new list of keys in the table's order. A row is read by column name (`row.Damage`); an integer is a number, an enum its option's name, an asset its path, a Vector3 and Color3 their types, and a reference the row it names (nil for none or a missing row). `for column, value in row do` goes through its columns in order. A wrong column name errors and lists the columns. Writing to a row or a table errors: "… can't be changed: data tables are read-only in scripts. Change them in the Data Table tab."
- **Abilities and Effects** (Phase 76): `DataService:CreateAbility(table, key)` and `CreateEffect(table, key)` make one from a row: columns named after properties set them, the rest become attributes ([../scripting/api-abilities.md](../scripting/api-abilities.md)).
- **Quests** (Phase 77): `QuestService` reads the tables `quests` and `quest_objectives` ([../scripting/api-dialogue.md](../scripting/api-dialogue.md)); a dialogue's **Data Table?** node tests a cell.
- **Blocks** (More): *row* (key) *of table* (name) is `DataService:GetTable("t"):Get(key)`; *value of column* (name) *in row* (row) is `row.Column` (or `row["Fire Rate"]`). `local DataService = game:GetService("DataService")` goes at the top. Their menus suggest the project's tables and columns.
- **Asset Check**: a table that can't be read is an import failure (Delete file). An asset cell naming a missing file, or a file of the wrong kind, and a reference cell naming a row its table hasn't got (or a table that isn't there) are broken dependencies at `Site::TableCell { file, row, column }`. Asset cells offer Use, Locate…, Replace… and Clear; reference cells offer Clear. Fixes rewrite the table file, as one undo step. The scan reads saved tables.
- **Packages**: a table brings the tables its reference columns name and the files in its asset cells. Export Package… on an Explorer object also reads the object's scripts (`package_contents_with_scripts`, `script_tables`): a `GetTable("name")` with the name written out brings that table; any other call is listed in the Console with its script and line, to check by hand.
- **Built games** include every table (everything under `assets/` is packed).
- **Tests**: `assets` (`data_table.rs`, `reload.rs`), `script/src/data_tests.rs`, `editor/src/app/data_table_tests.rs` (made in the grid and read in Play, changed during Play, Asset Check and its fixes, the view), `project` (`package/tests.rs`, `packed.rs`), and `blocks` (`data_blocks_read_a_tables_row_and_column_and_come_back_from_lua`).
