# Project folder

What a project folder contains, and how a damaged file is handled.

- Readable text files only (except user assets): a manifest, world and Instance data, `.lua` scripts (`*.server.lua` / `*.client.lua` / `*.module.lua`), block script files, `.css` stylesheets, the optional string table `strings.json` (UI text in each language; see `docs/ui.md`), the optional input map `input.json` (actions and their bindings; see `docs/scripting/client-server.md`; built games include it), and assets (glTF and FBX models, textures, sounds).
- One damaged file must not prevent loading the rest of the project. Report it and continue. Since Phase 13, `project::load` only fails for a missing or unreadable manifest (not a project folder), a newer `format_version`, or an upgrade that cannot finish. Anything else goes in `Project::problems` and is left out: a broken manifest gives the project its folder's name, a broken `world.json` an empty Workspace (`world_loaded = false`), and an unreadable script (not UTF-8, say) no Script. The player prints problems as `error:` lines and runs the rest.
- An older manifest is upgraded in place on open (`project::load`). The previous files are copied first to `.axcenity/previous/<version>/` (`project::PREVIOUS_FORMAT_DIR`), beside the upgraded project, and a later save does not write that folder. The manifest's `format_version` is then the current one. Format 1 and 2 describe the same world, so that first step only rewrites the manifest: `world.json`, scripts, and assets load as they did. The 2 → 3 step (v3 Phase 7, `project/src/migrate_animation.rs`) rewrites every clip in the one clip shape and every `*.controller.json` as a `*.statemachine.json`, moves those directly in `assets/animations` into a folder of their own (`Door.anim.json` → `Door/Door.anim.json`, `noodle.controller.json` → `noodle/noodle.statemachine.json`; a taken name gets a number), rewrites every path to a moved file (in state machines, and in `world.json` and prefabs, where an Animator's `Controller` becomes `StateMachine`), and gives each Animation whose parent has no Animator one beside it. `world.json` and prefabs are only written again if that changed them. Lua scripts are left as they are. A manifest newer than this engine still refuses to open, tells the creator to update Axcenity, and leaves the folder unchanged. Creating a project, opening a current one, and changing project settings do not copy or rewrite anything. `.axcenity`, `.git`, `target`, and `node_modules` are left out of the copy.
- The editor watches the folder and reloads files changed externally (see `docs/editor/scripts.md`). Before saving over a world file it never loaded, it renames that file to `world.backup.json` (`project::keep_world_file`).
