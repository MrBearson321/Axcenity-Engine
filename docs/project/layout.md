# Project folder

What a project folder contains, and how a damaged file is handled.

- Readable text files only (except user assets): a manifest, world and Instance data, `.lua` scripts (`*.server.lua` / `*.client.lua` / `*.module.lua`), block script files, `.css` stylesheets, the optional string table `strings.json` (UI text in each language; see `docs/ui.md`), the optional input map `input.json` (actions and their bindings; see `docs/scripting/client-server.md`; built games include it), the optional `collision-groups.json` (Phase 38: `{"groups": [...], "notCollidable": [[a, b], ...]}`, Default left out; written by the Collision Groups window, read into the world on open, kept in version history and built games; a damaged one is a load problem and every part collides; `docs/architecture/physics.md`), and assets (glTF and FBX models, textures, sounds).
- One damaged file must not prevent loading the rest of the project. Report it and continue. Since Phase 13, `project::load` only fails for a missing or unreadable manifest (not a project folder), a newer `format_version`, or an upgrade that cannot finish (or whose world no longer reads, which puts the old files back). Anything else goes in `Project::problems` and is left out: a broken manifest gives the project its folder's name, a broken `world.json` an empty Workspace (`world_loaded = false`), and an unreadable script (not UTF-8, say) no Script. The player prints problems as `error:` lines and runs the rest.
- An older manifest is upgraded in place on open (`project::load`). The previous files are copied first to `.axcenity/previous/<version>/` (`project::PREVIOUS_FORMAT_DIR`), beside the upgraded project, and a later save does not write that folder. The manifest's `format_version` is then the current one. Format 1 and 2 describe the same world, so that first step only rewrites the manifest: `world.json`, scripts, and assets load as they did. The 2 → 3 step (v3 Phase 7, `project/src/migrate_animation.rs`) rewrites every clip in the one clip shape and every `*.controller.json` as a `*.statemachine.json`, moves those directly in `assets/animations` into a folder of their own (`Door.anim.json` → `Door/Door.anim.json`, `noodle.controller.json` → `noodle/noodle.statemachine.json`; a taken name gets a number), rewrites every path to a moved file (in state machines, and in `world.json` and prefabs, where an Animator's `Controller` becomes `StateMachine`), and gives each Animation whose parent has no Animator one beside it. `world.json` and prefabs are only written again if that changed them. Lua scripts are left as they are. The 3 → 4 step (Phase 34, `project/src/migrate_physics.rs`) gives every Metal Part in `world.json` and the prefabs that has no `CustomPhysicalProperties` the values all parts had before (`PhysicalProperties::LEGACY`), since Metal is dense now, so the world simulates as it did; Plastic, Glass and Neon kept those values and need nothing. The 4 → 5 step (release system Phase 7) adds `"engine": {"saved_with": "<version>"}` to the manifest; who created the project isn't known, so `created_with` is left out. A new project records both (`templates.rs`), and each save in the editor sets `saved_with` (`project::record_engine`, which writes only when it changes). It's only for messages: the format number decides what opens, and a format 5 manifest without `engine` loads too. If the world read before an upgrade but doesn't afterwards, the upgrade is undone (`migrate::put_back`): the upgraded files move to `.axcenity/failed-upgrade/` and the copy from before is put back, so an older engine still opens it, and loading fails with that reason. An upgrade whose copy for that format was already there (an older one, kept as it was) is never put back. A manifest newer than this engine still refuses to open, tells the creator to update Axcenity, and leaves the folder unchanged; that includes one this engine can't parse whose `format_version` is newer, which used to open as a damaged current manifest. The editor asks first (`project::compatibility`, `app/project_upgrade.rs`): an older project shows "Upgrade this project?" with one line per step (`project::upgrade_steps`) and where the files from before go, and nothing is written until Upgrade; after an upgrade it runs the Asset Check once and warns if it finds problems. A project older than the oldest step, or newer than this engine, is refused with what to do (the newer one names the first release that opens its format, from the built-in release history). Command-line tools (the player, `--build-game`) upgrade without asking, as before. Creating a project, opening a current one, and changing project settings do not copy or rewrite anything. `.axcenity`, `.git`, `target`, and `node_modules` are left out of the copy.
- The editor watches the folder and reloads files changed externally (see `docs/editor/scripts.md`). Before saving over a world file it never loaded, it renames that file to `world.backup.json` (`project::keep_world_file`).
