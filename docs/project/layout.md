# Project folder

What a project folder contains, and how a damaged file is handled.

- Readable text files only (except user assets): a manifest, world and Instance data, `.lua` scripts (`*.server.lua` / `*.client.lua` / `*.module.lua`), block script files, `.css` stylesheets, and assets (glTF and FBX models, textures, sounds).
- One damaged file must not prevent loading the rest of the project. Report it and continue. Since Phase 13, `project::load` only fails for a missing or unreadable manifest (not a project folder), a newer `format_version`, or an upgrade that cannot finish. Anything else goes in `Project::problems` and is left out: a broken manifest gives the project its folder's name, a broken `world.json` an empty Workspace (`world_loaded = false`), and an unreadable script (not UTF-8, say) no Script. The player prints problems as `error:` lines and runs the rest.
- An older manifest is upgraded in place on open (`project::load`). The previous files are copied first to `.axcenity/previous/<version>/` (`project::PREVIOUS_FORMAT_DIR`), beside the upgraded project, and a later save does not write that folder. The manifest's `format_version` is then the current one. Format 1 and 2 describe the same world, so that first step only rewrites the manifest: `world.json`, scripts, and assets load as they did. A manifest newer than this engine still refuses to open, tells the creator to update Axcenity, and leaves the folder unchanged. Creating a project, opening a current one, and changing project settings do not copy or rewrite anything. `.axcenity`, `.git`, `target`, and `node_modules` are left out of the copy.
- The editor watches the folder and reloads files changed externally (see `docs/editor/scripts.md`). Before saving over a world file it never loaded, it renames that file to `world.backup.json` (`project::keep_world_file`).
