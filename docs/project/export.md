# Export

How a project becomes a shipped game, including version history and the splash.

- File > Build Game (Export Game before unified Phase 5; same targets, same files) translates block scripts to Lua (UI Event Graphs in `ui/` go as they are; the player's loader compiles them) and writes `game.axgame`, a small versioned archive containing the manifest, world, levels (`levels/`, Phase 48), string table, scripts, CSS and assets. Editor-only files are excluded, as are asset ID sidecars (`*.import.json`). Textures go with their current cooked copies from `.axcenity/imported/textures/` (BC7 with mips, cooked first if missing; [../rendering/textures.md](../rendering/textures.md)), and models with their current cached simpler copies from `.axcenity/imported/meshes/` and cooked whole models from `.axcenity/imported/models/` ([../rendering/models.md](../rendering/models.md)), the only parts of `.axcenity` that ship. The player (and `axcenity-server`) unpacks it to a private temporary folder and runs it; the archive refuses traversal and duplicate paths. **Format** (`project/src/packed.rs`): `AXCGAME\0`, version 2, the entry count, then per entry the path's length, flags, the file's modified time (nanoseconds since 1970, 0 for none), the stored and the unpacked length, the path and the data. An entry is zstd-compressed (level 3, with zstd's checksum) when that saves at least 5%: text, `world.json` (S10k's 10 MB becomes 0.2 MB), meshes and most cooked textures, but not PNG, JPEG or audio, which are compressed already. Unpacking reads and checks the whole index first, then writes the files on up to 8 threads, streaming each compressed entry into its file with no more than its stated length; it restores each file's modified time, so cooked copies are trusted without hashing their sources. Version 1 files (before M9: nothing compressed, no times) still unpack. Numbers: [../benchmarks.md](../benchmarks.md#game-files-m9).
- The editor pairs the archive with a player executable. The current-OS player is looked up beside the editor. Cross-target players are looked up under `players/windows`, `players/macos` or `players/linux` beside it; GitHub release packages ship all three. Without the requested player, export reports an error rather than silently falling back to another OS.
- Every export writes `LICENSES.txt` with the engine's `NOTICE`. macOS exports are unsigned `.app` bundles in v1.
- **Version history** (`project/src/versions.rs`; unified Phase 72 made it easier to use instead of adding a second, Git-based history): each successful save copies `world.json`, `strings.json`, `collision-groups.json`, the levels in `levels/` (Phase 48), `scripts/` and every `.css` file into `.axcenity/history/<id>/` (`project::record_version`), with `assets.txt`, a list of every file under `assets/` by size and modified time (not their bytes). `meta.txt` holds the label, then `pinned` for a pinned version. A second save with the same files and assets is skipped. Ids are `<secs>-<nn>` and always sort after the newest, even with many saves in one second. The newest 40 unpinned versions are kept; pinned ones are kept until unpinned (`project::set_pinned`).
  - **Checkpoints**: File > Save Checkpoint… (or the window's message box and Save Checkpoint) saves, then pins that version with the message ("Checkpoint" when empty; `project::record_checkpoint`). When the newest version already has the files, it's relabeled and pinned instead.
  - **Timeline and change view**: File > Version History lists versions newest first with their message (or "Save"), date and a pin button. Selecting one shows what changed since the version before it (`project::version_changes`; everything is "added" in the oldest): world and level files Instance by Instance in words ("Moved Part "Block" in Workspace", "Added PointLight "Lamp" to Workspace", "Changed Lighting: ClockTime"), other files with a line diff (two lines of context), and assets added, removed or changed. `world.json` keeps no Instance IDs, so an Instance is matched by its parent path, class, name and place among same-named siblings: a rename or reparent shows as removed and added. A property written on one side only (older or hand-written files leave defaults out) counts as changed only when it isn't the class default. Changing only `Position`/`Orientation`/`CFrame` is a move; only `Size`, a resize.
  - **Restore**: Restore project to here (`project::restore_version`: the files are copied back, and scripts or styles the version doesn't have are removed) or a file's Restore this file (`project::restore_file`; a file the version doesn't have is removed). Both ask first, and refuse while anything is unsaved. Both keep the current files first as a pinned version labeled "Before restore" (when the newest version already has them, that one is pinned, and a plain "Save" is relabeled), so a restore can always be undone. Assets, `axcenity.json` and `thumbnail.png` are left as they are. Version History on a project card on the start screen lists the same versions (pins shown) and restores the whole project after asking.
  - **Backup**: File > Back Up Project (also in the window) writes `<project folder>-<YYYY-MM-DD-HHMMSS>.zip` to the backup folder (`project::back_up_project`, with the pinned `zip`): every file under a folder named like the project's, without `.axcenity/` (or the backup folder, when it's inside the project). Unzipped anywhere, it opens as the project. The folder is asked for the first time (Choose Folder… changes it) and kept, with "Back up on every checkpoint", in `.axcenity/backup.json` (`project::BackupSettings`): it's this computer's, so it isn't in the manifest.
  - `.axcenity` is not exported or backed up; Build Game takes only its cooked textures, cached simpler copies and cooked models.
- The player splash is on by default: a black screen with the white wordmark (no plate), a white loading bar, and the caption "Made with Axcenity". Its clock starts on the first drawn frame and counts at most 50 ms per frame, so loading can't use it up unseen. `show_splash` in `axcenity.json` turns it off (missing values default to true). Click or a key skips to the fade-out. The bar is timed (about 3.3s including fade). The player reads the Workspace's models and textures ahead while it starts (roadmap I11, `player/src/preload.rs`): every file `scene::asset_files` lists is requested from the asset workers (`AssetFile::request`; they decode several at once, and `Assets::load_textures_in_background` stays on for the whole game), and the splash holds on its full bar (no skip) until they're all in, its caption then reading "Loading 12 of 40", so textures don't pop in. A file first needed later (a level a script loads, a model cloned from storage) still loads when first drawn: textures in the background, models in that frame. It's drawn over all the game's UI: the renderer keeps the UI list's order (see [rendering/pipeline.md](../rendering/pipeline.md)).
- **Loading screen** (File > Build Game > Loading screen; `loading_screen` in `axcenity.json`, `project::LoadingScreen`): **Axcenity splash** (`show_splash` on, no `screen_gui`), **None** (`show_splash` off), or one of the Workspace's ScreenGuis by `Name` (`screen_gui`), designed like any other UI. A chosen ScreenGui replaces the splash: `axcenity_ui::LoadingGui` turns its `Enabled` on before any script runs, lays it out over all other UI (BillboardGuis too, through `UiInput::on_top`), and turns `Enabled` off once it has been up for `min_seconds` (default 3) and, with `wait_for_script`, a LocalScript has called `ReplicatedFirst:RemoveDefaultLoadingScreen()` (whichever is later), and the player has the Workspace's assets in (`LoadingGui::set_assets_loading`). With **None**, the player draws a plain dark screen with a bar and "Loading 12 of 40" until those assets are in. Scripts can animate it meanwhile; keys and clicks still reach the game. With `wait_for_script` and the splash, the splash holds on its full bar (rings still moving, no skip) until that call. A name that matches no ScreenGui falls back to the splash setting with a warning. Play in the editor shows a chosen ScreenGui the same way (not the splash). The start screen's Project Settings notes when a ScreenGui replaces the splash. `examples/hello-loading` is a worked example.
- The manifest also takes an optional `description` (default empty). The editor's start screen edits `name`, `description` and `show_splash` from a project's Settings, and New Project uses `project::create_project_from` with the chosen `Template`: Baseplate (a grey baseplate), Empty, Starter scene (a lit scene with a spinning neon part, a touch pad, and the block script `scripts/Starter.server.blocks.json` that drives them), or one of the genre templates, First Person, Third Person, Vehicle, Top Down and Multiplayer Arena ([templates.md](templates.md)). The start page shows the genre templates as pictures under "Or from a game", and the dialog shows each template's picture (or icon), name and a line of description. `thumbnail.png` (320×180) in the project folder is the editor's project-list picture, written on Save and Close Project from a viewport screenshot; it isn't exported.
- **Developer Console** (File ▸ Build Game ▸ Developer Console (F9); `developer_console` in `axcenity.json`, default off): built games open the F9 console only with it on, or with `--dev`. Built games write `logs/latest.log` in the player's data folder and keep five ([../developer-console.md](../developer-console.md)).
