# Export

How a project becomes a shipped game, including version history and the splash.

- File > Build Game (Export Game before unified Phase 5; same targets, same files) translates block scripts to Lua (UI Event Graphs in `ui/` go as they are; the player's loader compiles them) and writes `game.axgame`, a small versioned archive containing the manifest, world, levels (`levels/`, Phase 48), string table, scripts, CSS and assets. Editor-only files are excluded. The player unpacks it to a private temporary folder and runs it; the archive refuses traversal and duplicate paths.
- The editor pairs the archive with a player executable. The current-OS player is looked up beside the editor. Cross-target players are looked up under `players/windows`, `players/macos` or `players/linux` beside it; GitHub release packages ship all three. Without the requested player, export reports an error rather than silently falling back to another OS.
- Every export writes `LICENSES.txt` with the engine's `NOTICE`. macOS exports are unsigned `.app` bundles in v1.
- **Version history**: each successful save copies `world.json`, `strings.json`, `collision-groups.json`, the levels in `levels/` (Phase 48), `scripts/` and every `.css` file into `.axcenity/history/<id>/` (`project::record_version`). A second save with the same files is skipped. The newest 40 are kept. File > Version History in the editor, and Version History on a project card on the start screen, list them and can restore one (`project::restore_version`): those files are copied back, and scripts or styles the version doesn't have are removed. Assets, `axcenity.json` and `thumbnail.png` are left as they are. The current files are recorded first (labeled "Before restore" when they weren't already the newest version). `.axcenity` is not exported.
- The player splash is on by default: a black screen with the white wordmark (no plate), a white loading bar, and the caption "Made with Axcenity". Its clock starts on the first drawn frame and counts at most 50 ms per frame, so loading can't use it up unseen. `show_splash` in `axcenity.json` turns it off (missing values default to true). Click or a key skips to the fade-out. The bar is timed (about 3.3s including fade), not a measure of remaining load. It's drawn over all the game's UI: the renderer keeps the UI list's order (see [rendering/pipeline.md](../rendering/pipeline.md)).
- **Loading screen** (File > Build Game > Loading screen; `loading_screen` in `axcenity.json`, `project::LoadingScreen`): **Axcenity splash** (`show_splash` on, no `screen_gui`), **None** (`show_splash` off), or one of the Workspace's ScreenGuis by `Name` (`screen_gui`), designed like any other UI. A chosen ScreenGui replaces the splash: `axcenity_ui::LoadingGui` turns its `Enabled` on before any script runs, lays it out over all other UI (BillboardGuis too, through `UiInput::on_top`), and turns `Enabled` off once it has been up for `min_seconds` (default 3) and, with `wait_for_script`, a LocalScript has called `ReplicatedFirst:RemoveDefaultLoadingScreen()` (whichever is later). Scripts can animate it meanwhile; keys and clicks still reach the game. With `wait_for_script` and the splash, the splash holds on its full bar (rings still moving, no skip) until that call. A name that matches no ScreenGui falls back to the splash setting with a warning. Play in the editor shows a chosen ScreenGui the same way (not the splash). The start screen's Project Settings notes when a ScreenGui replaces the splash. `examples/hello-loading` is a worked example.
- The manifest also takes an optional `description` (default empty). The editor's start screen edits `name`, `description` and `show_splash` from a project's Settings, and New Project uses `project::create_project_from` with the chosen `Template`: Baseplate (a grey baseplate), Empty, or Starter scene (a lit scene with a spinning neon part, a touch pad, and the block script `scripts/Starter.server.blocks.json` that drives them). `thumbnail.png` (320×180) in the project folder is the editor's project-list picture, written on Save and Close Project from a viewport screenshot; it isn't exported.
