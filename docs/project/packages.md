# Asset packages

An asset package (`.axpkg`, unified Phase 6) moves assets from one project to another. `project::package` reads and writes them and plans an import; the editor's side is `editor/src/app/files/packages.rs` and the Import dialog's Package tab (`editor/src/import_dialog/package.rs`).

- **The file**: a zip (the workspace's pinned `zip`, no new dependency) holding `axpkg.json` and the files at their project paths. The manifest is `{ "format": 1, "name", "roots", "files" }`: `roots` are what was exported, `files` every path in it. Reading checks every listed file is there and is under `assets/` with no `..`, `:`, or leading slash; anything else is refused ("`world.json` isn't an asset path inside a project"). A newer `format` is refused. Packages are optional files: they don't bump `project::FORMAT_VERSION`.
- **What goes in** (`package_contents(folder, roots, extra)`): each root, then everything it needs, followed again for what those need:
  - a state machine (`*.statemachine.json`) brings every clip its states play (blend trees too);
  - a clip (`*.anim.json`) linked to a take brings its model (the file of `link.source`, without a `#` pick);
  - a model in a folder of its own (`assets/models/<name>/…`) brings every file in that folder: buffers, textures and SurfaceAppearance maps imported with it;
  - a prefab (`*.prefab.json`) brings every asset its Instances name, by the same properties Asset Check reads (`validate::refs`: `MeshId`, `SoundId`, `Image`, `Texture`, `StateMachine`, `Clip`, SurfaceAppearance and TerrainLayer maps, a Terrain's `DataFolder`), and (Phase 49) the prefabs its copies are of: a variant's base and nested prefabs, and theirs in turn.
  - a data table (`*.data.json`) brings the tables its reference columns name and the files in its asset cells; Export Package… on an Explorer object also brings the tables its scripts name in `DataService:GetTable("…")` and lists other calls for a check ([data-tables.md](data-tables.md)).
  `extra` files go in as roots without being in the project: Export Package… on an Explorer object puts the object in as `assets/prefabs/<Name>.prefab.json` (`project::write_prefab`); the project gains no prefab file. A root that isn't there is an error; a needed file that isn't there is left out and listed (`Contents::missing`), and the editor says so in the Console.
- **Importing** (`plan_import(folder, package, clashes)`, which writes nothing): a package file the project has byte for byte is left alone and isn't a clash, so importing the same package twice adds nothing. A file whose path holds something else is a clash, settled one way for all of them (`Clashes`):
  - **Keep both** (the default): each *group* with a clash, a folder `assets/<kind>/<name>` or a file right in an asset folder, moves to the first free numbered name (`noodle` → `noodle2`, `wood.png` → `wood2.png`, numbered before the first dot). Every `.json` file in the package is rewritten to name the new paths (only whole JSON strings that start with the old path, followed by `/`, `"` or `#`). A rewritten file that now clashes moves too, until nothing new clashes. The rest of the group comes along to the new place even if identical, so it stays whole; a model shared with the project's copy (identical) isn't copied.
  - **Replace**: the package's files are written over the project's.
  - **Skip existing**: only files whose paths are free are written.
- **Tests** (`project/src/package/tests.rs`): what a state machine and a prefab bring; a round trip and refused paths; `an_imported_state_machine_plays_the_same_as_in_the_project_it_came_from` (noodle's state machine from hello-animation, imported into an empty project, poses the same world the same for 30 frames); importing twice adds nothing; each choice after a clip changed, with Asset Check clean after each; Keep both numbering a file and rewriting what names it.
