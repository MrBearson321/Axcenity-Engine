# Animation files

The JSON for clips and state machines.

- **Animation files** (Phase 38, `anim::files`; one clip format since v3 Phase 7): pretty JSON, written with every field in a fixed order (`to_json`, through a `.saving` temporary file), so saving the same thing gives the same text; unknown fields are errors that name the line. Paths in them are from the project folder.
- **Folders**: each animated thing has its own folder, `assets/animations/<name>/`, holding its clips and its state machine (`assets/animations/noodle/Walk.anim.json`, `assets/animations/noodle/noodle.statemachine.json`). Clips any model can play go in `assets/animations/Shared/`. Importing an animated FBX writes its clips and state machine into the model's folder; New ▸ State machine and New ▸ Property clip write into a folder named after them.
- A **clip** (`*.anim.json`, format 2): `{ "format_version": 2, "duration": 1.5, "loop": false, "link": { "source": "assets/models/noodle.fbx", "take": "Wave", "start": 0.0, "end": 1.0, "root_motion": true }, "tracks": [ … ], "events": [ { "time": 1.4, "name": "Opened" } ] }`.
  - `duration` is seconds one pass lasts; keys and events lie in `0..=duration`, and an event's `time` is seconds from the clip's start. `loop` may be left out (true).
  - `link` (optional, left out when there's none) links the clip to part of a take in a model file: its bones move as the take does from `start` to `end` (seconds of the take) over the clip's `duration`, so a shorter duration plays the take faster and `end` before `start` plays it backwards (`ClipFile::speed`). `root_motion` (left out when off) moves the MeshPart by the root bone's travel; see `docs/rendering/animation.md`. `retarget` (left out when there's none) names a retarget profile (below). Re-exporting the model updates the clip, since its motion is read from the file.
  - A **track**: `{ "id": "position", "target": ".", "property": "Position", "keys": [ { "id": "k1", "time": 0.0, "value": [0, 2, 0], "interp": "Linear" } ] }`. `target` is a path from the Animator's parent: `.` is that Part, Model or ScreenGui, and `Hinge/Panel` is a descendant by names (`anim::target_path` makes these); a bone is named the same way, by the bones above it (`Root/Mid/Top`, or just its name; unnamed bones are left out, `anim::bone_paths`). Bone tracks pose the skeleton of the Animator's parent, which must be a MeshPart whose model has one. `property` is `Position`, `Orientation`, `Size`, `Color`, `Transparency`, `BackgroundColor3`, `BackgroundTransparency`, `TextColor3`, `TextSize`, `ImageTransparency`, or `Bone` for a bone's transform. A key's `value` is the property's numbers (v3 Phase 5): `[x, y, z]` for a Vector3 (Orientation in degrees), `[r, g, b]` from 0 to 1 for a Color3, `[x_scale, x_offset, y_scale, y_offset]` for a UI element's UDim2 `Position` or `Size`, `[n]` for a number, and 10 numbers for a bone (translation, rotation quaternion `x, y, z, w`, scale, relative to its parent bone). Every key on a track has the same count, which must fit the property; it's applied by the target's own property kind. `interp` is how a key moves to the next one (unified Phase 8, `anim::sample_track`): `Step` (Constant in the editor: held until the next key), `Linear`, `Ease` or `Bezier`. An `Ease` key has `"easing": { "style": "Quad", "direction": "Out" }`, with `style` `Sine`, `Quad`, `Cubic`, `Back`, `Bounce` or `Elastic` and `direction` `In`, `Out` or `InOut` (Quad InOut if left out; `anim::ease`). A `Bezier` key has `"bezier": [x1, y1, x2, y2]`, its handles to the next key as CSS's `cubic-bezier` has them: `x` is time and `y` how far along, both 0 to 1 across the gap, `x` kept in 0..=1 and `y` free to overshoot (`[0.42, 0, 0.58, 1]` if left out; `anim::cubic_bezier`). Both fields are left out when unset, so clips from before them read and save unchanged and the format didn't change. The eased amount blends the two keys as `Linear` does: Orientation and bone rotations by quaternion slerp, everything else straight between numbers.
  - In a linked clip, a bone track for a bone the take moves is left out (the take moves it); its other tracks play alongside the take, so one clip can wave an arm and fade a sword (`Sword`, `Transparency`).
  - **Convert to keys** (`anim::convert_to_keys`) turns a linked clip into a keyed one: every bone the take moves gets a `Bone` track (`bone1`, `bone2`…) with a key a frame (the take's frame rate) over the clip's range, at the clip's own times, less the keys that linear blending between the keys around them already makes (within 0.0001 and 0.001 radians; a bone that never moves keeps one key). The link goes; `duration`, `loop`, events and the clip's other tracks stay. Bone keys are written with each rotation on the same side as the one before.
  - Values are where things are in the world, as Properties shows them. On a **Model**, `Position` and `Orientation` are its pivot: the middle of the box around its parts when it first plays, turned from how it was built; every part inside moves with it. A Part whose `Position` or `Orientation` is animated carries the parts inside it (a door's Panel inside its Hinge). Parents are applied before children, so a child's own tracks win.
  - Played by an Animator: its state machine's states, AnimationTracks from `LoadAnimation`, and Animations played with AutoPlay (see `docs/scripting/api-animation.md`).
- A **state machine** (`*.statemachine.json`; an "animator controller", `*.controller.json`, before v3 Phase 7, with the same content): `{ "format_version": 2, "parameters": [ { "type": "Bool", "name": "IsGrounded", "default": true }, { "type": "Number", "name": "Speed", "default": 0.0 }, { "type": "Trigger", "name": "Jump" } ], "default_state": "Idle", "states": [ { "name": "Idle", "motion": { "clip": "assets/animations/noodle/Idle.anim.json" }, "speed": 1.0, "position": [0.0, 0.0] } ], "transitions": [ { "from": "Any State", "to": "Jump", "conditions": [ { "parameter": "Jump", "test": "Triggered", "value": 0.0 } ], "blend": 0.25, "exit_time": null, "interruptible": false, "priority": 0 } ] }`. `position` places a state in the editor's graph. Condition tests are `IsTrue`, `IsFalse` (Bools), `Triggered` (Triggers), `Greater` and `Less` (Numbers, against `value`). An empty or unknown `default_state` starts in the first state. A state's clip may be `""` (no clip: it holds the rest pose). A state can have a Return setting (Phase 42): `"returns": { "to": "Idle", "when": "finished", "blend": 0.25 }`, where `when` is `"finished"`, `{ "bool_is": { "parameter": "IsAttacking", "value": false } }`, `{ "triggered": { "parameter": "Land" } }` or `{ "after": { "seconds": 2.0 } }`; the transition it makes is saved too, with `"generated": true` (and made again when the file is loaded, so a hand-edited setting works). A state's `motion` can also be a blend tree (Phase 41): `{ "blend_tree": { "parameter": "Speed", "children": [ { "clip": "assets/animations/noodle/Idle.anim.json", "threshold": 0.0 }, { "clip": "…/Walk.anim.json", "threshold": 2.0 } ] } }`. A state's `motion` can be a 2D blend space (Phase 78): `{ "blend_space": { "parameter_x": "MoveX", "parameter_y": "MoveZ", "children": [ { "clip": "…/Idle.anim.json", "position": [0.0, 0.0] }, { "clip": "…/StrafeLeft.anim.json", "position": [-1.0, 0.0] } ] } }`. **Layers** (Phase 78, optional, left out when there are none, so older files read and save the same): `"layers": [ { "name": "UpperBody", "weight": 1.0, "mode": "Override", "mask": ["Hips/Spine"], "default_state": "Empty", "states": [ … ], "transitions": [ … ] } ]`, each with its own states and transitions (and `any_state_position`/`entry_position` once moved), sharing the file's `parameters`; `mode` is `Override` or `Additive` (Override if left out), `weight` 1 if left out, and `mask` bone paths, each with everything under it (left out: the whole skeleton). `exit_time` is `null` or how much of the state's clip (1 is once through); see `docs/rendering/animation.md` (Transitions) for how they run. `any_state_position` and `entry_position` (where the editor draws the Any State and Entry; `entry_position` since unified Phase 8d, optional, so older files read the same) are written only once they've been moved.
- A **rig definition** (`assets/rigs/<name>.rig.json`, AP1; `assets::RigDefinition`, read once by `Assets::rig_definitions`, again after one changes): `{ "format_version": 1, "bones": { "Hips": "root_pelvis", "LeftLowerArm": "arm_lo.L", "LeftIndexProximal": "finger_a1.L", "Chest": "" } }`. It maps humanoid roles (the names in `docs/rendering/animation.md`, Humanoid retargeting; any case) to the skeleton's bone names for retargeting; `""` means no bone plays that role, and roles it leaves out are matched by name. It isn't tied to a model: it applies to every skeleton (a model's or an animation file's) that has every bone it names, and when several fit, the one naming the most bones wins, then the first by path. Keys are sorted, so saving the same map gives the same text. Unknown fields are errors; a file that can't be read is reported once in Output and left out.
- A **retarget profile** (`assets/rigs/<name>.retarget.json`, AP2; `anim::RetargetProfile`), named by a clip's link as `"retarget": "assets/rigs/Hero.retarget.json"` (left out when there's none): `{ "format_version": 1, "match_rest_pose": true, "hips": "Scaled", "plant_feet": false, "match_hands": false, "fingers": 1.0, "roles": { "Head": { "weight": 0.5 }, "LeftHand": { "offset": [0, 0, 10] } } }`. Every field but `format_version` may be left out (the values shown are the defaults; `roles` is left out when empty). `hips` is `Scaled`, `Unscaled` or `InPlace`; `fingers` and a role's `weight` go from 0 to 1; a role's `offset` is degrees about its bone's own X, Y and Z. Role names are the humanoid roles' (any case); an unknown role or field is an error. Profiles name roles, not bones, so a clip with one still plays on any humanoid. What each setting does: `docs/rendering/animation.md` (Humanoid retargeting).
- **Format 1** files are refused by `ClipFile::from_json` and `StateMachineFile::from_json` since unified Phase 92 ("it is in an older animation format (1); open its project in the editor to upgrade it"); the project upgrade reads them (`project/src/migrate_shapes.rs`'s `read_clip` and `read_state_machine`, used by the 2 → 3 and 5 → 6 steps) and writes them in the one shape: a take clip (`source`, `take`, `start`, `end`, `speed`, `loop`, `root_motion`, events in seconds of the take) becomes a linked clip whose duration is its length over its speed (a negative speed swaps `start` and `end`), and a property clip (`"kind": "property"`) drops its kind. Opening a format 2 project upgrades its files once (see `docs/project/layout.md`).
- `examples/hello-animation` has a generated rig (`noodle.fbx`, from `assets` `model/test_rig.rs`; a test checks it's up to date, and `AXCENITY_WRITE_EXAMPLES=1` rewrites it), five linked clips and a state machine in `assets/animations/noodle/`; `examples/hello-door` has one keyed clip, `assets/animations/Door/Door.anim.json`. Tests check those files are saved as the engine writes them.
