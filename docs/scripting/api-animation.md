# Animator, Animation and AnimationTrack

Animation from Lua.

- **Animator** (Phase 38; any parent since v3 Phase 7): put one in a Part, MeshPart, Model, ScreenGui or UI element. It plays animation on its parent while the game runs: its state machine, if `StateMachine` names one (`"assets/animations/hero/hero.statemachine.json"`; importing an animated FBX makes one), and the AnimationTracks loaded on it. On a MeshPart with a skeleton it poses the bones; on anything it sets the properties clips key. `Enabled` false holds everything still; `Speed` scales everything (0 pauses).
  - **State machine**: it starts in the default state. `animator:Play("Walk", blend?)` switches to a state from its start, blending from the pose now over `blend` seconds (0.25 if left out, 0 snaps; it must be a number 0 or more, and the state a string; an unknown state is reported in Output and changes nothing). `animator.CurrentState` is the state's name (read-only: setting it explains to use `Play`; empty for an Animator the host hasn't run, such as one just made with `Instance.new`). `animator.StateChanged` fires with the new state's name and the old one's, after the frame's Heartbeat. Parameters (Phase 40): `animator:SetBool(name, value)` (true or false), `SetNumber(name, n)` (finite), `SetTrigger(name)` and `ResetTrigger(name)`, and `GetBool(name)` and `GetNumber(name)`. They change the animator's live parameters, which its transitions test (see `docs/rendering/animation.md`, Transitions); a Trigger stays set until a transition uses it. Setting one as another type than it is ("`Speed` is a Number parameter; use SetNumber…") or reading one it doesn't have (the error lists those it has) is an error; setting one it doesn't have adds it, and the host reports once that its state machine doesn't have it. `animator.AnimationEvent` (Phase 39) fires with an event's name each time the state machine's clip passes one of its events, such as `"Footstep"` for a sound. **Layers** (Phase 78): `animator:SetLayerWeight(name, weight, fadeTime?)` sets how much a state machine layer counts (kept in 0–1; a number, finite), fading there over `fadeTime` seconds (0 or more; at once if left out), and `animator:GetLayerWeight(name)` reads it now (0 for a layer the Animator hasn't started; a weight set before the Animator first runs takes effect at once). A weight for a layer the state machine doesn't have is reported once by the host. Layer weights replicate with the parameters ([../architecture/networking.md](../architecture/networking.md)). Test: `animator_layer_weights_are_set_faded_and_read`.
  - `animator:LoadAnimation(animation)` returns an **AnimationTrack** for an Animation (anything else is an error). `animator:GetPlayingAnimationTracks()` lists the tracks loaded on it that are playing.
  - Live state (parameters, `CurrentState`, the requested state, its tracks) is `core::AnimatorState`, kept in the `World` beside the Instances rather than as properties, so it's never saved; hosts prime their Animators before scripts start, so `CurrentState` is set from the first line of a script.
- **Ragdoll** (Phase 41): put one in a skinned MeshPart and press Build in its Properties. `Enabled` (false) hands the skeleton to physics; setting it false gets up: the Animator plays `GetUpState` (a state's name, or `""`) and the pose blends back over `BlendTime` (0.5 s). `ragdoll:ApplyImpulse(bone, impulse)` pushes the body of the bone named `bone` (`"Head"` finds `mixamorig:Head`) as `part:ApplyImpulse` does; turn the ragdoll on in the same frame for it to knock. How it runs: `docs/rendering/animation.md`, Ragdolls.
- **IKControl** (Phase 79): put one in a skinned MeshPart (or its Animator): Insert > IK Control. It turns bones after the Animator and before drawing. `Type` is `"Position"`, `"Rotation"`, `"Transform"` or `"LookAt"`; `EndEffector` and `ChainRoot` name bones (`"Head"` finds `mixamorig:Head`); `Target` and `Pole` are a Part or an Attachment; `Weight` (1) says how much; `Enabled` off, or no Target, goes back to the plain animation; both fade over `SmoothTime` (0.1 s). LookAt faces the Target and holds at `MaxAngle` (75) from the way the character faces (`Forward`, 0 for the skeleton's own). `Weight` and `Target` replicate; IK itself runs on each device. How it runs: `docs/rendering/animation.md`, Runtime IK.
- **Animation** (v3 Phase 7): points at a clip (`Clip`, `"assets/animations/Door/Door.anim.json"`). Put it beside the Animator (on the same parent) or under it. With `AutoPlay` ticked, the Animator plays it by itself when the game starts, with no script.
  - `animation:Play()`, `Stop`, `Pause` and `Resume`, and its `Completed` and `AnimationEvent`, keep working from before: the Animator on the same parent plays it (from the start; `Stop` goes back to the start; it holds its last frame at the end). `Looped` decides whether `Play` loops it, and `Enabled` and `Speed` work like other playback Instances. The first of these calls on each side prints once that `animator:LoadAnimation(animation)` is the new way. If there's no Animator, it still plays on its parent. Live playback is `core::PropertyAnimationState` (not saved).
- **AnimationTrack** (v3 Phase 7): one Animation loaded on an Animator, made by the engine (`Instance.new` refuses), unparented and never saved. Its playback is `core::AnimationTrackState`.
  - `track:Play(fadeTime?, weight?, speed?)` plays the clip from its start, fading in over `fadeTime` seconds (0.1 if left out) to `weight` (1) at `speed` (1). `track:Stop(fadeTime?)` fades it out (0.1); `Stopped` fires once it has. `track:AdjustSpeed(speed)` and `track:AdjustWeight(weight, fadeTime?)` change those as it plays.
  - `IsPlaying` (from Play until Stop or the end of a clip that doesn't loop), `Length` (0 until the host has read the clip, the frame after loading), `Speed` and `WeightCurrent`/`WeightTarget` are read-only; `Looped` (starting as the clip's own) and `TimePosition` (seconds; setting it jumps there without firing the events it passes) can be set. `Animation` is the Animation it was loaded from.
  - `track.KeyframeReached` fires with an event's name each time it passes one; `track:GetMarkerReachedSignal(name)` is an event for one name, whose handler gets the name.
  - A clip that doesn't loop stops at its end: its last frame is applied, `Stopped` fires, and it lets go. Properties keep the value last given; bones go back to what plays under it.
- **Blending**: each frame an Animator plays its state machine first, then its tracks and played Animations over it, the oldest start first, so where two animate the same thing the one started last wins. A track counts by its weight: bones it moves are mixed toward its pose, and properties it keys toward its values, by `WeightCurrent`. Root motion comes from the state machine only. See `docs/rendering/animation.md`.
- `examples/hello-door` plays its door with `door.Animator:LoadAnimation(door.Open)` when something lands on the Pad; `examples/hello-animation` drives a state machine from keys.
