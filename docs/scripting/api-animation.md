# Animator and Animation

Skeletal animators and property clips from Lua.

- **Animator** (Phase 38): put one in a MeshPart whose model is animated (an FBX with a skeleton, or animated objects) and set `Controller` to an animator controller file in the project (`"assets/animations/hero.controller.json"`; importing an animated FBX makes one). During Play it starts in the controller's default state and plays it on the model. `animator:Play("Walk", blend?)` switches to a state from its start, blending from the pose now over `blend` seconds (0.25 if left out, 0 snaps; it must be a number 0 or more, and the state a string; an unknown state is reported in Output and changes nothing). `animator.CurrentState` is the state's name (read-only: setting it explains to use `Play`; empty for an Animator the host hasn't run, such as one just made with `Instance.new`). `Enabled` false holds the pose; `Speed` scales every state (0 pauses). `animator.StateChanged` fires with the new state's name and the old one's, after the frame's Heartbeat. Parameters (Phase 40): `animator:SetBool(name, value)` (true or false), `SetNumber(name, n)` (finite), `SetTrigger(name)` and `ResetTrigger(name)`, and `GetBool(name)` and `GetNumber(name)`. They change the animator's live parameters, which its transitions test (see `docs/rendering/animation.md`, Transitions); a Trigger stays set until a transition uses it. Setting one as another type than it is ("`Speed` is a Number parameter; use SetNumber…") or reading one it doesn't have (the error lists those it has) is an error; setting one it doesn't have adds it, and the host reports once that its controller doesn't have it. `animator.AnimationEvent` (Phase 39) fires with an event's name each time the playing clip passes one of its events (see `docs/rendering/animation.md`, Animation events), such as `"Footstep"` for a sound. Live state (parameters, `CurrentState`, the requested state) is `core::AnimatorState`, kept in the `World` beside the Instances rather than as properties, so it's never saved; hosts prime their Animators before scripts start, so `CurrentState` is set from the first line of a script.
- **Animation** (property clips): put one in a Part, MeshPart, Model, ScreenGui or frame and set `Clip` to a property clip (`"assets/animations/Door.anim.json"` with `"kind": "property"`). `animation:Play()` plays from the start; `Stop` resets; `Pause` / `Resume` hold and continue. `Enabled`, `Speed` and `Looped` (overrides the clip's loop for playback) work like other playback Instances. `Completed` fires when a non-looping clip finishes; `AnimationEvent` fires with each marker name as the clock crosses it. Live time/playing state is `core::PropertyAnimationState` (not saved). See `examples/hello-door`. Animator remains for skeletal controllers; Animation is for authored tracks of Parts, Models and UI elements.
