# Core Lua API

Globals, Instances, values, events, and RunService.

- Globals: `game`, `workspace`, `script` (the running Script, LocalScript or ModuleScript), `print`, `require(module)` (see Modules), `Instance.new(className)`, `Vector3.new(x, y, z)`, `Vector2.new(x, y)` (screen pixels, such as a ScrollingFrame's `CanvasPosition`; `.X`, `.Y`, `.Magnitude`, `+`, `-`, `*` and `/` by a number or a Vector2, unary `-`, and the math methods below except `Cross`), `Color3.new(r, g, b)`, `Color3.fromRGB(r, g, b)`, `Color3.fromHSV(h, s, v)`, `Color3.fromHex(hex)`, `CFrame` and `Random` (below), `UDim2.new(xScale, xOffset, yScale, yOffset)`, `UDim2.fromScale(x, y)`, `UDim2.fromOffset(x, y)`, `Enum` and `task` (see Execution model), and `typeof(value)` (`"Instance"`, `"Vector3"`, `"EnumItem"`, ...; see Sandbox).
- `game:GetService(name)` returns a service by class name (`Workspace`, `Players`, `ReplicatedStorage`, `ServerScriptService`, `StarterPlayer`), or one of the engine services that aren't Instances (`RunService`, `HttpService`, `UserInputService` and the rest in `instance::get_service`, and `Debris` and any other service a game system adds: [../architecture/game-systems.md](../architecture/game-systems.md)); a wrong name lists the choices. `Instance.new("Player")` is an error: Players are made when someone joins.
- Instances: `Name`, `ClassName` (read-only), `Parent` (an Instance or `nil`), every property in `core`'s class table, and `:FindFirstChild(name, recursive?)`.
- **Identity** (roadmap I2, `instance.rs`): each script VM hands out one userdata per Instance (a weak-valued cache in the Lua registry, keyed by arena index and checked against the full ID), so `rawequal(workspace.Baseplate, workspace.Baseplate)` is true and an Instance works as a table key (`data[player]` across `PlayerAdded` and `PlayerRemoving`). A destroyed Instance's userdata keeps its stale ID; a new Instance in the same arena slot gets its own userdata.
- **Tree methods** (Phase 27, `crates/script/src/tree.rs`): `GetChildren`, `GetDescendants` (parents before children), `IsA(className)` (`ClassName::is_a` in `core`: abstract classes are `BasePart` for Part, MeshPart and Seat (a Seat is also a `Part`), `PVInstance` for those and Model, `GuiObject` and `GuiBase2d` for screen elements, `GuiButton`, `LayerCollector` for ScreenGui and BillboardGui, `Light`, `LuaSourceContainer`, and a LocalScript is a `Script`; everything is an `Instance`), `FindFirstChildOfClass`, `FindFirstChildWhichIsA(className, recursive?)`, `FindFirstAncestor`, `FindFirstAncestorOfClass`, `FindFirstAncestorWhichIsA` (ancestors go up to `game`), `IsDescendantOf`, `IsAncestorOf`, `GetFullName` (`Workspace.Model.Part`; `game` left out), `ClearAllChildren` (skips services), `Clone` and `Destroy`.
- **`Clone`** copies the Instance and its descendants (everything `World::duplicate` copies, attributes and tags too; an ObjectValue in the copy that points inside the original points at the same place in the copy) and returns the copy with no Parent. A copied Script or LocalScript runs its original's code (from the runtime's started scripts) once it's somewhere scripts of its kind run: a Script in the Workspace or ServerScriptService; a LocalScript in the Workspace, StarterPlayerScripts or Players. It starts at the runtime's next `fire_changes` (right after the cloning script pauses or finishes), and waits there until it's moved somewhere it runs. A copied ModuleScript can be required at once on the side that cloned it, as a module of its own. A Script made with `Instance.new` has no code, so it never runs.
- **`Destroy`** fires `Destroying` on the Instance and everything inside it (once each, even if a handler destroys it again), then `DescendantRemoving` on its ancestors and `AncestryChanged(instance, nil)`, all before the Instances go, so handlers can still read them; then they go and their IDs are stale. Destroying twice does nothing. A destroyed Instance's `Parent` is locked: setting it errors "can't set Parent: this Instance has been destroyed, so its Parent is locked" (reading any member errors "this Instance has been destroyed"). Parenting to a destroyed Instance errors too. Services can't be destroyed or cloned ("Workspace is a service, so it can't be destroyed"), and nothing changes. A started script whose Instance is destroyed stops at the runtime's next `fire_changes` (`stop_destroyed_scripts`): its handlers disconnect and its waits are dropped, so a script that destroys itself finishes the code it's running until its next `task.wait`, and no more.
- **World streaming** (Phase 80, [architecture/streaming.md](../architecture/streaming.md)): `Instance.StreamingState` (`Enum.StreamingState.StreamedIn` or `StreamedOut`) and the `StreamedIn` event work on an Instance that's away, so scripts can handle parts that aren't there; `Player:RequestStreamAroundAsync(position)` loads a region and waits for it, before a teleport.
- **`WaitForChild(name, timeout?)`** returns the child at once if it's there, otherwise waits a frame at a time (through `task.wait`, so only in a coroutine) until it is. With a timeout, returns `nil` once that many seconds have passed. Without one, it adds one warning to Output after 5 seconds (`OutputKind::Warning`, naming the child and where) and keeps waiting, as Roblox's "infinite yield" does. It's Lua (`WAIT_FOR_CHILD`), because Rust functions can't pause a coroutine.
- **`workspace:Raycast(origin, direction)`** (v2 Phase 6): the first collider along `direction` from `origin`, or `nil`. The direction's length is how far the ray reaches. Hits sensors (`CanCollide` off) as well as solid Parts, MeshParts and Terrains. The result table has `Instance`, `Position`, `Normal` and `Distance`. Does not move anything. The editor can draw recent casts (Viewport > Overlays > Raycasts); the player never draws them. Hosts pass the project's `Assets` (`ScriptRuntime::set_assets`) so MeshParts collide as their hulls, matching physics.
- **Spatial queries** (Phase 38, `script/src/query.rs` over `physics` queries; `docs/architecture/physics.md`): `workspace:Raycast(origin, direction, params?)`, `workspace:Spherecast(position, radius, direction, params?)`, `workspace:Blockcast(cframe, size, direction, params?)` and `workspace:Shapecast(part, direction, params?)` return a RaycastResult or nil; `workspace:GetPartBoundsInBox(cframe, size, params?)`, `workspace:GetPartBoundsInRadius(position, radius, params?)` and `workspace:GetPartsInPart(part, params?)` return a list of parts. None step or change the world. Scripts' queries pass by parts with `CanQuery` off. `RaycastParams.new(fields?)` (for the casts) and `OverlapParams.new(fields?)` (for the lists) have `FilterDescendantsInstances` (a list; each Instance and everything inside it), `FilterType` (`Enum.RaycastFilterType.Exclude`, the default, or `Include`), `CollisionGroup` (`"Default"`), `RespectCanCollide` (false) and `AddToFilter(instance or list)`; RaycastParams also has `IgnoreWater` (no water yet, so it changes nothing) and OverlapParams `MaxParts` (0, no limit). `fields` is an optional table of starting values, an Axcenity addition so a block can make one in an expression. Passing the other kind of params is an error.
- **PhysicsService** (Phase 38): `game:GetService("PhysicsService")` on both sides has `RegisterCollisionGroup(name)`, `CollisionGroupSetCollidable(a, b, collidable)` and `CollisionGroupsAreCollidable(a, b)` over the world's collision groups (unknown names are errors). Changes last until Stop. Parts join a group with `CollisionGroup`.
- **Children by name** (decided in Phase 4): `workspace.Block` returns the first child named `Block`. Methods and properties win over children with the same name. A name that's none of these errors with `X is not a valid member of Workspace "Workspace"`.
- **Enums** (decided in Phase 4): `Enum.Material.Neon`, `Enum.PartType.Ball` and (Phase 14) `Enum.KeyCode.W`. Enum items are `LuaEnumItem { enum_type, name }` in `types.rs`; `KeyCode` isn't a property type, so it isn't a `Value`. Enum properties also accept the item's name as a string (`part.Material = "Neon"`); a wrong name errors and lists the choices. Reading always gives an enum item, which prints as `Enum.Material.Neon` and has `.Name` and (Phase 32) `.Value`: a RenderPriority's priority, otherwise its place in its enum's list from 0 (not Roblox's numbers).
- `Vector3`: `.X .Y .Z .Magnitude .Unit`, `+ -`, `*` and `/` by a number or another Vector3 (a number on either side), unary `-`, `==`. Prints as `1, 2, 3`. Methods (Phase 28, `types.rs`): `Dot`, `Cross`, `Lerp(goal, alpha)`, `Angle(other, axis?)` (radians; signed by the axis), `FuzzyEq(other, epsilon?)` (each component within epsilon, default 0.00001), `Min(...)`, `Max(...)`, `Abs`, `Floor`, `Ceil`. Constants `Vector3.zero`, `one`, `xAxis`, `yAxis`, `zAxis` (Vector2 has the same but `zAxis`; its `Angle(other, isSigned?)` is negative anticlockwise on screen).
- `Color3`: `.R .G .B`, `==`, `Lerp(goal, alpha)` (channels clamped to 0 to 1), `ToHSV()` (three numbers from 0 to 1) and `ToHex()` (six lowercase digits, no `#`). `Color3.fromHex` takes 6 or 3 digits, with or without `#`, in either case. `Color3.new` rejects channels outside 0 to 1 with a hint to use `fromRGB`, matching the world file's check (Roblox allows them silently).
- **`CFrame`** (Phase 28, `cframe.rs`): a position and a rotation (a glam `Quat`) in one value, never stored. `CFrame.new()`, `new(position)`, `new(x, y, z)`, `CFrame.lookAt(at, target, up?)`, `CFrame.Angles(rx, ry, rz)` (X then Y then Z, in radians, as Roblox), `CFrame.fromEulerAnglesYXZ` (the `Orientation` order), `CFrame.fromAxisAngle(axis, angle)` and `CFrame.identity`. Fields `Position`, `X`, `Y`, `Z`, `Rotation`, `LookVector` (-Z), `RightVector` (+X), `UpVector` (+Y). `*` with a CFrame or a Vector3 (a point), `+`/`-` a Vector3, `==`; methods `Inverse`, `Lerp` (slerp, the short way round), `ToWorldSpace`, `ToObjectSpace`, `PointToWorldSpace`, `PointToObjectSpace`, `VectorToWorldSpace`, `VectorToObjectSpace` (each takes one value) and `ToEulerAnglesYXZ` (radians). Prints as 12 numbers: the position, then the rotation matrix row by row.
- **`Part.CFrame`** (and MeshPart) is read from `Position` and `Orientation` (degrees, Z then X then Y) and setting it writes them back, with `Orientation` rounded to 3 decimals (X from -90 to 90, Y and Z from -180 to 180). A property the new CFrame doesn't change keeps its stored value exactly, so `part.CFrame = part.CFrame` leaves a saved world byte-for-byte the same, even for an `Orientation` such as (0, 270, 0). **`GetPivot()` / `PivotTo(cf)`** on Part, MeshPart and Model: a part's pivot is its CFrame; a Model's is the centre of the box around its descendant parts, unturned (the origin with no parts). `PivotTo` moves a part alone, or every part in a Model rigidly; pivoting to the current pivot changes nothing. Models have no `PrimaryPart` yet; Instance-reference properties exist since Phase 29 (`Value::Instance`, used by `ObjectValue`).
- **`Random.new(seed?)`** (Phase 28, `random.rs`): PCG32 in whole-number arithmetic, so a seed gives the same numbers on every run and platform (`NextUnitVector` rejects points outside the unit ball rather than using `sin`/`cos`). No seed takes one from the operating system. `NextNumber(min?, max?)` (0 to 1 by default, max excluded), `NextInteger(min, max)` (both included; min above max errors), `NextUnitVector()`, `Shuffle(list)` (in place) and `Clone()`.
- **UI Instances** (Phase 22): `ScreenGui` under `Workspace` contains `Frame` and `TextLabel` instances. `Position` and `Size` are `UDim2` values; each `.X` and `.Y` exposes `.Scale` and `.Offset`. The player and editor Play viewport recompute layout after scripts each frame, including after a resize.
- Numbers are Luau numbers (always decimals), so `print(part.Position.Y)` shows `5`, and `5.5` as `5.5`.
- **Events** (decided in Phase 7): `part.Touched` is a Signal. `signal:Connect(fn)` returns a Connection with `:Disconnect()` (calling it twice is harmless) and `.Connected`. `Touched` handlers get the other part. Event names come from `ClassName::events()` in `core`, plus `INSTANCE_EVENTS`, which every class has; `instance.Key` checks them after properties and before children, and assigning to one explains how to connect instead. Connections to a destroyed Instance are dropped at the next step. `:Once` and `:Wait` aren't built yet.
- **Tree events** (Phase 27): `DescendantAdded` and `DescendantRemoving` (handler gets the descendant; once for the Instance that moved and once for each Instance inside it, on every ancestor), and `AncestryChanged` (on the Instance that moved and everything inside it; handler gets that Instance and its new Parent). They come from the change log like `ChildAdded`, so they fire after the change, against the tree as it is then: `DescendantRemoving` fires once the Instance has been taken out (`Destroy` fires its own before), and an Instance put into a model that joins the Workspace later in the same batch is reported once, with the model. `Destroying` is fired by `Destroy` itself.
- **Change events** (Phase 16): every Instance has `Changed` (handler gets the property's name, as a string), `ChildAdded` and `ChildRemoved` (handler gets the child), and `instance:GetPropertyChangedSignal("Position")` (handler gets nothing; a wrong name lists the choices). `Name` and `Parent` count as properties. They fire whoever made the change: a script, physics (a falling part's `Position` and `Orientation`, every physics step it moves) or the editor during Play. Setting a property to the value it already has isn't a change. Unlike Roblox, physics movement does fire them (the plan asks for it). See Execution model for when they run.
- **`RunService`** (Phase 16, chosen by the developer; `run_service.rs`): `game:GetService("RunService")` (or `game.RunService`) has `Heartbeat`, which fires once a frame after physics and `Touched`, on both sides, with the frame's length in seconds. Not an Instance (like `UserInputService`), so it isn't in the Explorer. Since Phase 32: `Stepped(time, deltaTime)` fires on both sides before physics (`ScriptRuntime::stepped`; `time` is the game time, the scheduler's clock), and on LocalScripts only `RenderStepped(deltaTime)` fires just before the frame is drawn (`ScriptRuntime::render_step`, see [frame order](../architecture/frame-loop.md)). `BindToRenderStep(name, priority, fn)` (LocalScripts only) runs `fn(deltaTime)` every frame in that render step, lowest priority first, ties in the order bound, each as its own coroutine, before `RenderStepped`; binding a name again replaces it, and `UnbindFromRenderStep(name)` stops it. The priority is a number or an `Enum.RenderPriority` item (`First` 0, `Input` 100, `Camera` 200, `Character` 300, `Last` 2000; `.Value` gives the number). `IsServer()`, `IsClient()`, `IsStudio()` (the editor's Play, `ScriptRuntime::set_studio`, and its Console) and `IsRunning()` (false only in the Console outside Play).
- **BindableEvent and BindableFunction** (Phase 32, `bindable.rs`): Instances (Explorer Insert, into ReplicatedStorage) for scripts on **one side** to talk; nothing crosses between Scripts and LocalScripts. `event:Fire(...)` fires `event.Event` at once, each handler in its own coroutine, with the same values (tables aren't copied, unlike Roblox). `func.OnInvoke = function(...) ... end` sets the function `func:Invoke(...)` calls in the caller's own coroutine, so it may wait and its errors are the caller's; Invoke with no `OnInvoke` on that side errors (Roblox waits). `OnInvoke` and a RemoteFunction's `OnServerInvoke` are **callbacks**: set, never read (reading errors as Roblox's does), kept per side in `bindable::Callbacks`, owned by the script that set them (dropped when it stops), and nil removes one.
- **`Debris`** (Phase 32, the `gameplay` crate's `debris.rs`): `game:GetService("Debris"):AddItem(instance, seconds?)` (10 when left out) destroys the Instance (with `Destroy`'s events) once that much game time has passed, at the end of frame step 2 on the side that added it, without the script waiting. Items belong to the side, not the script, and one already destroyed is skipped.
- **`ContentProvider`** (roadmap M5, `content_provider.rs`): `PreloadAsync(contentIds, callback?)` pauses the script until everything listed has loaded or failed, while the game and other scripts go on. An entry is a project file path or an Instance, which stands for the files it and its descendants use (`MeshId`, `MaterialVariant`, texture maps, `Texture`, `TextureId`, `Image`, `SoundId`, `Bake`, `SkyImage`, foliage models). A failed file isn't an error: why goes to the Output, and `callback(path, status)` (`Enum.AssetFetchStatus.Success` or `Failure`) hears about each file, on a thread of its own. `RequestQueueSize` is how many files are still waiting or loading. Both sides have it. The file's name says what it's loaded as ([../project/assets.md](../project/assets.md)).
- **`DataService`** (Phase 33, `data.rs`): `GetTable(name)` reads a project data table, read-only; see [../project/data-tables.md](../project/data-tables.md).
- **`HttpService`** (Phase 32, `http.rs`; no network): `JSONEncode(value)` (a table with keys 1 to n, or empty, is an array; one with text keys an object; whole numbers have no decimal point; a mixed table, a cycle, NaN or infinity, non-UTF-8 text or any other type errors), `JSONDecode(text)` (serde_json; `null` is nil; a mistake errors as `JSONDecode can't read this JSON: <what> at line L column C`) and `GenerateGUID(wrapInCurlyBraces = true)` (a random version 4 GUID in capitals, from two `Random` generators with fresh seeds).
- **Attributes** (Phase 29, `collection.rs`): `SetAttribute(name, value)`, `GetAttribute(name)` (nil when missing), `GetAttributes()` (a table) and `GetAttributeChangedSignal(name)` (handler gets nothing) on every Instance, and the `AttributeChanged` event (handler gets the name; it fires before the attribute's own signal). A value is a boolean, number, string, Vector3, Vector2, Color3, UDim2, CFrame or EnumItem; nil removes it; anything else errors and lists the kinds. Names are 1 to 100 letters, digits and underscores, not starting with `RBX` (`core::is_attribute_name`). Stored per Instance in `core` (`Instance::attributes`, `World::set_attribute`); a property enum's item is kept as a plain `Value::EnumItem` (`Material.Neon`), so every enum item reads back the same way. Setting the value it already has isn't a change. They come from the change log (`Change::Attribute`), like `Changed`; `Changed` itself doesn't fire for attributes.
- **Tags** (Phase 29): `game:GetService("CollectionService")` (or `game.CollectionService`; not an Instance) has `AddTag(instance, tag)`, `RemoveTag`, `HasTag`, `GetTags(instance)` (in the order added), `GetTagged(tag)` (Instances in the game, parents before children), `GetAllTags()`, `GetInstanceAddedSignal(tag)` and `GetInstanceRemovedSignal(tag)` (handlers get the Instance). Every Instance also has `AddTag`, `RemoveTag`, `HasTag` and `GetTags`. As in Roblox, an Instance counts as tagged only while it's inside `game`, so the signals also fire when a tagged Instance joins the game (a clone parented to the Workspace) or leaves it. Once a tag has a signal, each side keeps the Instances it last saw with it and fires the difference after each round of change events (`fire_tag_changes`); Instances that joined in the same round come in tree order. `Destroy` fires the removed signal itself, while the Instance can still be read.
- **Value objects** (Phase 29): `IntValue`, `NumberValue`, `StringValue`, `BoolValue`, `Vector3Value`, `Color3Value`, `CFrameValue` and `ObjectValue`, each with one property, `Value` (`ClassName::is_value_object`; all `IsA("ValueBase")`). An IntValue rounds to a whole number (`World::set_property`). A CFrameValue stores a `core::CFrame` (position and quaternion); an ObjectValue stores `Value::Instance`, an Instance or nil, and reads nil once its target is destroyed. Their `Changed` fires only for `Value`, with the new value, not the property's name (`changes.rs`); `GetPropertyChangedSignal("Value")` works as usual. Insert them from Explorer Insert ▸ Value.
