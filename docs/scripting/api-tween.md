# TweenService

Moving a property smoothly to a goal from Lua and blocks (`crates/script/src/tween.rs`).

- `local TweenService = game:GetService("TweenService")` (also `game.TweenService`), on both sides. `TweenService:Create(instance, tweenInfo, goals)` returns a **Tween** for the properties in `goals`, a table such as `{Position = Vector3.new(0, 5, 0), Color = Color3.new(1, 0, 0)}`. Numbers, `Vector3` (so `Position`, `Orientation` and `Size` on Parts), `Color3`, `UDim2` and booleans (which switch at the end) tween; anything else, or a name that isn't a property of the Instance, is an error from `Create`. `ZIndex` and `DisplayOrder` step in whole numbers once they exist.
- `TweenInfo.new(time, easingStyle, easingDirection, repeatCount, reverses, delayTime)`: each may be left out, giving 1 second, `Enum.EasingStyle.Quad`, `Enum.EasingDirection.Out`, 0 repeats, no reversing and no delay. `Enum.EasingStyle` is Linear plus the clip key easings (Sine, Quad, Cubic, Back, Bounce, Elastic), eased by the same `anim::ease` curves as clip keys; `Enum.EasingDirection` is In, Out or InOut. Item names work too (`"Sine"`). `repeatCount` -1 repeats forever; `reverses` plays each repeat to the goal and back, ending where it started; `delayTime` waits once after `Play`. Its fields (`Time`, `EasingStyle`, `EasingDirection`, `RepeatCount`, `Reverses`, `DelayTime`) are read-only.
- **Tween**: `Play()` starts it from where the properties are when its delay ends (or carries on after `Pause()`); playing a tween that's playing does nothing. `Cancel()` stops it where it is, and playing it again starts over from there with its full time. `PlaybackState` is `Enum.PlaybackState` Begin, Delayed, Playing, Paused, Completed or Cancelled. `Completed` fires once when it reaches its goals, or when it's cancelled, with that state: `tween.Completed:Connect(function(state) ... end)`. `Instance` and `TweenInfo` are read-only.
- **One tween per property.** Playing a tween cancels any other playing tween that has one of the same properties of the same Instance (its `Completed` fires with Cancelled), so the newest wins. A tween on another property, or another Instance, carries on.
- **When it runs.** Each side steps its own tweens at frame step 2, before paused scripts resume (`docs/architecture/frame-loop.md`), and sets the properties like any script would, so `Changed` fires and the player needs nothing else. A tween whose Instance is destroyed stops (Cancelled, with no `Completed`). `Completed` for a finished tween fires in that step; for a cancelled one, at the next step.
- **UI.** A tween on a UI property is an ordinary property change, so `Position`, `Size`, `BackgroundColor3` and the transparencies tween like any other. Where CSS sets the same look (`background-color` replaces `BackgroundColor3` and `BackgroundTransparency`), CSS still decides; tween a UI element whose look comes from its properties.
- **Blocks** (the Tweens category, `docs/scripting/blocks.md`): tween *property* of *object* to *value* over *n* seconds *style* *direction*; slide *object* in from left, right, top or bottom; fade *object* in or out. They start the tween and carry on at once, like `tween:Play()`, so put a wait after one to let it finish. `examples/hello-tween` raises a block with typed Lua and slides a menu in and fades it out with blocks.
