# Language and API style

Luau, the definitions file, and how names are chosen.

- **Luau** via `mlua` (feature `luau`), built from source by the `luau0-src` crate, which is pinned in the workspace `Cargo.toml` (`=0.22.0`): newer Luau writes a bytecode version mlua 0.12 can't load, so raise it only together with `mlua`. Not PUC Lua, not LuaJIT. Moved from Lua 5.4 after v1.5. What scripts notice: numbers print without `.0` (`print(5.0)` shows `5`), error text is Luau's (`attempt to index nil with 'Position'`), Luau syntax works (`+=`, `continue`, `//`, string interpolation, type annotations), and Lua 5.4's `goto`, `<const>`/`<close>` and bitwise operators don't (use `bit32`). Luau's `bit32`, `buffer` and `typeof` are in the sandbox (see `sandbox.md`).
- **Native code** (roadmap L3): a script whose header (before its first line of code) has the `--!native` comment, as in Roblox, is compiled to machine code by Luau's code generator when it loads (`mlua` feature `luau-jit`; x86-64 and AArch64, elsewhere it stays interpreted). A script with an `@native` function is compiled whole too, since mlua's code generator call can't pick single functions. Everything else, the engine's own Lua included, runs in the interpreter. Native code behaves exactly like the interpreter (output, errors and line numbers, `task.wait`, the watchdog: `native_tests.rs`); it helps arithmetic, loops and table work (about 2× on top of the interpreter for math-heavy code), not calls into the engine (Instance properties, `Vector3`), which cost the same either way. With the debugger installed nothing is compiled natively, as Luau's line hooks only run in the interpreter. Numbers: [benchmarks.md](../benchmarks.md#fast-builtins-and-native-code-l3).
- Types for tooling come from a generated **luau-lsp definitions file** (Luau's `declare extern type ... with` / `declare` syntax with `---` doc comments, as in luau-lsp's own Roblox definitions; luau-lsp calls the format unstable), checked in at `definitions/axcenity.d.luau`. The generator is `crates/script/src/definitions.rs` (its tables are in `definitions/tables.rs`, in Luau type syntax, the descriptions in `definitions/docs.rs`): classes, properties and enums come from `core`, while functions, globals and value types are described there by hand. Luau's own globals (`math`, `bit32`, `typeof`, ...) are built into luau-lsp, so they aren't declared. Libraries such as `task` are a `<name>Library` type of function fields, so each function has a doc comment. Enum items are `Enum<Name>` (`EnumMaterial`; type names can't have dots). `Instance.new` is an intersection of one function per class, so `Instance.new("Part")` is a `Part`. `api_reference()` returns the same declarations as `ApiEntry`s (kind, owner, name, signature, the same description) from the same writer, for the editor's API Reference page, so a new API with its definition appears there once the editor is rebuilt. Every public API addition must update it, then run `cargo run -p axcenity-script --bin lua-definitions`. Tests fail if a property or event has no description, if a global or library function is missing from the descriptions, or if the checked-in file is out of date. No test parses it as Luau: check changes with `luau-lsp analyze --platform=standard --definitions:@axcenity=definitions/axcenity.d.luau <scripts>`.
- **In a project** (built in Phase 16, moved to luau-lsp after v1.5): the editor's **File > Set Up VS Code Autocomplete** writes `.axcenity/axcenity.d.luau` (the definitions), `.vscode/settings.json` (luau-lsp's `standard` platform rather than Roblox, no Rojo sourcemap, the definitions as `@axcenity`, `*.lua` files as Luau, and Luau globals the sandbox leaves out, such as `loadstring` and `getfenv`, disabled) and `.vscode/extensions.json` (suggests `JohnnyMorganz.luau-lsp`, and marks the Lua Language Server's `sumneko.lua` unwanted since it would also take `.lua` files and flag Luau syntax). The two `.vscode` files may hold the creator's settings, so only missing keys and list items are added; nothing the creator set is changed, and a file with comments (not plain JSON) is left alone with a message. Set Up also removes what the old Lua Language Server set-up wrote (`.axcenity/axcenity.lua`, and `.luarc.json` if unchanged), and replaces its unchanged `extensions.json`. Opening a project rewrites `.axcenity/axcenity.d.luau` when it's out of date; a project with only the old set-up gets a message to run Set Up again (`crates/editor/src/autocomplete.rs`). Scripts are checked in Luau's default nonstrict mode: with `luau-lsp analyze` every example has no warnings, and `task.wiat()` and `io.write` are flagged; `part.Size = 5` and `part.Material = "Neeon"` are only flagged in scripts that start with `--!strict` (strict mode on every example flags untyped code too often for beginners).
- **In this repo**: the root `.vscode/settings.json` and `extensions.json` set up luau-lsp the same way for `examples/`, with `definitions/axcenity.d.luau` as `@axcenity` (and `Lua.diagnostics.globals` for anyone still on the Lua Language Server). The `definitions/*.d.luau` files are declarations (`declare extern type … with`), not scripts: the settings open them as plain text and give them to `luau-lsp.ignoreGlobs`, so neither luau-lsp's workspace check nor selene reports their syntax as errors (luau-lsp still loads `axcenity.d.luau` through `definitionFiles`). selene reads `selene.toml`, whose `axcenity.yml` standard library is Luau plus the engine's globals (`crates/script/src/api.rs` and `task`); a new global needs adding there too. `selene examples` reports nothing.
- **Children by name** are an `[string]: any` indexer on every Instance type (Luau doesn't inherit indexers, so each class repeats it). A union of every class would flag `workspace.Pad.Color = ...`, since Luau only allows a property every member of a union has; so a child's properties aren't checked or autocompleted (luau-lsp's Roblox mode gets them from a Rojo sourcemap). `require` takes an `Instance`.

- Reuse familiar names and patterns: `Instance.new("Part")`, `part.Parent = workspace`, `part.Touched:Connect(fn)`, `Vector3.new`, `task.wait` / `task.spawn` / `task.delay`.
- Classes are PascalCase, properties are PascalCase, methods are called with `:`, events are `RBXScriptSignal`-like objects with `:Connect` (but don't name anything with `RBX`).
- Clean up Roblox quirks when it helps beginners. Don't chase full compatibility.
- Never use Roblox's name, logos or assets.
