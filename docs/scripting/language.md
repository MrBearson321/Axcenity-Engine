# Language and API style

Luau, the definitions file, and how names are chosen.

- **Luau** via `mlua` (feature `luau`), built from source by the `luau0-src` crate, which is pinned in the workspace `Cargo.toml` (`=0.22.0`): newer Luau writes a bytecode version mlua 0.12 can't load, so raise it only together with `mlua`. Not PUC Lua, not LuaJIT. Moved from Lua 5.4 after v1.5. What scripts notice: numbers print without `.0` (`print(5.0)` shows `5`), error text is Luau's (`attempt to index nil with 'Position'`), Luau syntax works (`+=`, `continue`, `//`, string interpolation, type annotations), and Lua 5.4's `goto`, `<const>`/`<close>` and bitwise operators don't (use `bit32`). Luau's `bit32`, `buffer` and `typeof` are in the sandbox (see `sandbox.md`).
- Types for tooling come from a generated **luau-lsp definitions file** (Luau's `declare extern type ... with` / `declare` syntax with `---` doc comments, as in luau-lsp's own Roblox definitions; luau-lsp calls the format unstable), checked in at `definitions/axcenity.d.luau`. The generator is `crates/script/src/definitions.rs` (its tables are in `definitions/tables.rs`, in Luau type syntax, the descriptions in `definitions/docs.rs`): classes, properties and enums come from `core`, while functions, globals and value types are described there by hand. Luau's own globals (`math`, `bit32`, `typeof`, ...) are built into luau-lsp, so they aren't declared. Libraries such as `task` are a `<name>Library` type of function fields, so each function has a doc comment. Enum items are `Enum<Name>` (`EnumMaterial`; type names can't have dots). `Instance.new` is an intersection of one function per class, so `Instance.new("Part")` is a `Part`. Every public API addition must update it, then run `cargo run -p axcenity-script --bin lua-definitions`. Tests fail (so CI fails) if a property or event has no description, if a global or library function is missing from the descriptions, or if the checked-in file is out of date. No test parses it as Luau: check changes with `luau-lsp analyze --platform=standard --definitions:@axcenity=definitions/axcenity.d.luau <scripts>`.
- **In a project** (built in Phase 16, moved to luau-lsp after v1.5): the editor's **File > Set Up VS Code Autocomplete** writes `.axcenity/axcenity.d.luau` (the definitions), `.vscode/settings.json` (luau-lsp's `standard` platform rather than Roblox, no Rojo sourcemap, the definitions as `@axcenity`, `*.lua` files as Luau, and Luau globals the sandbox leaves out, such as `loadstring` and `getfenv`, disabled) and `.vscode/extensions.json` (suggests `JohnnyMorganz.luau-lsp`, and marks the Lua Language Server's `sumneko.lua` unwanted since it would also take `.lua` files and flag Luau syntax). The two `.vscode` files may hold the creator's settings, so only missing keys and list items are added; nothing the creator set is changed, and a file with comments (not plain JSON) is left alone with a message. Set Up also removes what the old Lua Language Server set-up wrote (`.axcenity/axcenity.lua`, and `.luarc.json` if unchanged), and replaces its unchanged `extensions.json`. Opening a project rewrites `.axcenity/axcenity.d.luau` when it's out of date; a project with only the old set-up gets a message to run Set Up again (`crates/editor/src/autocomplete.rs`). Scripts are checked in Luau's default nonstrict mode: with `luau-lsp analyze` every example has no warnings, and `task.wiat()` and `io.write` are flagged; `part.Size = 5` and `part.Material = "Neeon"` are only flagged in scripts that start with `--!strict` (strict mode on every example flags untyped code too often for beginners).
- **Children by name** are an `[string]: any` indexer on every Instance type (Luau doesn't inherit indexers, so each class repeats it). A union of every class would flag `workspace.Pad.Color = ...`, since Luau only allows a property every member of a union has; so a child's properties aren't checked or autocompleted (luau-lsp's Roblox mode gets them from a Rojo sourcemap). `require` takes an `Instance`.

- Reuse familiar names and patterns: `Instance.new("Part")`, `part.Parent = workspace`, `part.Touched:Connect(fn)`, `Vector3.new`, `task.wait` / `task.spawn` / `task.delay`.
- Classes are PascalCase, properties are PascalCase, methods are called with `:`, events are `RBXScriptSignal`-like objects with `:Connect` (but don't name anything with `RBX`).
- Clean up Roblox quirks when it helps beginners. Don't chase full compatibility.
- Never use Roblox's name, logos or assets.
