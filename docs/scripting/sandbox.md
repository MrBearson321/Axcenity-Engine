# Sandbox

What a script is allowed to call.

Each script gets its own restricted environment. Remove or replace `io`, `os` (keep only safe time functions), `debug`, `load`, `loadfile`, `dofile`, `require` (replaced by an engine module loader), and `collectgarbage` beyond safe options. Treat all script code as untrusted.

- Since Phase 4 the environment is built from an **allowlist** (`crates/script/src/sandbox.rs`): the safe base functions, per-script copies of `bit32`, `buffer`, `coroutine`, `math`, `string` (without `dump`), `table` and `utf8`, and `os.clock/date/difftime/time`. `bit32` and `buffer` only work on numbers and their own byte buffers, with every read and write bounds-checked. `typeof` is the engine's (`types::typeof_name`): every Instance is `"Instance"`, enum items `"EnumItem"`, `Enum.Material` is `"Enum"` and `Enum` `"Enums"`, as in Roblox; other engine values are named as scripts know them (`"Vector3"`, `"Vector2"`, `"Color3"`, `"UDim2"`, `"CFrame"`, `"Random"`, `"Signal"`, `"Connection"`, `"RunService"`, `"Camera"`, ...), and anything else is Luau's own (`"number"`, `"buffer"`, ...). `_G` is the script's own environment, and only source text loads (mode `t`), never bytecode: Luau doesn't verify bytecode, so loading it could corrupt memory. Scripts, ModuleScripts, plugins and test specs go through `chunks::load`, which compiles each source once per thread and loads that bytecode for later copies (clones, both sides, the next Play run); the only bytecode it ever loads is its own compiler's output from source text, and a source that doesn't compile takes the text path, so its error reads as before. mlua adds `loadstring` and a file-system `require` to Luau's real globals; neither is on the allowlist.

### Fast builtins (roadmap L3)

- Each script's library copies (`bit32`, `buffer`, `coroutine`, `math`, `os`, `string`, `table`, `utf8`) are **read-only**, as Luau's and Roblox's are: `string.upper = f` or `math.extra = 1` errors with `attempt to modify a readonly table`. A script may still replace a whole library or a global with its own (`math = myMath`, `typeof = f`); `_G` and plain globals are the script's own.
- Script environments are **`safeenv`**, which lets Luau call its builtins (`math.sqrt`, `string.sub`, `type`, `select`, ...) directly instead of looking the name up and calling through the C API: about 3× faster for numeric code, and what lets native code (`--!native`, [language.md](language.md)) inline them. Luau assumes the environment's builtins are the real ones, which holds because the libraries are read-only and `sandbox::compiler` (what every script, module, console command, plugin and test spec compiles with) turns off the builtins the sandbox replaces (`setmetatable`, `typeof`) or leaves out (`unpack`, the `vector` and `integer` libraries). A global the script assigns by name isn't treated as a builtin (Luau's compiler sees the assignment). The one way around it is assigning a builtin library through `_G` (`_G.math = t`): then `math.sqrt(x)` still runs Luau's own. `sandbox_tests.rs` checks each of these.

### Hardened in Phase 15

- **String metatable**: every string shares one metatable, whose `__index` was the real `string` table. It's now a hidden copy without `dump`, and `getmetatable("")` returns `"The metatable is locked"` (as in Roblox).
- **`collectgarbage`** only takes `"count"` (memory in use, in KB). Anything else errors: the engine runs the collector for everyone.
- **`setmetatable`** refuses a metatable with `__gc`. Luau never runs `__gc` on tables, so the error says so instead of ignoring it silently.
- **`coroutine.resume/wrap/status/close`** are engine versions (`watchdog.rs`): errors come back as plain `path:line:` strings like `pcall`'s, `wrap` doesn't add a second location, and a coroutine the watchdog stopped looks dead and can't be resumed or closed.
- Engine objects' metatables (Instances, Vector3, ...) are locked by mlua: `getmetatable(workspace)` is `false`; `sandbox_tests.rs` checks this and every other escape attempt (missing `io`/`debug`/`load`/`package`/..., bytecode, `os` beyond the clock, cross-script and cross-side globals, `require` of paths and libraries).
- **Not covered** (out of scope for v1, noted for later): memory limits (a script can allocate until the process runs out), and C functions that run long by themselves (a huge `string.rep`, a pathological pattern in `string.find`): the watchdog only runs at Luau calls and loop iterations.
