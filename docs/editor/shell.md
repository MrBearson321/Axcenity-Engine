# Editor shell

The window, ribbon, panels, camera, and visual design. The other editor pages are listed in `docs/architecture.md`.

- Built on **eframe 0.32** (egui's app shell) with its wgpu backend. eframe owns the window, event loop and GPU device; it must stay on the same wgpu major as `render` (0.32 ↔ wgpu 25, winit 0.30), so upgrade them together.
- Layout like Roblox Studio: menu bar on top, **Explorer** down the right side, **Output** along the bottom under the viewport, viewport in the middle.
- **Dockable panels** (added on request after Phase 37; `layout.rs`, `egui_dock` 0.17): Scene (the viewport and script tabs), Explorer, Properties, Output and Assets are each a tab in a docking area, like Unity. Drag a tab onto another panel's tab bar to join it, onto a side of a panel to split it, or anywhere else to float it in its own window. The Scene can be moved but not closed or floated, so the main window is never empty. The others close with their ×, and View > Panels (or the View ribbon tab's Panels group) shows or hides them; Reset Layout puts everything back. A closed panel opens again next to the panel it starts beside. The layout is saved between runs (eframe storage, JSON); a damaged one gives the starting layout.
- **Ribbon tabs** (`ribbon_tabs.rs`): **Home** is Play and Stop, Select / Move / Resize / Rotate, snapping, and the four part shapes. **Model** is the build tools (Paint, Material, Anchor, Collision, Lighting, Emission, Angular), sounds, particles, lights, and Import. **Terrain**, **UI**, **Script**, **Test**, and **View** are their own tabs. **Custom tabs**: + after the tabs (or View > New Ribbon Tab…) makes a tab from any groups, in any order; right-click one to edit or delete it. Custom tabs and the tab showing are saved between runs.
- **Viewport**: `render::TextureRenderer` draws into a texture sized in physical pixels, registered with egui as a native texture and re-pointed after each resize. Only redraws when egui does (input or a requested repaint), so an idle editor uses no GPU.
- **Camera** (Studio-style): right-drag looks (cursor hidden; `Locked` on macOS, `Confined` elsewhere), WASD/E/Q fly while the mouse is over the viewport, Shift slows, wheel zooms toward the focus point, middle-drag pans, Alt+left-drag orbits the focus point. Keys are read by physical position, like the player.
- **Fly speed** (added to Phase 8 on request): Shift+wheel, or the wheel while right-dragging (like Unity and Godot), changes the WASD speed by 20% per notch, from 1 to 500 studs/s (default 20). A pop-up in the middle of the viewport shows the new speed for a second, then fades. The speed survives opening another project but isn't saved between sessions. The player keeps a fixed 20 studs/s.
- **Explorer**: shows the real root (`Game`, class `DataModel`; `game` in scripts) and every Instance under it. `game` and `Workspace` start open, everything else closed. The class is shown next to names that differ from it.
- **Output**: editor messages (project opened, with object and script counts) and load errors, one line each with the full cause chain (file and line for bad JSON). A failed open keeps the current project. During Play, script output and errors join it.
- **Opening projects**: `axcenity-editor <folder>` or File > Open Project… (`rfd` native folder dialog; the desktop portal on Linux). With no folder, the editor starts empty with a hint in Output.
- Scripts and physics only run during Play (see `docs/architecture/play-mode.md`).

## Look and feel

- **Design system** (`theme.rs`, `widgets.rs`): every colour comes from semantic tokens in `theme::Palette` (app background, panel, surface, elevated, inset, control states, borders, five text levels, accent, success, warning, error), read with `theme::palette(ctx)`; `theme::apply` fills egui's `Visuals` for both themes from the same tokens, so stock egui widgets match. Only scene content keeps its own colours (gizmo axes, selection outlines, block categories, syntax highlighting, Instance class tints). Shared controls live in `widgets.rs`: buttons by role (primary/secondary/ghost/danger), icon buttons, a segmented control, nav items, section labels, a search field, row hover/selection painting, ellipsised text, the section chevron and the vector logo mark.
- **Themes and accent**: neutral, near-monochrome dark (default) and light themes, plus System. One accent (Blue, Violet, Green or Orange) marks selection, focus rings, the active tab and primary buttons; the rest stays neutral. Text, accent and status colours meet WCAG AA in both themes (checked by a test); the "muted" token is for disabled and decorative text only.
- **Settings** (`app/settings.rs`; File > Settings…, View > Appearance…, the gear in the header or on the start screen, Ctrl/Cmd+,): Appearance (theme with live previews, accent, interface scale 90–150%), Text & density (Comfortable or Compact, code/Output font size), Editor layout (panels, Reset Layout, light cones, new ribbon tab), Shortcuts (reference) and Accessibility (Reduce motion). Changes apply at once and are saved as JSON under the `appearance` key; an older save's `theme` key is still read.
- **Density**: Compact tightens spacing and row heights and makes the ribbon icon-only with no captions (names move to tooltips); Comfortable shows icon-over-label buttons with captions.
- **Motion**: micro-interactions take about 160 ms (`theme::MOTION_SECONDS`, egui's `animation_time`): eased hover fills, popups, menus, tooltips and dialogs fading in, sections opening with a turning chevron, a sliding accent underline on ribbon and script tabs, toasts, and a short crossfade when the theme changes. Nothing waits on an animation and the viewport camera is never animated. Reduce motion makes all of it instant and turns off smooth scrolling. Docking changes are not animated (they would animate layout sizes).
- **Fonts**: Inter (Regular, Medium, SemiBold) for the UI, JetBrains Mono for code and Output, Phosphor for icons, egui's own fonts as fallback. The type scale is in `theme::type_scale`; hierarchy comes mostly from weight and colour.
- **Icons**: Phosphor, as an icon font (`egui-phosphor` 0.10), so an icon is a letter inside any text. Every Instance class has an icon and a softened colour (`theme::class_icon`, `class_color`) in the Explorer and tabs; ribbon icons are neutral except Play (success) and Stop (error).
- **Shell**: a compact header (logo mark, menus, project name with an unsaved dot, the Playing badge, Settings), ribbon tabs with an accent underline, the ribbon (`ribbon.rs`) under them, then the dock: quiet tab bars on the app background, the active tab joined to its panel, 1-point dividers that turn accent when hovered or dragged, and panels at least 140 points wide or tall. The Explorer highlights whole rows with indent guides; Properties shows what's selected, then collapsible sections with aligned name columns; Output has severity filters with counts; Assets has category chips and a search field. Saving and importing confirm with a toast (`toast.rs`); the full message is always in Output.
- **Start screen** (redesigned again): with no project open, the window shows a sidebar (the mark and name, Projects, Learn, Settings, the version) and the page. Projects has a header with New Project and Open Project, template cards (Baseplate, Empty, Starter scene; see `project::Template`), and up to 100 tracked projects (saved between runs) as cards or a list, searchable and sorted by last opened or name. Cards fill the width in equal columns; each has the thumbnail (or a neutral placeholder with the initials), the name and when its world was last saved ("Edited 3 days ago"). Clicking opens it; its ⋯ menu (shown on hover) or a right-click has Open, Settings (name, description, splash), Version History, Show in File Manager, Remove from List (files kept) and Delete (permanent, after confirmation). New Project asks for a template, a name and a folder. Learn has short cards on each part of the editor. The toolbar, Explorer, Properties, tabs and Output are hidden until a project opens, so open errors show on the start screen instead. File > Close Project returns to it.
- **Saved between runs** (eframe's `persistence` feature, in the OS's app data folder): the appearance settings, the recent projects, the window's size and position, the panel layout, the custom ribbon tabs and View > Light Cones. Tests never touch it (only `eframe::run_native` loads and saves it).
- **Logo**: the hexagon mark drawn as lines in the theme's text colour in the header and start screen; the full-colour wordmark in Help > About.
