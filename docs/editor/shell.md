# Editor shell

The window, ribbon, panels, camera, and visual design. The other editor pages are listed in `docs/architecture.md`.

- Built on **eframe 0.32** (egui's app shell) with its wgpu backend. eframe owns the window, event loop and GPU device; it must stay on the same wgpu major as `render` (0.32 ↔ wgpu 25, winit 0.30), so upgrade them together.
- Layout like Roblox Studio: menu bar on top, **Explorer** down the right side, the **Console** along the bottom under the viewport, viewport in the middle.
- **Dockable panels** (added on request after Phase 37; `layout.rs`, `egui_dock` 0.17): Scene View (the viewport), Explorer, Properties, Console, Assets, Animation, UI Designer (see `docs/ui.md`), Terrain, Profiler and Mixer (see `docs/architecture/play-mode.md`), Asset Check (see `docs/editor/assets.md`) and each open script (see `docs/editor/scripts.md`) are each a tab in a docking area, like Unity. Drag a tab onto another panel's tab bar to join it, onto a side of a panel to split it, or anywhere else to float it in its own window. The Scene View can be moved but not closed or floated, so the main window is never empty. The others close with their ×, and View > Panels (or the View ribbon tab's Panels group) shows or hides them; Reset Layout puts everything back. A closed panel opens again next to the panel it starts beside. The layout is saved between runs (eframe storage, JSON); a damaged one gives the starting layout.
- **Ribbon tabs** (`ribbon_tabs.rs`): **Home** is Play and Stop, Select / Move / Resize / Rotate, snapping, and the four part shapes. **Model** is the build tools (Paint, Material, Anchor, Collision, Lighting, Emission, Angular), Phase 50's **Solid Modeling** (Union, Negate, Intersect, Separate; `app/solid.rs`, `docs/architecture/solid-modeling.md`) and, Phase 38, **Collision Groups** (`app/collision_groups.rs`): a window that adds groups by name, removes them with × (not Default; their parts then collide as Default), and has a lower-triangle matrix of checkboxes, ticked where two groups collide; each change writes `collision-groups.json` at once (not undoable, like the Input window) and is disabled during Play, **Constraints** (Phase 35: **Weld** welds the selected parts, and the parts in selected Models, to the largest of them by volume, with a `WeldConstraint` (Part0 the largest, Part1 the other) inside each other part, as one undo step "Weld N parts", off with fewer than two parts; **Attachment**; and, Phase 36, **Constraint** (`app/constraint_tool.rs`), whose menu picks a joint: then the left button picks part surfaces instead of selecting (marked with a ring, and a line from the first to the mouse), a click on one part then on another makes an Attachment at each point, both with their X axis out of the first surface, and the joint in the first part, as one undo step "Insert <class>", a spring's FreeLength and a rope's or rod's Length set to the distance; the tool stays on until Stop in its menu, Esc or Play; Phase 37: the menu's second group is the movers: LinearVelocity, AngularVelocity, VectorForce and Torque take one click, making an Attachment there (X out of the surface) and the mover in that part, and AlignPosition and AlignOrientation take a second click on the part they follow, making its Attachment1 too (TwoAttachment, their default Mode), each as one undo step "Insert <class>"), sounds, particles, lights, and Import. **Terrain**, **UI**, **Script**, **Test** (Play/Stop and Check Assets), and **View** (Panels, then Overlays: colliders, raycasts, bounds, emitters, nav mesh, agent paths, constraints, culling; **Constraints** (Phase 35, `constraints.rs`) draws each WeldConstraint as a line between its parts' middles, light blue or grey when disabled, and every Attachment as a ring with its X (red) and Y (green) axes; a selected Attachment shows that way with the overlay off too; Phase 36: each joint is an orange line between its attachments (a zigzag for a spring), with the axis through Attachment0 for a hinge, prismatic or cylindrical constraint and a yellow arc between a hinge's limits, grey when disabled, and a selected joint shows with the overlay off; Phase 37: each mover is green from Attachment0: an arrow along a LinearVelocity's VectorVelocity or a VectorForce's Force, its axis and a circling arrow for an AngularVelocity or Torque (all in their RelativeTo axes), a line to an AlignPosition's target with a cross there, and a line to an AlignOrientation's Attachment1 with arrows along the X and Y axes it turns to, grey when disabled) are their own tabs. The tab row is centred, on the app background like the header; the ribbon under it is a shade lighter (the panel colour) with a hairline above and below, and the active tab is filled with that shade and outlined so it joins the ribbon, and each built-in tab has an icon before its name (house, cube, mountains, layout, code, flask, eye); custom tabs have a star. **Custom tabs**: + after the tabs (or View > New Ribbon Tab…) makes a tab from any groups, in any order; right-click one to edit or delete it. Custom tabs and the tab showing are saved between runs.
- **Viewport**: `render::TextureRenderer` draws into a texture sized in physical pixels, registered with egui as a native texture and re-pointed after each resize. Only redraws when egui does (input or a requested repaint), so an idle editor uses no GPU.
- **Camera** (Studio-style): right-drag looks (cursor hidden; `Locked` on macOS, `Confined` elsewhere), WASD/E/Q fly while the mouse is over the viewport, Shift slows, wheel zooms toward the focus point, middle-drag pans, Alt+left-drag orbits the focus point. Keys are read by physical position, like the player.
- **Fly speed** (added to Phase 8 on request): Shift+wheel, or the wheel while right-dragging (like Unity and Godot), changes the WASD speed by 20% per notch, from 1 to 500 studs/s (default 20). A pop-up in the middle of the viewport shows the new speed for a second, then fades. The speed survives opening another project but isn't saved between sessions. The player keeps a fixed 20 studs/s.
- **Explorer**: shows the real root (`Game`, class `DataModel`; `game` in scripts) and every Instance under it. `game` and `Workspace` start open, everything else closed. The class is shown next to names that differ from it.
- **Console** (v3 Phase 2; `output.rs` for the log, `console.rs` for the command line, `app/commands.rs` for what commands do; it replaced the Output panel, and layouts saved with `Output` still load): the log is editor messages (project opened, with object and script counts) and load errors, one line each with the full cause chain (file and line for bad JSON), filtered by severity. A failed open keeps the current project. During Play, script output and errors join it. Under the log is a command line; each command is echoed (a `>` line) before what it printed.
  - **Built-ins**: `help`, `clear`, `select <name|path>` (a dotted path from `game`, `workspace` or a service, such as `Workspace.Model.Door`, or a name searched everywhere), `find <name>` (lists and selects every Instance whose name contains it, ignoring case), `open <script>` (by its Instance's name or its path), `play`, `stop`, `save` and `check` (scans the project; see `docs/editor/assets.md`). A built-in is the first word with nothing after it that makes it Lua, so `clear = 5` and `select(2, ...)` are Lua.
  - **Lua**: anything else, with the same sandbox as scripts (`script::run_edit_command`, `ScriptRuntime::run_command`). A command is first tried as an expression, so `workspace.Baseplate.Size` prints its value. Outside Play it runs on the server side in a throwaway interpreter against a copy of the edit world; if it changed anything, the copy becomes the world and the old world is kept as one undo step, "Console: <command>" (`History::record_world`). During Play it runs on the game's server side as a coroutine (so `task.wait` works), commands share globals, and changes are lost at Stop like any Play change. Errors read `console:1: ...`. A line that isn't valid Lua and starts with a plain word (`teleport Pad`) is reported as an unknown command, with the Lua error after it; so is a lone word that isn't a global, outside Play.
  - **Keys**: Enter runs, Shift+Enter starts a new line, Up and Down walk the history while the input is one line (the last 200 commands, saved between runs), and Tab completes built-ins (as the first word), global names, and after a dot the children (with names Lua can write that way) and properties of the Instance the path names. With several matches Tab fills in what they share and lists them above the input.
- **File menu** (`app/chrome/menus.rs`, unified Phase 5): grouped under quiet headings. **Project**: New Project… (asks to save, closes the project and opens the start screen's New Project dialog), Open Project…, Save, Version History…, Close Project. **Import**: Import… (see `docs/editor/import.md`). **Publish**: **Build Game ▸** (Export Game before Phase 5): For this OS, For Windows, For macOS, For Linux, and Show splash in built games (see `docs/project/export.md`). Then Open Stylesheet…, New Stylesheet, Check Assets, Set Up VS Code Autocomplete, Settings… and Quit.
- **Opening projects**: `axcenity-editor <folder>` or File > Open Project… (`rfd` native folder dialog; the desktop portal on Linux). With no folder, the editor starts empty with a hint in Output.
- **Loading screen** (`loading.rs`): opening from the start screen, File > Open Project or the command line reads the project on a background thread, so the window never freezes. The thread reads the project's files (`project::load_with_progress` reports the manifest, any upgrade, `world.json`, each terrain and each script), then loads every model and texture the Workspace draws (`scene::asset_files`), then builds each Terrain's chunks for the starting camera (`TerrainCache::prepare`). Before this, the first frame did all of that at once on an empty window. Under the header, the screen shows the project's name, what's being read with "n of m", a real progress bar (files 0–35%, models and textures 35–85%, terrains 85–100%) with its percentage, the last five files finished, the seconds taken and Cancel (the current project, or the start screen, stays). The menus are disabled while it loads. Once read, the project opens and the screen stays two more frames ("Preparing the scene") while the scene goes to the GPU. A failed open goes to Output and to the start screen's notice. Restoring a version, and tests, still open synchronously (`EditorApp::open`).
- Scripts and physics only run during Play (see `docs/architecture/play-mode.md`).

## Look and feel

- **Design system** (`theme.rs`, `widgets.rs`): every colour comes from semantic tokens in `theme::Palette` (app background, panel, surface, elevated, inset, control states, borders, five text levels, accent, success, warning, error), read with `theme::palette(ctx)`; `theme::apply` fills egui's `Visuals` for both themes from the same tokens, so stock egui widgets match. Only scene content keeps its own colours (gizmo axes, selection outlines, block categories, syntax highlighting, Instance class tints). Shared controls live in `widgets.rs`: buttons by role (primary/secondary/ghost/danger), icon buttons, a segmented control, nav items, section labels, a search field, row hover/selection painting, ellipsised text, the section chevron and the logo mark image.
- **Themes and accent**: neutral, near-monochrome dark (default) and light themes, plus System. One accent (Blue, Violet, Pink, Red, Orange, Yellow, Green or Teal) marks selection, focus rings, the active tab and primary buttons; the rest stays neutral. Text, accent and status colours meet WCAG AA in both themes (checked by a test); the "muted" token is for disabled and decorative text only.
- **Settings** (`app/settings.rs`; File > Settings…, View > Appearance…, the gear in the header or on the start screen, Ctrl/Cmd+,): Appearance (theme with live previews, accent, interface scale 90–150%), Text & density (Comfortable or Compact, code/Console font size), Editor layout (panels, Reset Layout, light cones, collider/raycast/bounds/emitter/nav mesh/agent path/culling overlays, new ribbon tab), Graphics (this computer's quality preset and shadow quality, shadow distance, post-processing, render scale, texture quality and anti-aliasing overrides, with what's in use and why anything was lowered; applied to the viewport at once and saved as JSON under the `graphics` key; see `docs/rendering/shadows.md`), Shortcuts (reference) and Accessibility (Reduce motion). Changes apply at once and are saved as JSON under the `appearance` key; an older save's `theme` key is still read.
- **Density**: Compact tightens spacing and row heights and makes the ribbon icon-only with no captions (names move to tooltips); Comfortable shows icon-over-label buttons with captions.
- **Motion**: micro-interactions take about 160 ms (`theme::MOTION_SECONDS`, egui's `animation_time`): eased hover fills, popups, menus, tooltips and dialogs fading in, sections opening with a turning chevron, a sliding accent underline on ribbon and script tabs, toasts, and a short crossfade when the theme changes. Nothing waits on an animation and the viewport camera is never animated. Reduce motion makes all of it instant and turns off smooth scrolling. Docking changes are not animated (they would animate layout sizes). On launch, a black splash (`splash.rs`) covers the window for about 3.3s, laid out like Unity's loading window: a small white wordmark (16% of the window's width, 150–230 points), a status line under it naming each startup step (fonts, theme and settings, layout, recent projects, opening the project if one was given, renderer, then "Ready") with a percentage at the right, a thin white bar, and the version in the bottom-left corner. The bar is timed, not real progress: each step gets an equal slice and the bar moves quickly through the start of each slice, then waits. The backdrop is solid from the first frame; only the logo fades in. Its clock counts drawn frames, at most 50 ms each, so a slow start can't use it up unseen. Click or a key skips to the fade-out. Reduce motion shows a static wordmark at "Ready" for about a quarter of a second instead.
- **Fonts**: Inter (Regular, Medium, SemiBold) for the UI, JetBrains Mono for code and the Console, Phosphor for icons, egui's own fonts as fallback. The type scale is in `theme::type_scale`; hierarchy comes mostly from weight and colour.
- **Icons**: Phosphor, as an icon font (`egui-phosphor` 0.10), so an icon is a letter inside any text. Every Instance class has an icon and a softened colour (`theme::class_icon`, `class_color`) in the Explorer and tabs; ribbon icons are neutral except Play (success) and Stop (error).
- **Title bar** (`window_frame.rs`, like VS Code): there is one bar. The OS title bar is off and the header is the window's title bar, 34 points tall: logo mark and menus at the left, the window title in the middle (`Name* - Axcenity Editor`, kept clear of the menus), then the Playing badge, Settings and the window buttons. Its empty space drags the window; a double-click maximizes or restores. On Windows and Linux the window has no OS frame, so the editor draws minimize, maximize/restore and close (close turns red on hover and asks about unsaved changes, like File > Quit), 5-point resize grips along the edges and corners, and a 1-point border; grips and border are off while maximized or fullscreen. On macOS the frame stays, the content runs under a transparent title bar, and the header leaves room at its left for the traffic lights. The OS still gets the title, for the taskbar and window switcher.
- **Shell**: the header (above), ribbon tabs with an accent underline, the ribbon (`ribbon.rs`) under them, then the dock: quiet tab bars on the app background, the active tab joined to its panel, 1-point dividers that turn accent when hovered or dragged, and panels at least 140 points wide or tall. The Explorer highlights whole rows with indent guides; Properties shows what's selected, then collapsible sections with aligned name columns; Output has severity filters with counts; Assets has category chips and a search field. Saving and importing confirm with a toast (`toast.rs`); the full message is always in Output.
- **Panels at any shape** (v3 Phase 3; `responsive.rs`): every panel keeps its contents inside it when docked tall and narrow. Three shared layouts do it: `toolbar` (controls that wrap onto more rows), `form` (names and controls in a grid whose name column is 38% of the width, 64–150 points; below 280 points each control goes under its name and sliders fill the width) and `split` (two panes side by side, or stacked below a width). Properties, the Style section, the Terrain Studio and the Animation inspectors use `form`; vectors wrap their axes and a UDim2 puts Y under X below 270 points. The Explorer only scrolls vertically: names end in "…" and a row drops its class label when the name would get under 72 points. Assets switches to a list (see `docs/editor/assets.md`). The Animation tab's clip and state machine views stack below 560 points, and its outline folds into the breadcrumb below 720 (see `docs/editor/import.md`); a state machine's live preview goes above its controls below 420 points, and a toolbar starts a new row before a combo box that wouldn't fit (`responsive::room_for`). A second drawing test (`the_animation_tab_says_where_you_are_and_fits_any_shape`) draws the tab with a clip and with a state machine open at 600×400, 260×900 and 1100×600. A drawing test (`every_panel_fits_a_narrow_column_and_a_short_strip`) draws each closable panel at 260×900 and 900×260 and fails if anything is drawn outside it; with `AXCENITY_SNAPSHOTS` it saves `panel-<name>-tall.png` and `-wide.png`.
- **Start screen** (redesigned again): with no project open, the window shows a sidebar (the mark and name, Projects, Global Assets, Learn, API Reference, Settings, the version) and the page. Global Assets (`start/global.rs`) lists the global assets library as cards (an imported model's files are one card), with a search, Show Folder, and Remove from global assets (hover the card, or right-click; after confirmation): see `docs/editor/assets.md`. Projects has a header with New Project and Open Project, template cards (Baseplate, Empty, Starter scene; see `project::Template`), and up to 100 tracked projects (saved between runs) as cards or a list, searchable and sorted by last opened or name. Cards fill the width in equal columns; each has the thumbnail (or a neutral placeholder with the initials), the name and when its world was last saved ("Edited 3 days ago"). Clicking opens it; its ⋯ menu (shown on hover) or a right-click has Open, Settings (name, description, splash), Version History, Show in File Manager, Remove from List (files kept) and Delete (permanent, after confirmation). New Project asks for a template, a name and a folder. Learn (v2 Phase 11; `start/learn.rs`, words in `learn/tutorials.rs`, pictures in `learn/pictures.rs`) lists tutorials as cards ("Start here": place and move a part, run a script, press Play and Stop, open a sample; then more guides: blocks, tasks, UI, lights, sound, RemoteEvents) and, under them, short notes on each part of the editor. A tutorial is one task in a sample from `examples/`: numbered steps with their own pictures (drawn with egui from theme tokens, so they follow the theme, accent and scale; scene content keeps its own colours), Open sample (the folder is looked for in the working folder, then above the editor's executable; it opens in place), buttons that open the API Reference entries it uses, and Back/Next. Opening a sample from Learn also opens Help > Learn: a window over the project with the same Tutorials and API Reference pages and state, so the tutorial stays in view. From there, Open sample asks "Save changes?" first (`Discard::OpenSample`), is disabled during Play, and says when the sample is already the open project. Tests check each tutorial's sample exists, has the named manifest, opens and plays in the editor with no errors, and that each look-up opens its exact entry. API Reference (`start/reference.rs`) lists every class, type, enum, library and global from `script::api_reference`; typing in its search box ranks entries by name (exact, then starts with, then contains; `Part.Size` and `Instance:FindFirstChild` match by owner too, top-level entries first, at most 100 shown), Enter opens the first, and clicking a row opens the entry: its kind, owner link, signature, description (with `code` in the code font) and, for a class, type, enum or library, its properties, events, functions or items. Back to results returns to the list. The toolbar, Explorer, Properties, tabs and Output are hidden until a project opens, so open errors show on the start screen instead. File > Close Project returns to it.
- **Saved between runs** (eframe's `persistence` feature, in the OS's app data folder): the appearance settings, the recent projects, the window's size and position, the panel layout, the custom ribbon tabs, View > Light Cones, the View overlay toggles (colliders, raycasts, bounds, emitters, nav mesh, agent paths; not culling, nor View > View Mode, `docs/rendering/performance.md`) and the Console history. The window's size and position are not: the editor always opens at 1280×800, centered (`persist_window: false`). eframe still reads its old `window` entry at startup, so `save` blanks it. Tests never touch it (only `eframe::run_native` loads and saves it).
- **Logo**: white-on-transparent images tinted with the theme's strong text colour: the A (`mark-white-small.png`) in the header and start screen, the wordmark (`wordmark-white.png`) in Help > About and the splash.
