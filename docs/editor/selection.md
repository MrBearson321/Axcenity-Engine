# Selection and properties

How selection, picking, and the Properties panel work.

- **Selection** (`EditorApp::selection`, with `selected` the last one). A plain click replaces it. Ctrl (Cmd on macOS) toggles an Instance in or out, in the Explorer and in the viewport. Shift in the Explorer selects every visible row from the last one to the clicked one; Shift in the viewport adds the clicked part or UI element. A right-click on something already selected keeps the rest. Handles use the last one clicked; Properties shows them all (below). Once the Explorer is clicked (or tabbed into, after its Filter), Up and Down move the selection, Shift+Up and Down extend it from where the keys started, Left closes a branch or goes to the parent, Right opens one or goes to its first child, Home and End go to the first and last rows, and Enter or F2 renames; the selected row gets an accent focus ring and the list scrolls only as far as it takes to show it. Those keys are taken before the viewport or the UI Designer sees them, and only until something else is clicked; the tool keys, Delete, Ctrl+D and undo still work (`Explorer::has_keys`, `take_keys`; tests in `explorer/key_tests.rs` and `app/explorer_keys_tests.rs`). Delete and Duplicate apply to every selected Instance that isn't inside another. Clicking empty space clears the selection, unless Ctrl or Shift is held.
- **Viewport picking**: a left click (not a drag, not Alt) casts a ray from the camera (`scene::CameraView::ray`) and picks the nearest Workspace Part whose *drawn* shape it hits (`scene::pick`: exact box, wedge slope, sphere and cylinder tests, using the same transform as the draw list). Parts the camera is inside are skipped. Clicking empty space clears the selection. Picking in the viewport opens the Explorer branches above the part and scrolls to it.
- **Locked** (the `Locked` property, on Parts, MeshParts, Unions, Models, Folders, lights and emitters; the new-project templates and new levels have it on for the Baseplate; existing worlds are left as they are): a viewport click or drag goes straight through a locked part or icon to what's behind it (`viewport/input.rs::pick_unlocked`), though parts can still rest on it and it still blocks snapping. Selected in the Explorer, it shows a lock icon, gets no handles and the building tools skip it (`viewport::gather`), Properties greys out everything but `Locked`, and Duplicate, Delete and moving it are refused (`tree::check_editable`). What's inside a locked Model or Folder counts as locked (`World::is_locked`). A row's right-click has Lock or Unlock, for the whole selection if the row is in it, as one undo step. It's written to the world file only when on, and does nothing in a running game. Tests: `a_click_goes_through_a_locked_part_to_what_is_behind_it`, `the_tools_leave_locked_parts_and_what_is_in_a_locked_model_alone` (`viewport/tests.rs`), `locking_from_the_explorer_is_one_undo_step_and_stops_delete_until_unlocked` (`app/tests.rs`).
- **Highlight**: each selected part gets a blue (25, 160, 255) wireframe box around its drawn mesh, painted by egui on top of the viewport image, so it shows through other parts. Like Studio's selection box, balls and cylinders get a box too. `render` is untouched. In the Explorer, every selected row is highlighted. Handles stay on the last one clicked.
- **Properties panel**: under the Explorer, in collapsible groups like Studio: Data (Name; ClassName only when Filter properties asks for it, since the header already says the class), Appearance (Color, Material, Metalness, Roughness), Behavior (Anchored), Part (Shape, Position, Orientation, Size). A property no group lists goes under "Other", so new properties always show. Controls: checkbox for bools, dropdown for enums, a color picker (egui's, converted from sRGB to linear light and back) with the 0–255 values, and drag-number boxes (drag to scrub, click to type) for numbers and each vector axis. Metalness and Roughness stay within 0–1, and Size within 0.001 and up (Roblox's minimum); values already out of range are never clamped just by being shown. Numbers show up to 3 decimals. In a placed prefab copy (Phase 49), a property the copy overrides has its name in bold with a ↺ revert button (`Edit::RevertOverride`); right-clicking the name applies it to the prefab (`Edit::ApplyOverride`; see `docs/editor/assets.md`). **Several selected** (`properties/many.rs`, design system V5): the header says "3 Parts" or "5 selected · 2 kinds", and the panel shows the properties they all have (the last one clicked's sections and order; references such as an ObjectValue's target are left out). A value that differs shows as `—`, a half-ticked box for a checkbox: clicking `—` shows the control with the last one's value, and only an edit writes. An edit goes to each that has the property, as one undo step (`EditorApp::apply_many`, `change_many`), and undo gives each its own value back; ↺ resets each to its own class's default. Locked ones only take Locked. Name shows when all can be renamed here. Attributes, tags, Keep pins, prefab overrides, the Style section and buttons such as Animate show with one selected; during Play an edit changes each in the game (tests in `app/multi_edit_tests.rs`).
- **Descriptions and Filter properties** (usability pass, `properties.rs` `described_name`, `matches_filter`): hovering a property's name shows what it does, from the same descriptions scripts' autocomplete and the API reference use (`axcenity_script::property_description`, looked up only while hovered; Name and ClassName have their own). **Filter properties**, under the header, shows only the rows whose names have what's typed in them, ignoring case and spaces ("walk speed" finds WalkSpeed), every row of a section whose title matches, and Attributes or Tags when one of them matches; matching sections are held open, and "No properties match" says when nothing does. The filter is kept from one selection to the next. Tests: `common_properties_say_what_they_do`, `filter_properties_shows_only_matching_rows`.
- **Reset to default** (usability pass, `field_name_with_reset`): a property whose value differs from what a new one of its class starts with (`ClassName::default_properties`) has ↺ before its name; hovering says the default ("Changed. Click to reset it to the default, 0."), and clicking sets it back as an ordinary edit, so one undo step. Not during Play (Play's changes are kept or dropped at Stop), not on a locked Instance except for `Locked`, not on properties that point at another Instance, and a prefab copy's overridden property keeps its own ↺ (revert to the prefab). Test: `a_changed_property_resets_to_its_default_with_one_click`.
- **Advanced** (usability pass, `properties.rs` `is_advanced`): rarely changed properties fold out of their usual groups into one closed **Advanced** section after the others, as Terrain Studio's Advanced does. Its header says how many differ from their defaults ("Advanced · 1 changed"), so a changed one isn't missed, and Filter properties still finds them (the section opens while filtering). The list is per class family: on parts MaterialVariant, BlueprintTexture, EmissiveColor, Emission, CanQuery, CollisionGroup, WindAffected, CustomPhysicalProperties, Massless, the Assembly velocities and TileSize; on styled UI Class, Id, Interactable, Selectable, the NextSelection links, AccessibleName, TextKey and RichText; on character controllers the slope, step and crouch limits, camera zoom limits, FootPlacement, MoveDirection, PlatformStand and Sit; on a ParticleEmitter Drag, WindAffectsDrag, LightEmission and Brightness (a light's Brightness stays in view); on a Sound the RollOff distances and SoundGroup; on a Model ModelStreamingMode. Nothing is removed or renamed. Test: `rare_settings_fold_under_advanced_and_say_how_many_changed`.
- **Attributes and tags** (Phase 29): below the property groups (not for services), an **Attributes** section lists each attribute with the control for its type and a ✕ beside its name that removes it, then an Add row (name, type, Add; the name must be valid and unused). A CFrame shows its position and its rotation in degrees; an EnumItem of a property enum is a dropdown. A **Tags** section shows each tag as a chip (click to remove it) and a box that adds one on Enter. Each edit is one undo step (`History::record_annotations`, keyed so dragging one attribute's number is one step); during Play they change the game, with no undo, and aren't kept at Stop. An ObjectValue's `Value` is a dropdown of every Instance in the Workspace and ReplicatedStorage, by full name, and None.
- **Tags panel** (Phase 29, `tags.rs`, View ▸ Tags; starts closed): every tag on an Instance in the world, with how many have it. Select selects them all; Rename (pencil, then Enter) renames the tag on every one, keeping its place among their tags (one that already has the new name just loses the old), as one undo step (`app/tags.rs`).
- **Edits apply live**: the panel returns an `Edit`, and the app applies it to the world before the viewport draws, in the same frame. Setting a value it already has doesn't count as a change. Service names, and Script names (which come from their files), are read-only.
- **Saving**: File > Save or Ctrl+S (Cmd+S on macOS) writes `world.json` with `project::save_world`; scripts and the manifest aren't touched. Unsaved changes put `*` after the project name in the title and "Unsaved changes" at the right of the menu bar. Closing the window, File > Quit or File > Open Project… with unsaved changes asks "Save changes?" (Save / Don't Save / Cancel; Escape or clicking outside is Cancel). If saving fails, the error goes to Output and the editor stays open.
