# Explorer tree

Insert, rename, duplicate, delete, and reparent.

- **Model and Folder** classes group Instances. Neither has properties yet (no `PrimaryPart`; scripts get a Model's pivot from `GetPivot`, see [../scripting/api-core.md](../scripting/api-core.md)), and clicking a part in the viewport still selects that part, not its Model. Scripts can make them with `Instance.new("Model")`.
- **Inserting**: toolbar buttons Block, Sphere, Cylinder and Wedge (chosen by the developer), and a right-click menu on Explorer rows with Insert ▸ (the four parts, Model, Folder, Animator, Animation, Ragdoll, Third Person, First Person, Seat, Vehicle, Vehicle Seat, Wheel, Agent, Checkpoint, Camera and Attachment). Third Person inserts a `ThirdPersonController` and First Person a `FirstPersonController` (`docs/scripting/api-character.md`): into the selected Model, Part, or MeshPart, or, with none of those selected or when a controller already moves it, a new Model and a Body part in the Workspace with the controller under the Model. The Model tab's Effects group has the same button. **Agent** inserts a `NavigationAgent` the same way (into the selected Model or part, or a new `Agent` Model with a Body), with its `Destination` where the body stands, so it stays put until given somewhere to go (`docs/architecture/navigation.md`). **Camera** inserts a `Camera` viewpoint where the editor's camera is, looking the same way (`docs/scripting/client-server.md`, Camera). **Attachment** (also in the Model tab's Constraints group; Phase 35) inserts an `Attachment` into the selected Part or MeshPart, at its middle (offset 0); with no part selected it goes in the Workspace, where its offset is in the world. **Seat** (also in the Model tab's Effects group; Phase 39) inserts a 2×1×2 `Seat` at the camera's focus, like a part (`docs/scripting/api-character.md`, Seats). **Vehicle** (also in the Model tab; Phase 40) inserts a ready-to-drive `Car` Model at the camera's focus as one undo step; **Vehicle Seat** inserts a 2×1×2 `VehicleSeat` like a Seat, and **Wheel** a `VehicleWheel` into the selected part, as an Attachment goes (`docs/scripting/api-character.md`, Vehicles). **Ragdoll** (in Insert ▸ beside Animator and Animation; Phase 41) inserts a `Ragdoll` into the selected Part or MeshPart, warning when it isn't a MeshPart; its Properties have **Build**, which makes its capsules and joints from the MeshPart's skeleton as one undo step (`EditorApp::build_ragdoll`; `docs/rendering/animation.md`, Ragdolls). **Checkpoint** inserts a `Checkpoint` on top of the selected part (at the origin with no part selected), in the Workspace or the selected Model or Folder (`docs/architecture/saves.md`). New things go **into the selected Model or Folder** if one is selected (or right-clicked), otherwise into the Workspace, and become the selection. Parts go at the camera's focus point, on the move grid when Snap move is on (otherwise rounded to 3 decimals), with the core defaults (unanchored, plastic). Sizes: blocks and wedges 4×1×2, spheres 2×2×2, cylinders 4×2×2 (4 long along X, so they read as cylinders). Every primitive is named `Part`, as in Studio. UI elements go into a ScreenGui instead (see `docs/ui.md`).
- **Unique names** (`crates/editor/src/tree.rs`): a new or duplicated Instance gets the first of `Name`, `Name2`, `Name3`… that none of its siblings has. A number already on the end is replaced, so a copy of `Pad2` is `Pad3`. Renaming and moving don't enforce this.
- **Prefab ▸** in the right-click menu of a placed prefab copy's top row (Phase 49): apply its overrides to the prefab (all, or one), Revert all, Unpack (see `docs/editor/assets.md`).
- **Export Package…** in a row's right-click menu (after Insert ▸; off for scripts, services, UI and anything outside the Workspace): saves the object as a prefab with every asset it uses in a `.axpkg` file (see `docs/editor/assets.md`).
- **Rename** with F2, Edit > Rename or the right-click menu: the row turns into a text box; Enter or clicking away keeps it, Escape cancels, an empty name cancels. One undo step.
- **Duplicate** (Ctrl+D / Cmd+D) copies each selected subtree into the same parent, right after the original, in the same place in the world, and selects the copies, as one undo step. A UI element in a copy gets a fresh `Id` (`play` → `play2`) with copies of its own `#Id`, `#Id:hover` and other `#Id…` rules. **Delete** (Delete, or Backspace on macOS) removes each selected Instance and everything in it. A script is still deleted one at a time, so its file can be removed too.
- **Reparent** by dragging an Explorer row onto another row: it becomes that row's last child. A valid target is outlined in blue; an invalid one shows a "not allowed" cursor and the reason. Rejected: into itself or its own descendants, and anywhere outside the Workspace (the world file only saves the Workspace). There's no reordering among siblings yet.
- **Locked**: services can't be deleted, duplicated, moved or renamed. Scripts can be renamed and deleted since Phase 13 (see Script editing), but not duplicated or moved. Menu items are greyed out with the reason on hover.
- **Undo** (`history.rs`): tree changes are `Tree` steps holding `Move`s (an Instance's parent and child index before and after; `None` is out of the tree). **Deleting only detaches**: the Instance keeps its ID, properties and children outside the tree, so undo puts the very same Instances back at the same index, and older steps naming them still work. When an undone insert or duplicate can no longer be redone (a new change clears redo), its detached Instances are destroyed. After undo, redo or delete, a selection that left the tree is cleared. Tree edits are ignored while a part is being dragged in the viewport.
