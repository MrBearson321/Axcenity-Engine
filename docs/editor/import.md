# Import and animation

Importing models, and the Animation panel.

- **Import** (chosen by the developer): **File > Import Model…** and an **Import** button at the end of the toolbar's Insert group both open a file picker for `.gltf`/`.glb`/`.fbx` (FBX added after Phase 17). The model is loaded first, so a file that can't be loaded is reported in Output ("Could not import `…`: it isn't a valid glTF file: …") and nothing is copied or inserted. Off during Play and with no project open.
- **Copying** (`assets::import_model`): a `.glb` or `.fbx` that uses no other files goes to `assets/models/<name>.glb` (or `.fbx`); a `.gltf`, or a model that uses other files, goes to its own folder, `assets/models/<name>/<name>.gltf` (or `.glb`, `.fbx`), with the `.bin` buffers and textures it uses at the same relative paths. An FBX texture that isn't found is left out, and reported in Output after the import. `<name>` is the file name with only letters, digits, spaces, `-` and `_` kept, plus a number if taken (`pyramid2`). Files the model uses must be inside its folder.
- **The MeshPart** (chosen by the developer: the file's materials, no Color or Material override) is inserted like a part: at the camera's focus point, inside the selected Model or Folder if any, named after the file (`pyramid`, `pyramid2`…), at its size in the file (1 glTF unit, or 1 meter in an FBX file, = 1 stud; a flat axis gets 0.001), and selected. The insert is one undo step; undo leaves the copied file in the project.
- **Choosing objects** (Phase 18): a file with more than one object (node with a mesh) opens the Import dialog before anything is copied (`import_dialog.rs`). It lists the file's tree (groups and meshes, with triangle counts and material names), all ticked; ticking a group ticks what's inside it, and a search box filters the rows (Select all/none then act on what's shown). Cancel, Escape or a click outside imports nothing. The ticked objects come in as one of:
  - **A Model** (the default) named after the file, holding a MeshPart per object, placed as in the file around the camera's focus point. Groups in the file (nodes without a mesh) become Models inside it; an object inside one with a mesh goes next to it, since parts don't hold parts.
  - **Separate MeshParts**, each at the focus point.
  - **One merged MeshPart**, as for a single-object file (its `MeshId` names the ticked objects, or just the file if all are ticked).
  The file is copied once; every part's `MeshId` names its object in the copy (see `docs/project/world.md`). Each MeshPart is named after its object and sized to it. The whole insert is one undo step, and the last thing inserted is selected.
- **Texture maps on import** (Phase 21): the dialog also opens for a single-object file whose materials have any texture map (`ImportDialog::worth_asking`), and then shows only its Materials section. That section lists each of the file's materials with its eight maps (Color, Normal, Metalness, Roughness, Emission, Occlusion, Opacity, Specular) as found (see `docs/rendering/models.md`), each with a Browse button (any PNG/JPEG/TGA/BMP, anywhere) and a Clear button, a channel dropdown for the grey maps, and checkboxes for DirectX normals, glossiness-as-roughness and inverted opacity. The file is loaded once from where it is (`assets::load_model_file`) to find them; `editor/src/surface.rs` holds them as `MaterialMaps`.
- **SurfaceAppearances on import:** every new MeshPart gets one SurfaceAppearance child per material its model uses, named after the material (`MaterialName` set), with the maps as in the dialog. The model's own textures are paths into the copy's folder (embedded ones are copied out to its `textures` folder on import); files picked in the dialog are copied into that `textures` folder too, once each, under a free name. They're part of the insert's undo step.
- **Maps in Properties:** a SurfaceAppearance shows Appearance (`Color`), Surface (`MaterialName` and the eight maps) and Map Settings. A map shows its file name (full path on hover), a Browse button and a Clear button; it can't be typed, as each half-typed path would be loaded. Browse returns `Edit::PickTexture`, and the app asks for a file: one inside the project keeps its path, one outside is copied into `assets/textures` first (`assets::import_texture`). The change is one undo step, and the viewport shows it on the next frame.
- It moves, scales, rotates, duplicates, saves and reloads like a Part. Picking, the selection box, handles and drag-to-place all use its box (the model fills it). `MeshId` shows in Properties under Part but is read-only (importing sets it). Explorer icon: a see-through cube, part blue.
- **Animated FBX files** (Phase 38, `anim_import.rs`): a file whose model has a skeleton (or whose objects a take moves), or that has takes, opens the dialog with an **Animation** section: the skeleton's bone tree and joint count, each take with its frames, frame rate and the bones it moves, and a table of **clips to make** (name, take, start and end frame, loop), one per whole take to begin with. Add clip adds a row; Split replaces a take's rows with N equal parts ("Moves 1", "Moves 2"…), so one long take becomes Idle, Walk and so on. A clip of a file's only take with a meaningless name ("Take 001", "mixamo.com") is named after the file; Blender's `Armature|` prefix is dropped. Names must be unique (ignoring case) and each clip must end after it starts, or Import is off. An animated file comes in as one MeshPart by default. Importing writes each clip to `assets/animations/<model>/<name>.anim.json` and, with "Add an Animator" ticked (the default), a controller `assets/animations/<model>.controller.json` with a state per clip (one named Idle, or else the first, as the default state, at the left of the graph; the rest in rows of four), and gives every new MeshPart with a skeleton an Animator playing it (part of the insert's undo step; the files stay). A name already taken gets a number. A file with takes but nothing to draw (an animation exported "without skin") imports as clips only: the file is copied to `assets/models` and its clips are written, for a model with the same skeleton.
- **Animators** (Phase 38): Insert ▸ Animator (Explorer menu) puts one in the selected MeshPart, with a warning if there isn't one. Properties shows its Animation group: `Controller` (a Browse button that picks a `.controller.json` inside the project, and a Clear button), `Enabled` and `Speed`. Animators only play during Play (each Play makes a fresh `anim::Animators`, primed before the scripts start, run after Heartbeat; its problems go to Output once each); while editing, models show their bind pose.
- **Property Animation**: Insert ▸ Animation puts an `Animation` in the selected Part, MeshPart or Model. Properties: `Clip` (a `.anim.json` with `"kind": "property"`), `Enabled`, `Speed`, `Looped`. The Animation panel's **+ Property** makes a clip with Position keys; open it for the dope sheet (insert/move/delete keys, scrub on the selected Part with restore on Stop). Hosts run `anim::PropertyPlayers` beside `Animators` after Heartbeat.
- **Animation panel** (Phase 39, `animation.rs`; the Animation Studio): a dockable panel that starts as a tab beside the Scene (View > Panels opens it there again). On the left, the **Library**: every `*.anim.json` under `assets/animations`, grouped by folder (collapsible), with a search box, looked for again every 2 s while shown (`animation/store.rs`). New clip asks for a model file in `assets/models` (any `.fbx`), one of its takes and a name, and writes a clip of the whole take to `assets/animations/<model>/<name>.anim.json`. A clip's right-click menu has Rename (renames its file in its folder, and rewrites every controller that plays it to the new path, as the same undo step; names are letters, digits, spaces, `-` and `_`), Duplicate ("<name> copy", opened) and Delete (asks first, naming the controllers that play it; they keep the path, and report it missing when they run). Making a clip, renaming it, duplicating it and deleting it are each one undo step; undo of a delete restores the file, and the Library and the Assets panel show it again without reopening the project. Saving does not clear those steps. Clicking a clip opens it. The middle shows its **preview**: the model on a checkered floor (12×12 tiles a third of its height wide), drawn by its own `TextureRenderer` from its own `World`, through an orbiting camera (drag to turn, wheel to zoom), never the edited world or Play; the model is the clip's source if it has a skeleton the take moves, otherwise the first model in `assets/models` that does (Preview on picks another). Under it, play/pause, back to the start, the frame and the time, and the **timeline** (`animation/timeline.rs`): the whole take with frame numbers, the clip's part of it with handles that drag its start and end, the playhead (click or drag to scrub; scrubbing pauses) and the events as diamonds (drag to move, right-click to remove), all on whole frames. On the right, its **settings**: name (rename), model, take (picking one resets the range to the whole take), start and end frames, speed (−10 to 10; below 0 plays backwards), Loop, Root motion (with a note when no bone moves across the ground), Preview on, and the events (name, frame, remove; Add at playhead with a typed name). The preview plays the clip as the game will: its range, speed and loop, and with root motion on it stays in place. Changes are written to the file once the gesture ends (no mouse button held, nothing being typed), and before Play, on Save and when the project closes; they aren't undo steps (Revert puts back the file as opened). The **Assets panel** has an Animations category with clips and controllers; double-clicking (or dropping) a clip opens it in the Animation panel, and dropping a controller on a MeshPart sets its Animator's `Controller` (adding an Animator if it has none), as one undo step.
- **Controllers in the Animation panel** (Phase 40, `animation/controller_editor.rs`, `animation/graph.rs`): the Library also lists the controllers (`*.controller.json` in `assets/animations`; right-click to rename, duplicate or delete, each one undo step), and + Controller makes one (the new file is one undo step; giving it to the selected Animator stays a separate undo step): named after the selected MeshPart, with a state per clip in its model's folder (`assets/animations/<model>/`; an Idle one, or else the first, as the default) if ticked, and given to that MeshPart's Animator (one undo step; an Animator is added if it has none) if ticked. Properties opens an Animator's controller with the button beside `Controller`. An open controller shows its **state machine graph** in the middle, like Unity's Animator: states as boxes (the default state orange, each showing its clip), the Any State (teal), and transitions as arrows with a head halfway along (two-way pairs side by side; generated ones dashed; the one blending in the preview green). Drag a box to move it (positions are saved: `position`, and `any_state_position` once it's moved); drag the background, or with the middle button, to pan; the wheel zooms around the mouse. Click a box or an arrow to select it, the background for the controller's settings; Delete removes the selection. Right-click a box for Make Transition (then click the state it goes to; Escape cancels), Set as Default State, Rename and Delete (with its transitions); right-click the background to add an empty state or one playing a clip. The **inspector** shows the controller's default state and **parameters** (add Bool, Number or Trigger; rename, which renames them in conditions; defaults; remove), a state's name (renaming it renames it in transitions and as the default), clip, speed and transitions, or a transition's conditions (parameter, a test that fits its type, a value for Numbers), blend (a 0–2 s slider and Instant 0 / Smooth 0.25 / Slow 0.75), exit time (on/off and how much of the clip), interruptible and priority, with a warning when it can never happen. Under the graph, a **live preview**: the state machine running (its own `Machine` and parameters, not the game's) on a model (the Animator's MeshPart's, or the first clip's, or picked), with play/pause and restart (the default state and parameters again), the state playing (also highlighted in the graph with its progress) and blend, and controls for every parameter: checkboxes for Bools, sliders for Numbers (from 0 to past the values their conditions test) and Fire for Triggers. Editing keeps it running where it was (only moving boxes doesn't rebuild it). With a transition selected, **Preview the blend** scrubs between its two states' poses, showing each one's share. **Return when** (Phase 42): a state's inspector has a Return when… setting: when (its clip finishes, a Bool becomes true or false, a Trigger is set, or some seconds pass), the Bool or Trigger, back to which state (the default state to begin with) and the blend. It makes its transition (`files::with_returns`, every frame the controller is open, and again when an animator loads it): one per state, from it to the state it returns to, marked `generated` and drawn dashed, at the end of the list; "its clip finishes" is exit time 1, a Bool or Trigger is a condition, and seconds become an exit time by the clip's length at its speed (a second if that can't be read). The inspector shows a generated transition read-only, with Edit the Return setting and Remove it (which turns the setting off); renaming a state renames it in Return settings, and deleting one removes the settings that return to it. **Blend trees** (Phase 41): a state plays "A clip" or "A blend tree" (the graph's background menu also has Add Blend Tree; a new one uses the first Number parameter, adding `Speed` if there's none). Its editor picks the Number parameter, and lists each clip with its threshold (a slider and a number) and its share in the preview now (a bar), with Add clip, Sort (by threshold) and **Add Locomotion** (Speed, 0–6 m/s: the project's clips named with idle, walk and run, from the same folder if it can, at 0, 2 and 6; Speed is added if missing); under them, the thresholds on a line with each clip's name and the parameter's value now as a marker. The graph shows a blend tree state as "blend tree · Speed · 3 clips", and the preview's Number sliders reach its highest threshold. A **step bar** across the panel's top follows the five Animator steps (model selected, clips imported, controller open, transitions made, test) with Import…, New/Open and Play buttons.
- **Models load when first drawn** (or simulated) through the project's shared `Assets`, made on open. A model that can't be loaded is reported once in Output ("Could not load the model `assets/models/x.glb`: the file isn't there") and drawn as a grey box. Model files aren't watched: a changed model shows after opening the project again.
