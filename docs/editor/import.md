# Import and animation

Importing models and other assets (one Import…), and the Animation tab (the Animation window).

- **One Import…** (unified Phase 5, `app/files/import.rs`): **File > Import…**, **Import…** in the ribbon's Import group (Model tab), the Assets panel's Import and the empty Animation tab's Import… all open one file picker for every kind it imports (`EditorApp::import_with_dialog`): models (`.gltf`/`.glb`/`.fbx`), images, sounds and prefabs, several at once. Files dropped onto the editor window go the same way (`import_dropped`; images into `assets/textures`, or into the Assets panel's shown image folder when picked there). Each file is imported by its kind (`EditorApp::import_file`): a model through the Import dialog; images, sounds and prefabs straight in, with no dialog, reported in the Console and a toast. Models picked or dropped together open the dialog one after another (`import_queue`). The model is loaded first, so a file that can't be loaded is reported in the Console ("Could not import `…`: it isn't a valid glTF file: …") and nothing is copied or inserted. An asset package (`.axpkg`) opens the same dialog with one tab, **Package**, and no preview (`import_dialog/package.rs`): what's in it and what happens to each file (new, already in the project, or a clash and where it goes), and, when some files are already in the project with other contents, Keep both / Replace / Skip existing for all of them (see `docs/project/packages.md`). The summary says what Import adds and lists the clashes ("Adds 6 files: 5 clips, 1 state machine. 1 file already exists: Walk. Keep both puts the package's in `assets/animations/noodle2/`."); with nothing to add, Import is off and says why. Importing writes the files as one undo step (`History::record_blobs`, which keeps their bytes, so models and pictures come back too; "Import <package name>"). A replaced model file shows after the project is opened again, as with any changed model. Tests: `app/files/package_tests.rs`. Off during Play (a drop then says "Press Stop before importing files.") and with no project open. Test: `every_way_in_opens_the_same_dialog_for_a_model`.
- **Copying** (`assets::import_model`): a `.glb` or `.fbx` that uses no other files goes to `assets/models/<name>.glb` (or `.fbx`); a `.gltf`, or a model that uses other files, goes to its own folder, `assets/models/<name>/<name>.gltf` (or `.glb`, `.fbx`), with the `.bin` buffers and textures it uses at the same relative paths. An FBX texture that isn't found is left out, and reported in Output after the import. `<name>` is the file name with only letters, digits, spaces, `-` and `_` kept, plus a number if taken (`pyramid2`). Files the model uses must be inside its folder.
- **The MeshPart** (chosen by the developer: the file's materials, no Color or Material override) is inserted like a part: at the camera's focus point, inside the selected Model or Folder if any, named after the file (`pyramid`, `pyramid2`…), at its size in the file (1 glTF unit, or 1 meter in an FBX file, = 1 stud; a flat axis gets 0.001), and selected. The insert is one undo step; undo leaves the copied file in the project.
- **The Import dialog** (`import_dialog.rs` and `import_dialog/`) opens before anything is copied for a file with more than one object, texture maps or animation (`ImportDialog::worth_asking`). Cancel, Escape or a click outside imports nothing.
  - **Tabs** (`Tab`, `import_dialog/tabs.rs`): under the title (what the file holds: objects, triangles, materials, skeleton, takes), tabs show only what the file needs, in order: **Objects** (the objects, then **Bring in as**; more than one object), **Materials** (the texture maps; any materials), **Animation** (animated). Each tab scrolls on its own and keeps its place. **Import** works from any tab with the choices as they are on all of them. A tab with a problem (nothing ticked; a clip problem) shows a warning sign, and Import is off with the reason beside it.
  - **Summary** (`ImportDialog::creates`, `Creates::sentence`): above Import and Cancel, one sentence says what Import creates and where, following every choice, such as "Creates: 1 MeshPart · 4 clips in `assets/animations/noodle/` · 1 state machine · an Animator. Copies the model to `assets/models/noodle.fbx`." or "Creates: 1 Model with 3 MeshParts and 1 Model for its groups. Copies the model and 1 texture to `assets/models/props/`." A test (`the_import_summary_matches_what_import_creates`) imports noodle.fbx and a three-object glTF and checks the counts and folders against what was made.
  - **Preview** (`import_dialog/preview.rs`): the model as loaded from the file (its own materials), on a checkered floor through the Animation tab's `Preview` (drag to turn, wheel to zoom), drawn from a private `Assets` holding that one model, so nothing is read twice and the project's assets aren't touched. An animated file plays the clip picked with ▶ on the Animation tab (the first to begin with), looping, as `Clip::bind` plays it in the game; play/pause is under it. After a map is changed it says the change shows once imported. An animation-only file shows a note instead.
  - **What you'll get** (`import_dialog/outcome.rs`): under the preview, the Instances the import makes as the Explorer will show them (`ImportDialog::made`: the Model and its group Models and MeshParts, or the MeshParts, or the one MeshPart with a SurfaceAppearance per material and its Animator; at most 12 rows, the last "… and N more"), where they go, and the files written (`files_made`: `assets/models/<name>/` with the model and its textures, or `assets/models/<name>.<ext>`; `assets/animations/<name>/` with its clips and state machine). It follows every choice.
- **Choosing objects** (Phase 18): the Objects tab lists the file's tree (groups as Models and meshes as MeshParts, with triangle counts and material names), all ticked; ticking a group ticks what's inside it, and a search box filters the rows (Select all/none then act on what's shown). Under them, **Bring in as** shows the three ways as cards, each saying what it makes and what it's for, with **Recommended** on One MeshPart for an animated file and on A Model otherwise (and a warning that each part gets its own Animator when an animated file isn't one MeshPart):
  - **A Model** (the default) named after the file, holding a MeshPart per object, placed as in the file around the camera's focus point. Groups in the file (nodes without a mesh) become Models inside it; an object inside one with a mesh goes next to it, since parts don't hold parts.
  - **Separate MeshParts**, each at the focus point.
  - **One merged MeshPart**, as for a single-object file (its `MeshId` names the ticked objects, or just the file if all are ticked).
  The file is copied once; every part's `MeshId` names its object in the copy (see `docs/project/world.md`). Each MeshPart is named after its object and sized to it. The whole insert is one undo step, and the last thing inserted is selected.
- **Texture maps on import** (Phase 21): the Materials tab lists each of the file's materials as a card that opens (the first open, all open with two or fewer): its name, how many maps, and a small picture of each. Open, it has a row for each map the material has (Color, Normal, Metalness, Roughness, Emission, Occlusion, Opacity, Specular, as found; see `docs/rendering/models.md`): a 36-point picture, what the map is (its tooltip says what it does), the file name, a channel dropdown for the grey maps, Replace (any PNG/JPEG/TGA/BMP, anywhere) and Remove. Only the settings for maps it has are shown (DirectX normals, glossiness-as-roughness, inverted opacity), and **Add map** lists the maps it doesn't have. Pictures of the model's own maps are shrunk from its decoded images; a picked file is read once. The file is loaded once from where it is (`assets::load_model_file`) to find them; `editor/src/surface.rs` holds them as `MaterialMaps`.
- **Fits the window** (v3 Phase 6): the dialog is at most 960 points wide and never taller than the window, keeping 16 points from its edges; its body is at most 560 points tall. From 700 points wide the preview and What you'll get are a column at the left (320 points) and the tab scrolls on its own at the right (both ways, so the clips table never widens the dialog); narrower, the preview, the tab and What you'll get scroll together. The summary, Import and Cancel are pinned under it (the summary's height is measured), so they can be reached in any window size. Heights are worked out, not taken from `available_height`, which in a modal grows with last frame's size. A drawing test (`the_whole_dialog_fits_an_800_by_600_window_with_import_clickable`) opens noodle.fbx with every tab in an 800×600 window, clicks each tab in the tab bar and then Import; with `AXCENITY_SNAPSHOTS` it saves `import-dialog-800x600-<tab>.png`.
- **SurfaceAppearances on import:** every new MeshPart gets one SurfaceAppearance child per material its model uses, named after the material (`MaterialName` set), with the maps as in the dialog. The model's own textures are paths into the copy's folder (embedded ones are copied out to its `textures` folder on import); files picked in the dialog are copied into that `textures` folder too, once each, under a free name. They're part of the insert's undo step.
- **Maps in Properties:** a SurfaceAppearance shows Appearance (`Color`), Surface (`MaterialName` and the eight maps) and Map Settings. A map shows its file name (full path on hover), a Browse button and a Clear button; it can't be typed, as each half-typed path would be loaded. Browse returns `Edit::PickTexture`, and the app asks for a file: one inside the project keeps its path, one outside is copied into `assets/textures` first (`assets::import_texture`). The change is one undo step, and the viewport shows it on the next frame.
- It moves, scales, rotates, duplicates, saves and reloads like a Part. Picking, the selection box, handles and drag-to-place all use its box (the model fills it). `MeshId` shows in Properties under Part but is read-only (importing sets it). Explorer icon: a see-through cube, part blue.
- **Animated FBX files** (Phase 38, `anim_import.rs`): a file whose model has a skeleton (or whose objects a take moves), or that has takes, opens the dialog with an **Animation** tab: the skeleton's bone tree and joint count, each take with its frames, frame rate and the bones it moves, and a table of **clips to make** (▶ to play it in the preview, name, take, start and end frame, loop), one per whole take to begin with. Add clip adds a row; Split replaces a take's rows with N equal parts ("Moves 1", "Moves 2"…), so one long take becomes Idle, Walk and so on. A clip of a file's only take with a meaningless name ("Take 001", "mixamo.com") is named after the file; Blender's `Armature|` prefix is dropped. Names must be unique (ignoring case) and each clip must end after it starts, or Import is off. An animated file comes in as one MeshPart by default. Importing writes each clip to `assets/animations/<model>/<name>.anim.json` and, with "Add an Animator" ticked (the default), a state machine `assets/animations/<model>/<model>.statemachine.json` (beside its clips; a controller in `assets/animations` before v3 Phase 7) with a state per clip (one named Idle, or else the first, as the default state, at the left of the graph; the rest in rows of four), and gives every new MeshPart with a skeleton an Animator playing it, with an Animation per clip under it (named after the clip, `Clip` set, AutoPlay off; v3 Phase 8), as part of the insert's undo step (the files stay). A name already taken gets a number. A file with takes but nothing to draw (an animation exported "without skin") imports as clips only: the file is copied to `assets/models` and its clips are written, for a model with the same skeleton.
- **Animators** (Phase 38): Insert ▸ Animator (Explorer menu) puts one in the selected MeshPart, with a warning if there isn't one. Properties shows its Animation group: `StateMachine` (a Browse button that picks a `.statemachine.json` inside the project, and a Clear button; `Controller` before v3 Phase 7), `Enabled` and `Speed`; an Animation shows `Clip`, `AutoPlay`, `Enabled`, `Speed` and `Looped`. Dropping a state machine from the Assets panel onto a Part or MeshPart gives it an Animator playing it. Since v3 Phase 7 the editor says "state machine" where it said "controller" (code names such as `ControllerDoc` still say controller). Animators only play during Play (each Play makes a fresh `anim::Animators`, primed before the scripts start, run after Heartbeat; its problems go to Output once each); while editing, models show their bind pose.
- **Property Animation**: Insert ▸ Animation puts an `Animation` in the selected Part, MeshPart, Model, ScreenGui or frame. Properties: `Clip` (a `.anim.json` with `"kind": "property"`), `Enabled`, `Speed`, `Looped`. The Animation tab's New ▸ Keyed clip… makes an empty clip to key in its preview (below); Animate does it in one step. Hosts run `anim::PropertyPlayers` beside `Animators` after Heartbeat.
- **One Animation window** (v3 Phase 8, `animation.rs`; Phase 4 had an Animation tab and an Animator tab): one dock tab beside the Scene (View > Panels opens it there again; a saved layout's old Animator tab loads as it). A clip and a state machine can be open at once; the tab shows one of them.
  - **It follows the selection** (`Subject`, `animatable_of`): the selected Part, MeshPart, Model, ScreenGui or UI element, or the parent of a selected Animator or Animation (an Animation under an Animator stands for the Animator's parent). Selecting another object that has an Animator opens its state machine, or else its first Animation's clip. Selecting something inside the followed object keeps it (so a Door's Hinge can be picked for its preview); selecting an Animation of it opens that Animation's clip. Selecting another object with no Animator follows it with nothing open, ready for Animate. A clip opened from the Assets panel (double-click or drop) opens **on its own**, following nothing, until something with an Animator is selected; it previews on the model picked with **Preview on…** (a take clip), or on what's selected (a keyed clip).
  - **Outline** (left; wider than 720 points): the object's name, then its Animator; its **State Machine**, with each state and the clip it plays (and that clip's badge); and its **Animations** (under the Animator, then beside it on the object), each with its clip's badge; then **+ New Animation**, which animates it again (another clip and Animation). Clicking the State Machine shows its graph, inspector and live preview; clicking a state or an Animation opens its clip. An object with no Animator shows **Animate <name>** instead. Narrower than 720 points the outline drops down from the breadcrumb's first crumb.
  - **Breadcrumb** (top): where you are, such as **Hero ▸ State Machine ▸ Walk**, **Door ▸ DoorOpen** (an Animation) or **Hero ▸ State Machine**; a clip or state machine that isn't the followed object's shows just its own name. Double-clicking a state in the graph (`GraphEvent::Open`) opens its clip (a blend tree's first) under the state machine; clicking **State Machine** in the breadcrumb goes back up to the graph. Beside it: the open clip's badge, **Open ▾** (every state machine and clip, grouped by folder, searchable, each with a ⋯ for Rename, Duplicate and Delete; the pickers before Phase 8) and **New ▾** (Keyed clip…, Clip from a take…, State machine…).
  - **Icons and colours** (`theme::AnimKind`): Animator (running figure, green), State Machine (flow arrow, orange), Animation (film slate, teal) and clip (film strip, violet), the same in the outline, the breadcrumb, the Explorer, the Assets panel and Open ▾. A clip's **badge** says **Linked to noodle.fbx · Walk** (a clip linked to a take) or **Keyed**.
  - **Animate** (the empty tab's button, the Explorer's right-click menu and the top of Properties, for any object that can animate; `EditorApp::animate`): one undo step (`History::record_files_and_tree`) that adds an Animator if the object has none, writes a keyed clip to `assets/animations/<name>/<name>.anim.json` (a number added if taken), and puts an Animation named after the clip, playing it, in the Animator. The tab then follows the object and opens the clip with **Record** on. Tick AutoPlay on the Animation (Properties) to play it when Play starts. With nothing open and nothing animatable selected, the tab shows only Import….
  - **Clips**, top to bottom: a toolbar (for a take clip play/pause, back to the start, Loop, Speed, **Preview on…** the model and **Record**; for a keyed clip play/pause, back, Stop, Loop, what the preview shows a copy of ("Preview on Door") and **Record**; then buttons that show or hide the drawer and the inspector, and a ⋯ menu with Rename, Duplicate and Delete, and for a linked clip **Convert to keys**); the preview, with a **drawer** on its left listing the preview model's bones as a tree (those the take moves locked, 🔒; the rest selectable, with their key counts) or a property clip's objects and their tracks, and under a skinned MeshPart its bones (click one to select it); the **timeline** (or a property clip's dope sheet, resizable) docked along the bottom; and the clip's **settings** in the inspector on the right. Narrower than 560 points it stacks: the preview, the drawer and Settings as collapsible sections, and the timeline, scrolling together.
  - **Keying Parts, Models and UI** (v3 Phase 5, `animation/object_preview.rs`, `animation/property_editor.rs`): a keyed clip's preview shows a **copy** of the followed object (or, for a clip opened on its own, of the Part, Model, ScreenGui or UI element selected in the Explorer; an Animation stands for its parent), in a world of its own taken with `World::clone` (so ids match): alone on a floor, or for a UI element its whole ScreenGui, laid out flat with the project's stylesheets. The edited world is never changed. The copy stays when something outside it is selected; selecting something inside it selects it in the preview; ↻ in the toolbar copies it again after editing the world. Click a part or UI element in the preview (or an object in the drawer) to select it. 3D: Move, Rotate and Resize buttons above the preview pick the handles (snapping 1 stud and 15°); a Model's handles move its pivot (no Resize); dragging elsewhere turns the camera, and the wheel zooms. UI: the element's eight handles (as in the Scene View, ignoring CSS sizes) move and resize it. A move with **Record** on sets keys at the playhead (making tracks as needed). With Record off it shows only until the playhead moves, and **Key selected** (K) keys it: the object's tracks, its moves, and where it is (Position and Orientation, or a UI element's Position and Size). Add track lists the selected object's keyable properties and keys its current value.
  - **Posing skeletal rigs** (unified Phase 7, `animation/posing.rs`): a skinned model's bones show in the drawer as a tree (unnamed bones are left out) and in the preview as joints joined by lines. Click a joint (or a bone in the drawer) to select it; its gizmo turns it around the world's axes in 5° steps (Rotate), and a root bone (no named bone above it) can also be moved (Move); the buttons above the preview pick which. A turn with **Record** on keys the bone at the playhead; with it off it shows until the playhead moves, and **K** keys it. Bone keys are `Bone` tracks on the clip (target the bone's path, `Root/Mid/Top`; see `docs/project/animation-files.md`), so they play through Animators, state machines, blend trees and AnimationTracks like any clip. In a keyed clip the preview is the copy of the skinned MeshPart, its tracks are in the dope sheet, and the bones' tracks are listed under them in the drawer. In a linked clip, the bones the take moves are locked (🔒, dimmed in the preview, and "can't be keyed" in the Console if tried); the others key alongside the take (right-click a bone in the drawer to remove its keys). **Convert to keys** (the linked clip's ⋯ menu; `anim::convert_to_keys`) is one undo step (`Convert <name> to keys`): it bakes the take's motion over the clip's range into bone keys, a key a frame at the take's frame rate, drops the keys the keys around them already make, removes the link and keeps the clip's own tracks and events, so the badge becomes Keyed and the clip opens as a keyed clip, looking the same. It's baked on the preview model's skeleton; with root motion on, the root is baked in place (as the preview shows it) and the Console says root motion isn't kept. Tests: `a_three_key_wave_made_on_an_imported_rig_plays_in_the_preview_a_state_and_play` and `a_linked_clips_take_bones_are_locked_until_convert_to_keys_which_looks_the_same` (`app/posing_tests.rs`), and `posing.rs`'s own.
  - **Dope sheet**: click a key to select it (Shift or Ctrl adds or removes); drag a box over empty space to select many; drag a selected key to move them all (a moved key that lands on another replaces it); the ruler and empty clicks move the playhead. Copy (Ctrl+C), cut (Ctrl+X), paste at the playhead onto the same tracks (Ctrl+V) and Delete. **Snap** puts keys and the playhead on whole frames (30 fps by default, not saved). While the mouse is over the tab, K, Delete and Backspace are the dope sheet's (`AnimationStudio::wants_keys`), not the F3X Collision tool's or the Explorer's. The drawer lists the copy's tree with each object's tracks (right-click a track to delete it), then any track whose object isn't in the copy; the preview names tracks it couldn't apply. The selected key's time, numbers (X/Y/Z, R/G/B, the UDim2's scales and offsets, or Value) and interpolation are in the inspector: Constant, Linear, Ease (with a Style, Sine to Elastic, and a Direction, In, Out or InOut) or Bezier (its handles' Out and In time and value). See `docs/project/animation-files.md` for how each plays.
  - **Curves** (unified Phase 8, `property_editor/curves.rs`): **Dope sheet · Curves** above the dope sheet switch between them. Curves draws the shown tracks' numbers over time, one colour a number (X red, Y green, Z blue, as the gizmo), sampled with `anim::sample_track`, so they're the curves the game plays; bone, property and UI tracks alike. Its left column lists the tracks: click one to show it, Shift or Ctrl to add more (with none picked it shows the selected track). Click a key to select it (it's the same selection as the dope sheet's); drag it to move it in time (snapped) and value. A Bezier key's two handles to the next key show while either key is selected; drag them to shape the motion. Drag empty space, or with the middle button, to pan; the wheel zooms around the mouse (Shift: time only; Ctrl: values only); **Frame all** (F) fits the clip, its curves and handles, and showing other tracks frames again. Test: `bezier_handles_dragged_in_the_curves_view_are_saved_and_reloaded` (and `a_keys_easing_changes_the_preview_and_plays_the_same_in_the_game`). A door: a Door Model with a Hinge Part, and the Panel inside the Hinge. Select the Hinge, Rotate it with Record on, and the Panel swings with it in the preview and in Play.
  - **State machines**: a toolbar (**Preview on…** the live preview's model, play/pause and restart, a button that shows or hides the inspector, and the ⋯ menu), the state machine graph with its inspector on the right, and the live preview with its parameters along the bottom (at most half the height). Below 560 points the graph, the live preview and Settings stack.
  - **Tests**: `animate_makes_an_animator_a_clip_and_an_animation_as_one_undo_step`, and `the_animation_tab_says_where_you_are_and_fits_any_shape` (the breadcrumb through Animate, the state machine, a state's clip and back up; the tab drawn with a clip and with a state machine at 600×400, 260×900 and 1100×600; with `AXCENITY_SNAPSHOTS` it saves `animation-<view>-<shape>.png`). `an_animated_fbx_comes_in_with_an_animator_a_state_machine_and_an_animation_per_clip` checks import.
  - **Open ▾** lists every `*.statemachine.json` and `*.anim.json` under `assets/animations`, looked for again every 2 s while the tab is shown (`animation/store.rs`); the outline's states and badges are read again then too. With nothing open, the tab shows Animate <name> (for what's selected or followed) and Import… (Phase 4's checklists and the step bar before them are gone).
  - New clip asks for a model file in `assets/models` (any `.fbx`), one of its takes and a name, and writes a clip of the whole take to `assets/animations/<model>/<name>.anim.json`. A clip's ⋯ menu has Rename (renames its file in its folder, and rewrites every state machine that plays it to the new path, as the same undo step; names are letters, digits, spaces, `-` and `_`), Duplicate ("<name> copy", opened) and Delete (asks first, naming the controllers that play it; they keep the path, and report it missing when they run). Making a clip, renaming it, duplicating it and deleting it are each one undo step; undo of a delete restores the file, and the pickers and the Assets panel show it again without reopening the project. Saving does not clear those steps. The **preview** shows the model on a checkered floor (12×12 tiles a third of its height wide), drawn by its own `TextureRenderer` from its own `World`, through an orbiting camera (drag to turn, wheel to zoom), never the edited world or Play; the model is the clip's source if it has a skeleton the take moves, otherwise the first model in `assets/models` that does (the toolbar's model picker picks another). Above the **timeline** (`animation/timeline.rs`) are the frame and the time; the timeline shows the whole take with frame numbers, the clip's part of it with handles that drag its start and end, the playhead (click or drag to scrub; scrubbing pauses) and the events as diamonds (drag to move, right-click to remove), all on whole frames. The **settings**: name (rename), model, take (picking one resets the range to the whole take), start and end frames, Root motion (with a note when no bone moves across the ground), and the events (name, frame, remove; Add at playhead with a typed name); speed (−10 to 10; below 0 plays backwards) and Loop are in the toolbar. The preview plays the clip as the game will: its range, speed and loop, and with root motion on it stays in place. Changes are written to the file once the gesture ends (no mouse button held, nothing being typed), and before Play, on Save and when the project closes; they aren't undo steps (Revert puts back the file as opened). The **Assets panel** has an Animations category with clips and controllers; double-clicking (or dropping) a clip opens it in the Animation tab, and dropping a controller on a MeshPart sets its Animator's `Controller` (adding an Animator if it has none), as one undo step.
- **State machines in the Animation tab** (Phase 40, `animation/controller_editor.rs`, `animation/graph.rs`): Open ▾ lists the state machines (`*.statemachine.json` under `assets/animations`; ⋯ to rename, duplicate or delete, each one undo step), and New ▾ State machine… makes one in a folder of its own, `assets/animations/<name>/` (the new file is one undo step; giving it to the followed object's Animator stays a separate undo step): named after the followed object, with a state per clip in its folder (a MeshPart's model's, `assets/animations/<model>/`, or else `assets/animations/<name>/`; an Idle one, or else the first, as the default) if ticked, and given to its Animator (one undo step; an Animator is added if it has none) if ticked. Properties opens an Animator's state machine with the button beside `StateMachine`. An open controller shows its **state machine graph**, like Unity's Animator: states as boxes (the default state orange, each showing its clip), the Any State (teal), and transitions as arrows with a head halfway along (two-way pairs side by side; generated ones dashed; the one blending in the preview green). Drag a box to move it (positions are saved: `position`, and `any_state_position` once it's moved); drag the background, or with the middle button, to pan; the wheel zooms around the mouse. Click a box or an arrow to select it, the background for the controller's settings; Delete removes the selection. Right-click a box for Make Transition (then click the state it goes to; Escape cancels), Set as Default State, Rename and Delete (with its transitions); right-click the background to add an empty state or one playing a clip. The **inspector** shows the controller's default state and **parameters** (add Bool, Number or Trigger; rename, which renames them in conditions; defaults; remove), a state's name (renaming it renames it in transitions and as the default), clip, speed and transitions, or a transition's conditions (parameter, a test that fits its type, a value for Numbers), blend (a 0–2 s slider and Instant 0 / Smooth 0.25 / Slow 0.75), exit time (on/off and how much of the clip), interruptible and priority, with a warning when it can never happen. Under the graph, a **live preview**: the state machine running (its own `Machine` and parameters, not the game's) on a model (the Animator's MeshPart's, or the first clip's, or picked in the toolbar), with play/pause and restart (the default state and parameters again) in the toolbar, the state playing (also highlighted in the graph with its progress) and blend, and controls for every parameter: checkboxes for Bools, sliders for Numbers (from 0 to past the values their conditions test) and Fire for Triggers. Editing keeps it running where it was (only moving boxes doesn't rebuild it). With a transition selected, **Preview the blend** scrubs between its two states' poses, showing each one's share. **Return when** (Phase 42): a state's inspector has a Return when… setting: when (its clip finishes, a Bool becomes true or false, a Trigger is set, or some seconds pass), the Bool or Trigger, back to which state (the default state to begin with) and the blend.
