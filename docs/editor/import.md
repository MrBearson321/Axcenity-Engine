# Import and animation

Importing models and other assets (one Import…), and the Animation tab (the Animation window).

- **One Import…** (unified Phase 5, `app/files/import.rs`): **File > Import…**, **Import…** in the ribbon's Models group (Model tab, beside the Model Studio button), the Assets panel's Import and the empty Animation tab's Import… all open one file picker for every kind it imports (`EditorApp::import_with_dialog`): models (`.gltf`/`.glb`/`.fbx`/`.obj`, and USD, converted first), images, sounds and prefabs, several at once. Files dropped onto the editor window go the same way (`import_dropped`; images into `assets/textures`, or into the Assets panel's shown image folder when picked there). Each file is imported by its kind (`EditorApp::import_file`): a model through the Import dialog; images, sounds and prefabs straight in, with no dialog, reported in the Console and a toast. Models picked or dropped together open the dialog one after another (`import_queue`). The model is loaded first, so a file that can't be loaded is reported in the Console ("Could not import `…`: it isn't a valid glTF file: …") and nothing is copied or inserted. An asset package (`.axpkg`) opens the same dialog with one tab, **Package**, and no preview (`import_dialog/package.rs`): what's in it and what happens to each file (new, already in the project, or a clash and where it goes), and, when some files are already in the project with other contents, Keep both / Replace / Skip existing for all of them (see `docs/project/packages.md`). The summary says what Import adds and lists the clashes ("Adds 6 files: 5 clips, 1 state machine. 1 file already exists: Walk. Keep both puts the package's in `assets/animations/noodle2/`."); with nothing to add, Import is off and says why. Importing writes the files as one undo step (`History::record_blobs`, which keeps their bytes, so models and pictures come back too; "Import <package name>"). A replaced model file shows after the project is opened again, as with any changed model. Tests: `app/files/package_tests.rs`. Off during Play (a drop then says "Press Stop before importing files.") and with no project open. Test: `every_way_in_opens_the_same_dialog_for_a_model`.
- **Copying** (`assets::import_model`): a `.glb`, `.fbx` or `.obj` that uses no other files goes to `assets/models/<name>.glb` (or `.fbx`); a `.gltf`, or a model that uses other files, goes to its own folder, `assets/models/<name>/<name>.gltf` (or `.glb`, `.fbx`), with the `.bin` buffers and textures it uses at the same relative paths. An FBX texture that isn't found is left out, and reported in Output after the import. `<name>` is the file name with only letters, digits, spaces, `-` and `_` kept, plus a number if taken (`pyramid2`). Files the model uses must be inside its folder.
- **Model presets** (P7.3; `assets/src/model_presets.rs`, `import_dialog/settings.rs`, `app/files/model_presets.rs`): a **Preset** row above the dialog's tabs picks how a model comes in: **Default** (as before), **Static prop** (one MeshPart, Anchored, Hull collision), **Building kit** (a Model, welded, Anchored, PreciseConvexDecomposition) and **Character** (one MeshPart, Animator, Box), plus the project's own, which take a built-in one's place by name. Each says what it does on hover, and the row shows "(changed)" once a choice differs. A preset sets Bring in as (By file, A Model, Separate MeshParts, One MeshPart; only for a file with more than one object), Weld parts, Add an Animator, and the four choices on the new **Settings** tab (always last): **Scale** (every size and distance times it, about the insert point; 0.01 for a file in centimetres that doesn't say so), **Up axis** (Z turns a Z-up export a quarter round X), **Anchored** and **Collision** (each part's `CollisionFidelity`). **Save as preset…** keeps the current choices under a name in the project's `import-presets.json` (`"model_presets"`, beside the texture presets, `assets::presets_file_with_model_preset`; one undo step, "Save import preset …"). The dialog starts with the preset last used in the project (`.axcenity/model-preset.json`, this computer's), and a model with nothing to ask goes straight in with it too, as does an AI client's import. Tests: `app/files/model_preset_tests.rs`, `assets/src/model_presets.rs`.
- **USD** (P7.2, [ADR-0027](../../wiki/Architecture/Architecture-Decisions/ADR-0027-Convert-New-Model-Formats-To-glTF-On-Import.md); `app/files/convert.rs`, the `convert` crate): a `.usd`, `.usda`, `.usdc` or `.usdz` file is converted to a `.glb` of the same name before the Import dialog opens (`EditorApp::import_converted`, `axcenity_convert::convert`), and from there it's imported as that `.glb`, so the project only ever holds glTF and the player never reads USD. The stage is composed (sublayers, references, payloads, default variants; a `.usdz`'s files from inside it). Each `Mesh` under its `Xform` path is an object in the Objects tab with the same name; `metersPerUnit` and `upAxis` are applied (a 200 cm box is 2 studs); polygons are fanned into triangles and `leftHanded` meshes turned round; normals and the first `st`-like primvar are kept. `UsdPreviewSurface` materials (bound to the prim or to `GeomSubset`s) become metallic-roughness with their textures embedded: separate metallic and roughness maps packed into one, opacity into the color's alpha (`opacityThreshold` makes it a cut-out). What it leaves out is reported in Output as "Converting `Kitchen.usdz`: …" (prim types such as `Sphere`, lights and cameras; a texture that isn't there; UDIM textures; a material that isn't a UsdPreviewSurface, drawn in its display color; a layer that couldn't be read). The dialog's title and Output name the USD file, and the copy's sidecar notes it (`"converted_from": "Kitchen.usdz"`, `assets::note_converted_from`, in the import's undo step). A file that can't be read, or with no meshes, is reported and nothing is copied. Not converted yet: UsdSkel skeletons and animation (P7.6), instancing other than flattened copies. A dropped folder converts each USD file in it, layers included. Tests: `app/files/convert_tests.rs`, `crates/convert/src/usd/tests.rs`; `cargo run -p axcenity-convert --example usd_to_glb -- in.usdz out.glb` converts one by hand.
- **The MeshPart** (chosen by the developer: the file's materials, no Color or Material override) is inserted like a part: at the camera's focus point, inside the selected Model or Folder if any, named after the file (`pyramid`, `pyramid2`…), at its size in the file (1 glTF unit, or 1 meter in an FBX file, = 1 stud; a flat axis gets 0.001), and selected. The insert and the files the import copied and wrote (the model, its textures, its clips and its state machine) are one undo step (`History::record_blobs_and_tree`, "Import <name>"): it finds them by listing `assets/` before and after (`files_made_since` in `app/files/import.rs`; an import only makes new files, under free names, so files already there are never part of it). Undo removes them, and the folders that leaves empty (but not `assets/models` and the like); redo writes the same bytes back and puts the same Instances back, so nothing is copied twice. An animation-only file is one undo step the same way. Tests: `undoing_an_animated_fbx_import_removes_only_its_files_and_redo_brings_them_back`, `importing_a_model_copies_it_and_inserts_a_mesh_part_in_one_undo_step`.
- **The Import dialog** (`import_dialog.rs` and `import_dialog/`) opens before anything is copied for a file with more than one object, texture maps or animation (`ImportDialog::worth_asking`). Cancel, Escape or a click outside imports nothing.
  - **Tabs** (`Tab`, `import_dialog/tabs.rs`): under the title (what the file holds: objects, triangles, materials, skeleton, takes), tabs show only what the file needs, in order: **Objects** (the objects, then **Bring in as**; more than one object), **Materials** (the texture maps; any materials), **Animation** (animated). Each tab scrolls on its own and keeps its place. **Import** works from any tab with the choices as they are on all of them. A tab with a problem (nothing ticked; a clip problem) shows a warning sign, and Import is off with the reason beside it.
  - **Summary** (`ImportDialog::creates`, `Creates::sentence`): above Import and Cancel, one sentence says what Import creates and where, following every choice, such as "Creates: 1 MeshPart · 4 clips in `assets/animations/noodle/` · 1 state machine · an Animator. Copies the model to `assets/models/noodle.fbx`." or "Creates: 1 Model with 3 MeshParts and 1 Model for its groups. Copies the model and 1 texture to `assets/models/props/`." A test (`the_import_summary_matches_what_import_creates`) imports noodle.fbx and a three-object glTF and checks the counts and folders against what was made.
  - **Preview** (`import_dialog/preview.rs`): the model as loaded from the file (its own materials), on a checkered floor through the Animation tab's `Preview` (drag to turn, wheel to zoom), drawn from a private `Assets` holding that one model, so nothing is read twice and the project's assets aren't touched. An animated file plays the clip picked with ▶ on the Animation tab (the first to begin with), looping, as `Clip::bind` plays it in the game; play/pause is under it. After a map is changed it says the change shows once imported. An animation-only file shows a note instead.
  - **What you'll get** (`import_dialog/outcome.rs`): under the preview, the Instances the import makes as the Explorer will show them (`ImportDialog::made`: the Model and its group Models and MeshParts, or the MeshParts, or the one MeshPart with a SurfaceAppearance per material and its Animator; at most 12 rows, the last "… and N more"), where they go, and the files written (`files_made`: `assets/models/<name>/` with the model and its textures, or `assets/models/<name>.<ext>`; `assets/animations/<name>/` with its clips and state machine). It follows every choice.
- **Choosing objects** (Phase 18): the Objects tab lists the file's tree (groups as Models and meshes as MeshParts, with triangle counts and material names), all ticked; ticking a group ticks what's inside it, and a search box filters the rows (Select all/none then act on what's shown). Under them, **Bring in as** shows the three ways as cards, each saying what it makes and what it's for, with **Recommended** on One MeshPart for an animated file and on A Model otherwise (and a warning that each part gets its own Animator when an animated file isn't one MeshPart):
  - **A Model** (the default) named after the file, holding a MeshPart per object, placed as in the file around the camera's focus point. Groups in the file (nodes without a mesh) become Models inside it; an object inside one with a mesh goes next to it, since parts don't hold parts. Under the cards, **Weld parts** (Phase 35, off by default, `ImportDialog::weld`) welds every part of the Model to its largest the way the ribbon's Weld does (`constraints::weld_model`), in the import's undo step. Test: `a_model_imported_with_weld_parts_ticked_is_welded_to_its_largest_part`.
  - **Separate MeshParts**, each at the focus point.
  - **One merged MeshPart**, as for a single-object file (its `MeshId` names the ticked objects, or just the file if all are ticked).
  The file is copied once; every part's `MeshId` names its object in the copy (see `docs/project/world.md`). Each MeshPart is named after its object and sized to it. The whole insert is one undo step, and the last thing inserted is selected.
- **Texture maps on import** (Phase 21): the Materials tab lists each of the file's materials as a card that opens (the first open, all open with two or fewer): its name, how many maps, and a small picture of each. Open, it has a row for each map the material has (Color, Normal, Metalness, Roughness, Emission, Occlusion, Opacity, Specular, as found; see `docs/rendering/models.md`): a 36-point picture, what the map is (its tooltip says what it does), the file name, a channel dropdown for the grey maps, Replace (any PNG/JPEG/TGA/BMP, anywhere) and Remove. Only the settings for maps it has are shown (DirectX normals, glossiness-as-roughness, inverted opacity), and **Add map** lists the maps it doesn't have. Pictures of the model's own maps are shrunk from its decoded images; a picked file is read once. The file is loaded once from where it is (`assets::load_model_file`) to find them; `editor/src/surface.rs` holds them as `MaterialMaps`.
- **Fits the window** (v3 Phase 6): the dialog is at most 960 points wide and never taller than the window, keeping 16 points from its edges; its body is at most 560 points tall. From 700 points wide the preview and What you'll get are a column at the left (320 points) and the tab scrolls on its own at the right (both ways, so the clips table never widens the dialog); narrower, the preview, the tab and What you'll get scroll together. The summary, Import and Cancel are pinned under it (the summary's height is measured), so they can be reached in any window size. Heights are worked out, not taken from `available_height`, which in a modal grows with last frame's size. A drawing test (`the_whole_dialog_fits_an_800_by_600_window_with_import_clickable`) opens noodle.fbx with every tab in an 800×600 window, clicks each tab in the tab bar and then Import; with `AXCENITY_SNAPSHOTS` it saves `import-dialog-800x600-<tab>.png`.
- **SurfaceAppearances on import:** every new MeshPart gets one SurfaceAppearance child per material its model uses, named after the material (`MaterialName` set), with the maps as in the dialog. The model's own textures are paths into the copy's folder (embedded ones are copied out to its `textures` folder on import); files picked in the dialog are copied into that `textures` folder too, once each, under a free name. They're part of the insert's undo step.
- **Maps in Properties:** a SurfaceAppearance shows Appearance (`Color`), Surface (`MaterialName` and the eight maps) and Map Settings. A map shows its file name (full path on hover), a Browse button and a Clear button; it can't be typed, as each half-typed path would be loaded. Browse returns `Edit::PickTexture`, and the app asks for a file: one inside the project keeps its path, one outside is copied into `assets/textures` first (`assets::import_texture`). The change is one undo step, and the viewport shows it on the next frame.
- It moves, scales, rotates, duplicates, saves and reloads like a Part. Picking, the selection box, handles and drag-to-place all use its box (the model fills it). `MeshId` shows in Properties under Part but is read-only (importing sets it). Explorer icon: a see-through cube, part blue.
- **Animated FBX files** (Phase 38, `anim_import.rs`): a file whose model has a skeleton (or whose objects a take moves), or that has takes, opens the dialog with an **Animation** tab: the skeleton's bone tree and joint count, each take with its frames, frame rate and the bones it moves, and a table of **clips to make** (▶ to play it in the preview, name, take, start and end frame, loop), one per whole take to begin with. Add clip adds a row; Split replaces a take's rows with N equal parts ("Moves 1", "Moves 2"…), so one long take becomes Idle, Walk and so on. A clip of a file's only take with a meaningless name ("Take 001", "mixamo.com") is named after the file; Blender's `Armature|` prefix is dropped. Names must be unique (ignoring case) and each clip must end after it starts, or Import is off. An animated file comes in as one MeshPart by default. Importing writes each clip to `assets/animations/<model>/<name>.anim.json` and, with "Add an Animator" ticked (the default), a state machine `assets/animations/<model>/<model>.statemachine.json` (beside its clips; a controller in `assets/animations` before v3 Phase 7) with a state per clip (one named Idle, or else the first, as the default state, at the left of the graph; the rest in rows of four), and gives every new MeshPart with a skeleton an Animator playing it, with an Animation per clip under it (named after the clip, `Clip` set, AutoPlay off; v3 Phase 8), as part of the insert's undo step (with the files, see above). A name already taken gets a number. A file with takes but nothing to draw (an animation exported "without skin") imports as clips only: the file is copied to `assets/models` and its clips are written, for a model with the same skeleton.
- **Animators** (Phase 38): Insert ▸ Animator (Explorer menu) puts one in the selected MeshPart, with a warning if there isn't one. Properties shows its Animation group: `StateMachine` (a Browse button that picks a `.statemachine.json` inside the project, and a Clear button; `Controller` before v3 Phase 7), `Enabled` and `Speed`; an Animation shows `Clip`, `AutoPlay`, `Enabled`, `Speed` and `Looped`. Dropping a state machine from the Assets panel onto a Part or MeshPart gives it an Animator playing it. Since v3 Phase 7 the editor says "state machine" where it said "controller" (code names such as `ControllerDoc` still say controller). Animators only play during Play (each Play makes a fresh `anim::Animators`, primed before the scripts start, run after Heartbeat; its problems go to Output once each); while editing, models show their bind pose.
- **Property Animation**: Insert ▸ Animation puts an `Animation` in the selected Part, MeshPart, Model, ScreenGui or frame. Properties: `Clip` (a `.anim.json` with `"kind": "property"`), `Enabled`, `Speed`, `Looped`. The Animation tab's New ▸ Keyed clip… makes an empty clip to key in its preview (below); Animate does it in one step. Hosts run `anim::PropertyPlayers` beside `Animators` after Heartbeat.
- **One Animation window** (v3 Phase 8, `animation.rs`; Phase 4 had an Animation tab and an Animator tab): one dock tab beside the Scene (View > Panels opens it there again; a saved layout's old Animator tab loads as it). A clip and a state machine can be open at once; the tab shows one of them.
  - **It follows the selection** (`Subject`, `animatable_of`): the selected Part, MeshPart, Model, ScreenGui or UI element, or the parent of a selected Animator or Animation (an Animation under an Animator stands for the Animator's parent). Selecting another object that has an Animator opens its state machine, or else its first Animation's clip. Selecting something inside the followed object keeps it (so a Door's Hinge can be picked for its preview); selecting an Animation of it opens that Animation's clip. Selecting another object with no Animator follows it with nothing open, ready for Animate. A clip opened from the Assets panel (double-click or drop) opens **on its own**, following nothing, until something with an Animator is selected; it previews on the model picked with **Preview on…** (a take clip), or on what's selected (a keyed clip).
  - **Outline** (left; wider than 720 points): the object's name, then its Animator; its **State Machine**, with each state and the clip it plays (and that clip's badge); and its **Animations**; the State Machine's states and the Animations each fold with a ▸/▾ (unified Phase 8a) (under the Animator, then beside it on the object), each with its clip's badge; then **+ New Animation**, which animates it again (another clip and Animation). Clicking the State Machine shows its graph, inspector and live preview; clicking a state or an Animation opens its clip. An object with no Animator shows **Animate <name>** instead. Narrower than 720 points the outline drops down from the breadcrumb's first crumb.
  - **Breadcrumb** (top): where you are, such as **Hero ▸ State Machine ▸ Walk**, **Door ▸ DoorOpen** (an Animation) or **Hero ▸ State Machine**; a clip or state machine that isn't the followed object's shows just its own name. Double-clicking a state in the graph (`GraphEvent::Open`) opens its clip (a blend tree's first) under the state machine; clicking **State Machine** in the breadcrumb goes back up to the graph. Beside it: the open clip's badge, **Open ▾** (every state machine and clip, grouped by folder, searchable, each with a ⋯ for Rename, Duplicate and Delete; the pickers before Phase 8) and **New ▾** (Keyed clip…, Clip from a take…, State machine…).
  - **Icons and colours** (`theme::AnimKind`): Animator (running figure, green), State Machine (flow arrow, orange), Animation (film slate, teal) and clip (film strip, violet), the same in the outline, the breadcrumb, the Explorer, the Assets panel and Open ▾. A clip's **badge** says **Linked to noodle.fbx · Walk** (a clip linked to a take) or **Keyed**; in the outline's rows a linked clip's badge is just the take (**🔗 Walk**, the whole badge on hover), so the file isn't repeated under every state. A property clip's drawer leaves out the Animator and Animation Instances unless a track keys them.
  - **Animate** (the empty tab's button, the Explorer's right-click menu and the top of Properties, for any object that can animate; `EditorApp::animate`): one undo step (`History::record_files_and_tree`) that adds an Animator if the object has none, writes a keyed clip to `assets/animations/<name>/<name>.anim.json` (a number added if taken), and puts an Animation named after the clip, playing it, in the Animator. The tab then follows the object and opens the clip with **Record** on. Tick AutoPlay on the Animation (Properties) to play it when Play starts. With nothing open and nothing animatable selected, the tab shows only Import….
  - **Clips**, top to bottom: a toolbar (for a take clip Loop, Speed, **Preview on…** the model and **Record**; for a keyed clip Loop, what the preview shows a copy of ("Preview on Door") and **Record**; then buttons that show or hide the drawer and the inspector, and a ⋯ menu with Rename, Duplicate and Delete, and for a linked clip **Convert to keys**); the preview, with a **drawer** on its left listing the preview model's bones as a tree (those the take moves locked, 🔒; the rest selectable, with their key counts) or a property clip's objects and their tracks, and under a skinned MeshPart its bones (click one to select it); a bone tree folds (unified Phase 8a, `posing::Folds`): a bone with bones under it has a ▸/▾, Collapse all and Expand all sit in the drawer's header, a tree opens with its first three levels showing, a folded bone shows a dot when a bone under it has keys, and folds are kept per model (`MeshId`) while the editor runs, whichever clip is open (tests: `a_mixamo_rigs_bone_tree_folds_unfolds_and_collapses_to_its_root`, `a_bone_tree_stays_folded_as_it_was_when_switching_clips`); the **transport** (`animation/transport.rs`, both kinds of clip through its `Playback` trait: go to the start, back a frame, play/pause/resume (play at the end starts over), on a frame, go to the end, Stop (pause and back to the start), the playhead's time, a seek bar, the length, the frame number, and the preview's rate, 0.25× to 4×, kept while the editor runs and never saved; below 480 points it takes two rows; its keys, with the mouse over the clip and no text, menu or tabbed-to widget taking them (`wants_transport_keys`), are Space, Left/Right a frame, Shift+Left/Right ten, Home and End, taken before the clip's widgets draw; tests `transport::tests`, `app/animation_tests.rs`), then the **timeline** (and, for a linked clip, its imported keys under it) or a property clip's dope sheet, in a resizable panel docked along the bottom; and the clip's **settings** in the inspector on the right. Narrower than 560 points it stacks: the preview, the drawer and Settings as collapsible sections, and the timeline, scrolling together.
  - **Record and unkeyed moves** (usability pass, `clip_ui.rs` `key_status` and `recording_frame`): while **Record** is on, a red frame goes round the preview and a red line above the timeline says "Recording: moving something in the preview sets a key at 0.50 s"; an empty dope sheet then says to just move something ("Record keys it") rather than press K. With Record off, a move or turn that isn't keyed yet (`PropertyDoc::unkeyed`, `ClipDoc::unkeyed`) shows an amber "Not keyed yet: moving the playhead or pressing play drops this change." with **Key it (K)**, which keys it as K does. Nothing about when moves are keyed or dropped changed. Test: `recording_and_unkeyed_moves_are_said_above_the_timeline` (`app/tests.rs`).
  - **Retargeting** (AP3, `animation/retarget_panel.rs`), under a linked clip's settings: a line saying how the take plays on the preview model (by bone names; retargeted through humanoid roles, with or without its profile; by names because the skeletons can't be retargeted, so its profile isn't used; or why it can't play), then, when the take goes through roles, what `check_rig` (the model's and the take's skeletons) and `check_pair` (both) found, worst first, each with Model, Take or Both. **Model's bone map…** and **Take's bone map…** open a window listing every role (Body open; Left and Right fingers folded; the 15 required ones in full text) with a list of the skeleton's bones beside each, `(none)` first; picking a bone another role had takes it from that role. Its own errors and warnings show above, **Match by names** starts again from the names, and **Save** writes the map as a rig definition: the definition that fits the skeleton now, else `assets/rigs/<file>.rig.json` (`BoneMap::definition` writes every role's bone, and `""` for a role names would give a bone but the map gives none), then makes `Assets` read the definitions again and binds the preview again. **Profile** picks the clip's retarget profile: None (defaults), any `assets/rigs/**/*.retarget.json`, or **New profile** (`assets/rigs/<clip>.retarget.json`, made with the defaults; `<clip> 2` and on when taken). A picked profile's settings follow: Match rest poses, Hips (Scaled to the legs, As in the take, In place), Plant feet, Match hands, Fingers, and **Single bones** (each body role's weight and X/Y/Z offset in degrees, Reset single bones). Each change is written to the profile file at once (it's shared by every clip that names it; not an undo step) and the preview binds again; picking a profile changes the clip's link, saved and undone like any clip change. The preview, Convert to keys and the imported keys bind the take as Animators do (`ClipDoc::bind_on`: the project's rig definitions and the clip's profile), so Convert to keys on a retargeted clip bakes the retargeted motion onto the model's own bones (`anim::convert_to_keys_with`) and the bones retargeting moves are the locked ones. Tests: `retarget_panel_tests.rs`, and `convert_to_keys_bakes_the_retargeted_motion_onto_the_models_own_bones` (`anim`).
  - **Keying Parts, Models and UI** (v3 Phase 5, `animation/object_preview.rs`, `animation/property_editor.rs`): a keyed clip's preview shows a **copy** of the followed object (or, for a clip opened on its own, of the Part, Model, ScreenGui or UI element selected in the Explorer; an Animation stands for its parent), in a world of its own taken with `World::clone` (so ids match): alone on a floor, or for a UI element its whole ScreenGui, laid out flat with the project's stylesheets. The edited world is never changed. The copy stays when something outside it is selected; selecting something inside it selects it in the preview; ↻ in the toolbar copies it again after editing the world. Click a part or UI element in the preview (or an object in the drawer) to select it. 3D: Move, Rotate and Resize buttons above the preview pick the handles (snapping 1 stud and 15°); a Model's handles move its pivot (no Resize); dragging elsewhere turns the camera, and the wheel zooms. UI: the element's eight handles (as in the Scene View, ignoring CSS sizes) move and resize it. A move with **Record** on sets keys at the playhead (making tracks as needed). With Record off it shows only until the playhead moves, and **Key selected** (K) keys it: the object's tracks, its moves, and where it is (Position and Orientation, or a UI element's Position and Size). Add track lists the selected object's keyable properties and keys its current value. **New keys** (unified Phase 8b, `property_editor::NewKeys`), in the dope sheet's toolbar (and beside a linked clip's Convert to keys, for the bones it can key), is the easing new keys get from Record, K, posing and Add track: **Smooth** (Ease InOut, Sine; the default), **Linear** or **Constant**. It's kept from clip to clip while the editor runs. Keying over a key at the same time changes its value and keeps its easing; existing clips aren't changed. Right-clicking selected keys (in the dope sheet or Curves; a key that isn't selected is selected alone first) has **Easing ▸**: Smooth, Linear, Constant, Ease In/Out/InOut with any style, and Bezier, for all of them at once (`PropertyDoc::ease_selected`); like any keyed-clip edit it's an undo step.
