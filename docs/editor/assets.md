# Asset browser

The Assets panel, props, prefabs, and drag-and-drop.

- **The Assets panel** (`asset_browser.rs`) shares the bottom of the window with Output, switched by tabs above them. It shows category chips (All, Props, Models, Prefabs, Images, Textures, Audio, Particles), a search box (matches the path), Get texture, Import, Save prefab and a refresh button. Tiles show a thumbnail for images and an icon otherwise. Thumbnails are read and shrunk (to 192 px, each pixel the average of the block it covers) on three background threads (`asset_browser/thumbnails.rs`), only for tiles on screen; a tile shows its icon until its thumbnail arrives. Hovering a picture tile shows it up to 192 px with its path. **Narrow and wide** (v3 Phase 3): narrower than 360 points the panel is a list (a 24-point picture, the name ending in "…", and the kind at the right from 200 points), with the same drag, double-click, tooltip and prefab menu as a tile; wider, it's tiles. From 980 points the chips, search and buttons share one row; below that the search gets its own row (with Get texture, Import and Save prefab beside it from 520 points, otherwise on a row of their own) and the chips wrap under it.
- **Finding files**: the project's `assets` folder is walked again every 2 s while the panel is shown (hidden folders skipped). Kinds come from the extension and folder: models (`.gltf`, `.glb`, `.fbx`), prefabs (`*.prefab.json`), sounds, and images: particle textures in `assets/particles`, textures in `assets/textures` or `assets/models`, UI images elsewhere. A `*.texture.json` file is one texture set (shown under Textures, with its color map as the thumbnail); the images in that set's folder are not listed again.
- **Asset Check** (v2 Phase 7; `project::check_assets`, `asset_check.rs`): File > Check Assets, Test ▸ Check Assets, the Console `check` command, or the panel's button scans the open project and lists missing files, invalid references, import failures, and broken dependencies in one place, each with the Instance or asset file that holds the reference. A clean project says so. The scan does not write or delete files. A missing model still leaves the rest of the project open; this list is how those problems are seen together. The panel starts closed and opens when a check runs (View > Panels shows it). Exported games have no Asset Check.
- **Built-in props** (`props.rs`): Floor, Wall, Stairs, Ramp, Lamp, Table, Tree and Crate, each prefab text in the source, so they work in any project.
- **Placing**: dragging a tile sets an egui drag-and-drop payload; the viewport reports where it would land (`DropTarget`: the surface under the mouse, else the ground plane, else the camera's focus) with a blue marker, and the app places it on release. Double-clicking a tile places it at the focus point. While the Terrain Studio's Foliage tool is on, clicking a prop or model tile selects it as the paint item instead of placing it (see `docs/terrain.md`). Models, prefabs and props go in the Workspace and are moved as a whole so their world bounding box rests against the surface (snapped to the move grid across it); a model becomes a MeshPart named after its file (no SurfaceAppearances: the file's own materials). A sound becomes a Sound in the part under the mouse, or the Workspace. An image sets the `Image` of the ImageLabel or button under the mouse, otherwise inserts an ImageLabel showing it. A texture sets `ColorMap` on every SurfaceAppearance of the MeshPart under the mouse. A texture set fills every map it has: on a Part (creating a SurfaceAppearance if it has none, and setting the part's `Material` to Plastic and, when the set has a color map, its `Color` to white), on every SurfaceAppearance of a MeshPart (or one new appearance per material name when it has none), or on the top TerrainLayer of a terrain (including `HeightMap`; a selected TerrainLayer is filled itself; and that layer's settings are set to suit its maps, `auto_layer_settings` in `app/texture_set.rs`: roughness 1 with a roughness map and 0.9 without, metalness 1 with a metalness map and 0 without, normal strength 1). Dropping uses the part under the mouse; double-clicking fills the selection. That apply is one undo step. Downloading a set is not. Each placement is one undo step, and the result is selected. The maps are set at once; their images load in the background (see `docs/rendering/models.md`), so the window keeps responding and the textures appear as each finishes, with a "Loading textures 2 of 5: …" note and bar in the bottom-right corner (`toast::Busy`) until they are all in.
- **Terrain layers from project textures** (`terrain_studio/layers.rs`): an open layer in the Terrain Studio has **Use texture set**, a menu of the project's texture sets with thumbnails (`AssetBrowser::textures`; a search box from 7), which fills every map of that layer as one undo step (`TerrainAction::UseTextureSet`, the same apply as a drop). Each map's folder button is a menu of the project's textures, with **Browse files…** at the bottom for a file outside the project. Dragging a texture set from the Assets panel onto a layer's row or its open card fills that layer, and dragging a texture onto one map's row sets that map; the target is outlined while one is held over it. The project's textures are only looked up while a layer is open. Each layer in the list shows its color map's thumbnail, tinted by its `Color` (the color with an image icon until the thumbnail is read), and the open layer shows each map's thumbnail beside its file name (`StudioContext::pictures`). A layer's Roughness and Metalness scale its map when it has one (the slider says "× map"; 1 is the map as it is), as the terrain shader multiplies them, and are the value itself without one. **Auto settings** puts back what suits the layer's maps, as one undo step (`TerrainAction::AutoLayerSettings`).
- **Get texture** (`ambient_cg.rs`): searches ambientCG's public catalog (`GET https://ambientcg.com/api/v2/full_json`, `type=Material`, no API key) and downloads one resolution into `assets/textures/<AssetId>/` with `<AssetId>.texture.json`. The default package is 2K JPG; 1K, 4K and 8K, JPG or PNG, are choices. If that exact package is missing, the dialog says so and does not substitute another. Map files are classified by the same name rules as model textures (`_Color`, `_NormalGL`, `_NormalDX`, `_Roughness`, `_Metalness`, `_AmbientOcclusion`, `_Displacement`, and the emission, opacity and specular names). When both normal maps are present, the set uses NormalGL and leaves `NormalMapDirectX` off. The zip is written to disk before it is extracted, paths that escape the folder are rejected, and non-images are skipped. Getting the same asset again replaces that folder. Results show as soon as the catalog answers, as a grid of cards (preview, name, category and maps, Get); the 256 px previews are then fetched six at a time over one shared connection pool and kept for the dialog's life, so a repeated search shows them at once. Hovering a card shows the preview at full size. The download runs on a background thread; closing the dialog discards a download that has not been moved into the project. Failure (offline, no such package, disk) is reported in Output. Saved files are CC0, record the asset id and `shortLink`, and work offline in the editor and the player. The player does not depend on the download crates (`ureq`, `zip`).
- **Prefabs**: Save prefab writes the selected Workspace parts, Models and Folders (not scripts or UI) to `assets/prefabs/<name>.prefab.json` (`project::write_prefab`; a number is added if taken), as one undo step. A prefab tile's right-click menu renames, duplicates or deletes that file, each as one undo step; undo of a delete restores the file's contents and the tile without reopening the project. Saving does not clear these steps. Import copies models (through the Import Model dialog), sounds (`assets/audio`), images (into the folder of the shown category: `assets/textures`, `assets/particles` or `assets/images`) and prefab files (checked first) into the project.
- **Multi-Instance undo**: `History::record_many` (through `EditorApp::change_many`) records changes to several Instances as one step, merging while the same field of the same Instances is edited.
