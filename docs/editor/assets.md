# Asset browser

The Assets panel, props, prefabs, and drag-and-drop.

- **The Assets panel** (`asset_browser.rs`) shares the bottom of the window with Output, switched by tabs above them. It shows category chips (All, Props, Models, Prefabs, Images, Textures, Audio, Particles), a search box (matches the path), Import, Save prefab and a refresh button. Tiles show a thumbnail for images (scaled to 96 px, nearest pixel) and an icon otherwise.
- **Finding files**: the project's `assets` folder is walked again every 2 s while the panel is shown (hidden folders skipped). Kinds come from the extension and folder: models (`.gltf`, `.glb`, `.fbx`), prefabs (`*.prefab.json`), sounds, and images: particle textures in `assets/particles`, textures in `assets/textures` or `assets/models`, UI images elsewhere.
- **Built-in props** (`props.rs`): Floor, Wall, Stairs, Ramp, Lamp, Table, Tree and Crate, each prefab text in the source, so they work in any project.
- **Placing**: dragging a tile sets an egui drag-and-drop payload; the viewport reports where it would land (`DropTarget`: the surface under the mouse, else the ground plane, else the camera's focus) with a blue marker, and the app places it on release. Double-clicking a tile places it at the focus point. Models, prefabs and props go in the Workspace and are moved as a whole so their world bounding box rests against the surface (snapped to the move grid across it); a model becomes a MeshPart named after its file (no SurfaceAppearances: the file's own materials). A sound becomes a Sound in the part under the mouse, or the Workspace. An image sets the `Image` of the ImageLabel or button under the mouse, otherwise inserts an ImageLabel showing it. A texture sets `ColorMap` on every SurfaceAppearance of the MeshPart under the mouse. Each placement is one undo step, and the result is selected.
- **Prefabs**: Save prefab writes the selected Workspace parts, Models and Folders (not scripts or UI) to `assets/prefabs/<name>.prefab.json` (`project::write_prefab`; a number is added if taken), as one undo step. A prefab tile's right-click menu renames, duplicates or deletes that file, each as one undo step; undo of a delete restores the file's contents and the tile without reopening the project. Saving does not clear these steps. Import copies models (through the Import Model dialog), sounds (`assets/audio`), images (into the folder of the shown category: `assets/textures`, `assets/particles` or `assets/images`) and prefab files (checked first) into the project.
- **Multi-Instance undo**: `History::record_many` (through `EditorApp::change_many`) records changes to several Instances as one step, merging while the same field of the same Instances is edited.
