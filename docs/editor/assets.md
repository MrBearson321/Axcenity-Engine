# Asset browser

The Assets panel, props, prefabs, and drag-and-drop.

- **The Assets panel** (`asset_browser.rs`) shares the bottom of the window with Output, switched by tabs above them. It shows category chips (All, Props, Models, Prefabs, Images, Textures, Audio, Particles, Animations, Skies, Global), a search box (matches the path), Get texture, Import, Save prefab and a refresh button. Tiles show a thumbnail for images and an icon otherwise. Thumbnails are read and shrunk (to 192 px, each pixel the average of the block it covers) on three background threads (`asset_browser/thumbnails.rs`), only for tiles on screen; a tile shows its icon until its thumbnail arrives. Hovering a picture tile shows it up to 192 px with its path. **Narrow and wide** (v3 Phase 3): narrower than 360 points the panel is a list (a 24-point picture, the name ending in "…", and the kind at the right from 200 points), with the same drag, double-click, tooltip and prefab menu as a tile; wider, it's tiles. From 980 points the chips, search and buttons share one row; below that the search gets its own row (with Get texture, Import and Save prefab beside it from 520 points, otherwise on a row of their own) and the chips wrap under it.
- **Finding files**: the project's `assets` folder is walked again every 2 s while the panel is shown (hidden folders skipped). Kinds come from the extension and folder: models (`.gltf`, `.glb`, `.fbx`), prefabs (`*.prefab.json`), sounds, and images: particle textures in `assets/particles`, textures in `assets/textures` or `assets/models`, UI images elsewhere. A `*.texture.json` file is one texture set (shown under Textures, with its color map as the thumbnail); the images in that set's folder are not listed again. A `*.material.json` file is a material (shown under Textures, with a sphere icon; `docs/rendering/models.md`). An `.exr` or `.hdr` file anywhere is a sky (shown under Skies, with a sun icon; its thumbnail is rolled off toward white so the sun doesn't wash it out).
- **Imported models are folders** (`asset_browser/packages.rs`): each model in `assets/models` (in a folder of its own, or a file on its own) is a package holding every file in its folder and in `assets/animations/<name>/` (matched ignoring case), when that's more than one file. The grid shows the props, then a folder tile per package (a folder with the model's icon and a count of its files; "Folder · N" in the list) for any package holding something the category shows, then the files in no package. Hovering says what's in it ("1 model, 1 clip, 1 state machine, 25 textures"); a click opens it, and dragging it places its model like the model's own tile. Open, a row above the files has **All assets** (back), the folder's name and what's in it, and its files are under Model, Animation and Textures headings (the category still filters them). A search shows every matching file on its own, in or out of a folder. A folder that's gone closes.
- **Global assets** (`global_assets.rs`): a library of assets shared by every project on the computer, in the editor's data folder (`eframe::storage_dir("Axcenity Editor")/Global Assets`; on Windows `%APPDATA%\Axcenity Editor\data\Global Assets`). The library mirrors a project: its files sit under `assets/` at the paths they have in a project, so an asset is global when the library has a file at its path. Assets are local by default. Any tile's or folder tile's right-click menu has a **Global asset** checkbox (not on built-in props); ticking it copies the asset's own files (an imported model's folder and its `assets/animations/<name>/` folder, a texture set's folder, or the one file) and every file its JSON names (a prefab's models, a glTF's buffers and images; only paths under `assets/`) into the library, replacing older copies. Unticking deletes only its own files from the library; projects that used it keep their copies, and files it merely needed stay global. Global assets have a globe badge, and the **Global** chip shows only them. Every project's panel lists the library's assets it hasn't got beside its own (thumbnails read from the library). Using one (placing, dropping, a foliage pick, a terrain layer's texture or texture set) first copies what it needs into the project at the same paths, never replacing a file the project has, and says so in Output. So projects stay self-contained: the player and exported games never read the library. The start screen's Global Assets page lists the library (see `docs/editor/shell.md`).
- **Asset Check** (v2 Phase 7; `project::check_assets`, `asset_check.rs`): File > Check Assets, Test ▸ Check Assets, the Console `check` command, or the panel's button scans the open project and lists missing files, invalid references, import failures, and broken dependencies in one place, each with the Instance or asset file that holds the reference. A clean project says so. The scan does not write or delete files. A missing model still leaves the rest of the project open; this list is how those problems are seen together. The panel starts closed and opens when a check runs (View > Panels shows it). Exported games have no Asset Check.
- **Fixing what Asset Check finds** (unified Phase 22; `project::plan_fix` in `project/src/asset_fix.rs`, made by `app/asset_fixes.rs`): each finding knows where its reference is written (`Site`: an Instance's property, a prefab's property by its place in the file, a linked clip's source, a state's clip, a data table's cell (Phase 33, [../project/data-tables.md](../project/data-tables.md)), a texture a model names, or a file that fails on its own) and what kind of file it wants. Its row offers what suits it: **Use `<name>`** when the project has a file of the right kind with that name elsewhere (the one sharing the most leading folders, then the shortest path; a model's `#` pick is kept when the file name is the same); **Copy in** for a reference that's a full path to a real file outside the project; **Locate…** (a file dialog; a file outside the project is copied to the folder Import uses for its kind: `assets/models`, `assets/audio`, `assets/animations`, `assets/images` for an `Image`, `assets/particles` for a `Texture`, otherwise `assets/textures`, with a number added if a different file has the name; a `.gltf` from outside is refused, since it needs its other files, so import it); **Replace…** (a menu of the project's files of that kind); **Clear** (empties the reference; a linked clip whose model is gone is unlinked); **Delete file** for a file that fails on its own; and **Ignore**. A model's missing texture is fixed by copying the picked image to `textures/<name>` next to the model, where the model looks (it must have the extension the model asks for). **Apply to all like this (N more)** appears when other shown findings have the same path and kind ("isn't there" counts as one kind, whether the world or an asset names it); ticked, the fix covers them all. A fix is one undo step (`History::record_blobs_and_properties`: the properties set and the files rewritten, copied or deleted, by their bytes), the model cache forgets what changed (`Assets::forget`, `forget_failures`), and the check runs again. Fixes are off during Play. **Ignore** saves the finding (kind, owner, path, message) in `.axcenity/asset-check.json`, which isn't an undo step; ignored findings aren't counted, **Show ignored (N)** lists them dimmed with **Unignore**. Planning a fix writes nothing; a failed plan says why in Output.
- **Built-in props** (`props.rs`): Floor, Wall, Stairs, Ramp, Lamp, Table, Tree and Crate, each prefab text in the source, so they work in any project.
- **Placing**: dragging a tile sets an egui drag-and-drop payload; the viewport reports where it would land (`DropTarget`: the surface under the mouse, else the ground plane, else the camera's focus) with a blue marker, and the app places it on release. Double-clicking a tile places it at the focus point. While the Terrain Studio's Foliage tool is on, clicking a prop or model tile selects it as the paint item instead of placing it (see `docs/terrain.md`). Models, prefabs and props go in the Workspace and are moved as a whole so their world bounding box rests against the surface (snapped to the move grid across it); a model becomes a MeshPart named after its file (no SurfaceAppearances: the file's own materials). A sound becomes a Sound in the part under the mouse, or the Workspace. An image sets the `Image` of the ImageLabel or button under the mouse, otherwise inserts an ImageLabel showing it. A texture sets `ColorMap` on every SurfaceAppearance of the MeshPart under the mouse. A texture set fills every map it has: on a Part (creating a SurfaceAppearance if it has none, and setting the part's `Material` to Plastic and, when the set has a color map, its `Color` to white), on every SurfaceAppearance of a MeshPart (or one new appearance per material name when it has none), or on the top TerrainLayer of a terrain (including `HeightMap`; a selected TerrainLayer is filled itself; and that layer's settings are set to suit its maps, `auto_layer_settings` in `app/texture_set.rs`: roughness 1 with a roughness map and 0.9 without, metalness 1 with a metalness map and 0 without, normal strength 1). Dropping uses the part under the mouse; double-clicking fills the selection. That apply is one undo step. Downloading a set is not. A sky, dropped anywhere in the viewport or double-clicked, asks "Use *name* as the sky?" (`app/sky.rs`) and only then sets Lighting's `SkyImage`, as one undo step with a toast; the box says when the editor's Reflection quality is Low, which shows the sky colors instead. A material file sets the `MaterialVariant` of the Part or MeshPart under the mouse (double-clicking: of every selected one) and a Part's `Color` to white, since the material carries its color (`app/material_files.rs`), as one undo step. Each placement is one undo step, and the result is selected. The maps are set at once; their images load in the background (see `docs/rendering/models.md`), so the window keeps responding and the textures appear as each finishes, with a "Loading textures 2 of 5: …" note and bar in the bottom-right corner (`toast::Busy`) until they are all in.
- **Terrain layers from project textures** (`terrain_studio/layers.rs`): an open layer in the Terrain Studio has **Use texture set**, a menu of the project's texture sets with thumbnails (`AssetBrowser::textures`; a search box from 7), which fills every map of that layer as one undo step (`TerrainAction::UseTextureSet`, the same apply as a drop). Each map's folder button is a menu of the project's textures, with **Browse files…** at the bottom for a file outside the project. Dragging a texture set from the Assets panel onto a layer's row or its open card fills that layer, and dragging a texture onto one map's row sets that map; the target is outlined while one is held over it. The project's textures are only looked up while a layer is open. Each layer in the list shows its color map's thumbnail, tinted by its `Color` (the color with an image icon until the thumbnail is read), and the open layer shows each map's thumbnail beside its file name (`StudioContext::pictures`). A layer's Roughness and Metalness scale its map when it has one (the slider says "× map"; 1 is the map as it is), as the terrain shader multiplies them, and are the value itself without one. **Auto settings** puts back what suits the layer's maps, as one undo step (`TerrainAction::AutoLayerSettings`).
- **Get texture** (`ambient_cg.rs`): searches ambientCG's public catalog (`GET https://ambientcg.com/api/v2/full_json`, `type=Material`, no API key) and downloads one resolution into `assets/textures/<AssetId>/` with `<AssetId>.texture.json`. The default package is 2K JPG; 1K, 4K and 8K, JPG or PNG, are choices. If that exact package is missing, the dialog says so and does not substitute another. Map files are classified by the same name rules as model textures (`_Color`, `_NormalGL`, `_NormalDX`, `_Roughness`, `_Metalness`, `_AmbientOcclusion`, `_Displacement`, and the emission, opacity and specular names). When both normal maps are present, the set uses NormalGL and leaves `NormalMapDirectX` off. The zip is written to disk before it is extracted, paths that escape the folder are rejected, and non-images are skipped. Getting the same asset again replaces that folder. Results show as soon as the catalog answers, as a grid of cards (preview, name, category and maps, Get); the 256 px previews are then fetched six at a time over one shared connection pool and kept for the dialog's life, so a repeated search shows them at once. Hovering a card shows the preview at full size. The download runs on a background thread; closing the dialog discards a download that has not been moved into the project. Failure (offline, no such package, disk) is reported in Output. Saved files are CC0, record the asset id and `shortLink`, and work offline in the editor and the player. The player does not depend on the download crates (`ureq`, `zip`).
- **Export Package…** (unified Phase 6; `app/files/packages.rs`, format in `docs/project/packages.md`): a click picks a tile and Ctrl/Cmd+click adds or removes one (picked tiles are filled and outlined). A project tile's right-click menu has Export Package…, for the picked assets if it's one of them ("Export Package… (3 assets)", named Package) or else just that one (named after it); a model folder's menu exports every file in it. It asks where to save `<name>.axpkg`, writes the files and everything they need, and says in the Console how many went in and what they needed that isn't in the project. Global assets not copied into the project have no Export Package…. Explorer rows have Export Package… too, for parts, Models and Folders in the Workspace (`tree::can_be_prefab`): the object goes in as a prefab.
- **Deleting assets**: a project tile's or folder tile's right-click menu has **Delete…** (not during Play, not on built-in props or global assets the project hasn't got). Like Export Package…, it's for the picked tiles if this is one of them ("Delete… (3 assets)"). It deletes each asset's own files, the same as Global asset uses (`global_assets::own_files`, gathered by `AssetBrowser::files_to_delete`): an imported model's folder and its `assets/animations/<name>/` folder, a texture set's folder, or the one file. A dialog names the files first, and says the library's copy of a global asset stays. `EditorApp::delete_assets` removes them, and the folders they leave empty below `assets/<kind>`, as one undo step that keeps their bytes (`BlobChange`, as an asset package import does), so undo puts models and pictures back too. Saving does not clear the step. What used the asset shows it missing; Asset Check lists those.
- **Save as Material** (graphics Phase 7): a Part's Explorer row menu saves its look (color, Material preset, Metalness, Roughness, glow and SurfaceAppearance; `scene::part_material_file`) as `assets/materials/<name>.material.json` (a number is added if taken), as one undo step. A part that already uses a material file saves an instance of it (`base`), with its tint as the color. It doesn't assign the file: drag it onto parts, or edit it in the Material tab. A material file changed outside the editor is read again (the watcher, `docs/editor/scripts.md`), redrawing every part using it or a material built on it; an open Material tab reads it again too, unless it has unsaved edits, which are kept.
- **The Material tab** (graphics Phase 21; `material_editor.rs`, `app/material_tab.rs`): a material tile's right-click menu has **Edit material**, which opens the file in the tab (a tab beside the Scene, which starts closed). Its list picks another of the project's materials, and **New material** makes `assets/materials/<name>.material.json` with the default material's color, metalness and roughness written out. The tab shows every value of the file and every map (image, and as each map has them its channel and inversion, strength, and DirectX switch). **Builds on** picks the `base`, and the chain under it (`Mossy → Stone → default`) says where each left-out value comes from; a base that can't be read, or bases that go around, are warned about. A value the file sets is marked (an accent dot) and has a reset button that leaves it to the base again (or the default material); a value it leaves out shows the base's, dimmed. Changing one value of a map sets only that value, keeping the base's others. **Presets** (Plastic, Metal, Glass, Wood, Stone, Fabric) set the color, metalness, roughness and opacity and keep the maps. The live preview draws the material on a sphere, a cube, or the first selected Part or MeshPart (its shape, size and `Color`), on a checkered floor, through a renderer of its own (`animation::preview::Canvas`): a small world of its own run through `scene` like the viewport's, so it draws what the viewport and Play draw; dragging turns it and the wheel zooms. **Apply to selected parts** sets their `MaterialVariant` as a dropped material does (one undo step; not during Play). Each edit is one step of the material's own undo, used while the pointer is over the tab (a slider drag or typing is one step), and is handed to `Assets` at once (`Assets::put_material_file`), so every part using the material, or a material built on it, is drawn with it in the viewport and in Play. Materials are written with the project's Save; unsaved ones count as unsaved changes.
- **The Material tab's Shader section** (graphics Phase 22): **Add shader** gives the material a surface shader, starting from `STARTER_SHADER` (its own look, scrolling); **Remove shader** goes back to the standard surface (writing `""` when the base has one), and the reset button leaves it to the base. The code box numbers its lines. Typing goes into a draft that becomes the material's `shader` once typing pauses for 0.6 s or the box loses focus, so the viewport and Play compile it once rather than on every key (each use joins the same undo step while the box keeps focus). The code is checked with `naga` as it's used (`SurfaceShader::check`), and its first error is shown under the box with its line, whose number turns red; the parts using it draw in glowing magenta checks until it's fixed. A shader from the base is shown with a note; typing in it makes it the material's own. The viewport hands each shader error to the Output window once (`ViewportOutput::shader_errors`), and keeps drawing frames while a surface shader is on screen, since it may move with time. The surface shader format is in `docs/rendering/models.md`.
- **Prefabs**: Save prefab writes the selected Workspace parts, Models and Folders (not scripts or UI) to `assets/prefabs/<name>.prefab.json` (`project::write_prefab`; a number is added if taken), as one undo step. A prefab tile's right-click menu also renames or duplicates that file, each as one undo step; undo restores the file and the tile without reopening the project. Saving does not clear these steps. Import is the one Import… (see `docs/editor/import.md`): it copies models (through the Import dialog), sounds (`assets/audio`), skies (`.exr` or `.hdr`, into `assets/sky`, then asks whether to use it as the sky, also when dropped on the window from the system), images (into the folder of the shown category: `assets/textures`, `assets/particles` or `assets/images`) and prefab files (checked first) into the project.
- **Multi-Instance undo**: `History::record_many` (through `EditorApp::change_many`) records changes to several Instances as one step, merging while the same field of the same Instances is edited.
