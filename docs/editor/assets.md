# Asset browser

The Assets panel, props, prefabs, and drag-and-drop.

- **The Assets panel** (`asset_browser.rs`) shares the bottom of the window with Output, switched by tabs above them. It shows category chips (All, Props, Models, Prefabs, Images, Textures, Audio, Particles, Animations, Skies, Global), a search box (matches the path), Toolbox, Import, Save prefab and a refresh button. Tiles show a thumbnail for images and an icon otherwise. Thumbnails are read and shrunk (to 192 px, each pixel the average of the block it covers) on three background threads (`asset_browser/thumbnails.rs`), only for tiles on screen; a tile shows its icon until its thumbnail arrives. Hovering a picture tile shows it up to 192 px with its path. **Narrow and wide** (v3 Phase 3): narrower than 360 points the panel is a list (a 24-point picture, the name ending in "…", and the kind at the right from 200 points), with the same drag, double-click, tooltip and prefab menu as a tile; wider, it's tiles. From 1300 points the chips, the Source menu, search and buttons share one row; below that the search gets its own row (with Toolbox, Import and Save prefab beside it from 520 points, otherwise on a row of their own) and the chips wrap under it. **By source** (Phase 5 of the editor brief; `asset_browser/origin.rs`): by default the grid is in a section for each place its assets came from, in this order: **Built-in** (props), **Made in Axcenity** (prefabs, materials, clips, state machines, sequences, behavior trees, data tables), **Imported** (models, textures, skies, sounds and images copied in from this computer, and the clips an animated model's import writes into `assets/animations/<model>/`), one section per **Toolbox source** (from `.axcenity/asset-sources.json`, which names each installed file or folder), and **Global assets** the project hasn't got. Nothing is guessed from names: an asset's origin is what the project records, worked out again when the files or the snapshot change. An imported model's folder takes its model's origin, so a Poly Haven model's textures stay inside it. A material whose maps all live in one texture set's folder (Toolbox **Make material**, or by hand) is listed right after that set, in the set's section, and its tooltip says "Made from the texture set …". Each section's heading shows its icon, name and count; clicking it folds the section. The **Source** menu (after the chips) shows one source only, and its **Group by source** checkbox turns the sections off for one grid, as before. The kind chips, Unused and search still apply; with a search the matches are listed one by one inside their sections, and a source's name ("poly haven") finds its assets. An open model folder shows its files under their kinds' headings as before.
- **Finding files**: the project's `assets` folder is walked again every 2 s while the panel is shown (hidden folders skipped). Kinds come from the extension and folder: models (`.gltf`, `.glb`, `.fbx`), prefabs (`*.prefab.json`), sounds, and images: particle textures in `assets/particles`, textures in `assets/textures` or `assets/models`, UI images elsewhere. A `*.texture.json` file is one texture set (shown under Textures, with its color map as the thumbnail); the images in that set's folder are not listed again. A `*.material.json` file is a material (shown under Textures, with a sphere icon; `docs/rendering/models.md`). An `.exr` or `.hdr` file anywhere is a sky (shown under Skies, with a sun icon; its thumbnail is rolled off toward white so the sun doesn't wash it out).
- **Imported models are folders** (`asset_browser/packages.rs`): each model in `assets/models` (in a folder of its own, or a file on its own) is a package holding every file in its folder and in `assets/animations/<name>/` (matched ignoring case), when that's more than one file. The grid shows the props, then a folder tile per package (a folder with the model's icon and a count of its files; "Folder · N" in the list) for any package holding something the category shows, then the files in no package. Hovering says what's in it ("1 model, 1 clip, 1 state machine, 25 textures"); a click opens it, and dragging it places its model like the model's own tile. Open, a row above the files has **All assets** (back), the folder's name and what's in it, and its files are under Model, Animation and Textures headings (the category still filters them). A search shows every matching file on its own, in or out of a folder. A folder that's gone closes.
- **The Downloaded / Imported Assets tab** (`asset_inventory.rs`, its actions `app/inventory.rs`; Phase 5 of the editor brief) lists every asset that came from outside the editor, of every kind, whether it was downloaded into the Toolbox's asset library on this computer, imported into the open project, or both. It opens from the Toolbox's view menu (**Downloaded / Imported Assets…**), the Window menu and Ctrl+K, beside Assets. Each asset is **one row** however often it was downloaded or imported: a Toolbox asset by its `provider:id` (every variant in the library, its installs and its project files on that row), an imported model's folder as one row with its textures and clips, anything else by its path. Assets made in the editor (prefabs, plain materials, clips) aren't listed; a material made from a downloaded or imported texture set is, noting the set. Rows are grouped under **Models, Textures, Materials, HDRIs, Sounds, Animations, Other**, each with its source (and licence for a Toolbox asset) and badges: **Downloaded** (in the library), **Imported** (brought into this project), **In project** (its files are there now), or **Removed from project** (installed, but its files were deleted). **All / Downloaded / Imported**, type chips with counts, a **Source** menu and a search (name, source, author, tags, paths) filter them. Clicking a row opens its details (beside the list from 640 points, below it narrower): source page, authors, licence in plain words with the commercial-use warning, **Copy credit line**, the library's variants with their sizes and age, the project's files, and **Show in Assets** (reveals the file), **Open in Toolbox** (its kind's tab, Downloaded or This project view, details open), **Open library folder** and **Remove download** (a second click confirms; deletes the library's copies and forgets them, keeping the asset's record, favourites and installs; projects keep their own copies). It reads the metadata database, this project's installs and `.axcenity/asset-sources.json`, and the Assets panel's scan and origins, again when the project's files change, every three seconds while shown, and after any Toolbox action; without an asset directory it lists only the project's assets and says why.
- **Global assets** (`global_assets.rs`): a library of assets shared by every project on the computer, in the editor's data folder (`eframe::storage_dir("Axcenity Editor")/Global Assets`; on Windows `%APPDATA%\Axcenity Editor\data\Global Assets`). The library mirrors a project: its files sit under `assets/` at the paths they have in a project, so an asset is global when the library has a file at its path. Assets are local by default. Any tile's or folder tile's right-click menu has a **Global asset** checkbox (not on built-in props); ticking it copies the asset's own files (an imported model's folder and its `assets/animations/<name>/` folder, a texture set's folder, or the one file) and every file its JSON names (a prefab's models, a glTF's buffers and images; only paths under `assets/`) into the library, replacing older copies. Unticking deletes only its own files from the library; projects that used it keep their copies, and files it merely needed stay global. Global assets have a globe badge, and the **Global** chip shows only them. Every project's panel lists the library's assets it hasn't got beside its own (thumbnails read from the library). Using one (placing, dropping, a foliage pick, a terrain layer's texture or texture set) first copies what it needs into the project at the same paths, never replacing a file the project has, and says so in Output. So projects stay self-contained: the player and exported games never read the library. The start screen's Global Assets page lists the library (see `docs/editor/shell.md`).
- **Asset Check** (v2 Phase 7; `project::check_assets`, `asset_check.rs`): File > Check Assets, Test ▸ Check Assets, the Console `check` command, or the panel's button scans the open project (every level since Phase 48: the open one as the world, the others from their files, [../project/levels.md](../project/levels.md)) and lists missing files, invalid references, import failures, and broken dependencies in one place, each with the Instance or asset file that holds the reference. A script inside an object's `SourceFile` (G2) is checked too: a missing file, one with the wrong ending, one in `scripts/` (it would also run once as a service script), and a block script that won't translate; and each file in `objects/` that no script names is listed as an **Unused file**, with Ignore as its only fix. A clean project says so. The scan does not write or delete files. A missing model still leaves the rest of the project open; this list is how those problems are seen together. The panel starts closed and opens when a check runs (View > Panels shows it). Exported games have no Asset Check.
- **Fixing what Asset Check finds** (unified Phase 22; `project::plan_fix` in `project/src/asset_fix.rs`, made by `app/asset_fixes.rs`): each finding knows where its reference is written (`Site`: an Instance's property, a prefab's property by its place in the file, a linked clip's source, a state's clip, a data table's cell (Phase 33, [../project/data-tables.md](../project/data-tables.md)), a texture a model names, or a file that fails on its own) and what kind of file it wants. Its row offers what suits it: **Use `<name>`** when the project has a file of the right kind with that name elsewhere (the one sharing the most leading folders, then the shortest path; a model's `#` pick is kept when the file name is the same); **Copy in** for a reference that's a full path to a real file outside the project; **Locate…** (a file dialog; a file outside the project is copied to the folder Import uses for its kind: `assets/models`, `assets/audio`, `assets/animations`, `assets/images` for an `Image`, `assets/particles` for a `Texture`, otherwise `assets/textures`, with a number added if a different file has the name; a `.gltf` from outside is refused, since it needs its other files, so import it); **Replace…** (a menu of the project's files of that kind); **Clear** (empties the reference; a linked clip whose model is gone is unlinked); **Delete file** for a file that fails on its own; and **Ignore**. A model's missing texture is fixed by copying the picked image to `textures/<name>` next to the model, where the model looks (it must have the extension the model asks for). **Apply to all like this (N more)** appears when other shown findings have the same path and kind ("isn't there" counts as one kind, whether the world or an asset names it); ticked, the fix covers them all. A fix is one undo step (`History::record_blobs_and_properties`: the properties set and the files rewritten, copied or deleted, by their bytes), the model cache forgets what changed (`Assets::forget`, `forget_failures`), and the check runs again. Fixes are off during Play. **Ignore** saves the finding (kind, owner, path, message) in `.axcenity/asset-check.json`, which isn't an undo step; ignored findings aren't counted, **Show ignored (N)** lists them dimmed with **Unignore**. Planning a fix writes nothing; a failed plan says why in Output.
- **Asset references** (unified Phase 70; `project::find_references`, `unused_assets` and `plan_rename` in `project/src/asset_refs.rs`, made by `app/asset_refs.rs`): a project tile's right-click menu has **Find References**, which opens a window listing everything that names it: Instances in the open world (Asset Check's properties, plus a part's `MaterialVariant` and a Tool's `TextureId`) and in the other levels, prefabs, linked clips, state machines, data table cells, material files (maps, `base`, graph images) and texture sets (any string that is the path), Lua scripts on each line that has the literal path on its own (not inside a longer path), block scripts (each text with it), copies of a prefab, and a Terrain's painted foliage. Clicking a row selects the Instance, opens the script at the line or the block script at the block, opens a material or data table in its tab, or shows the file in the panel. The **Unused** chip (after the categories) shows only the project's assets nothing names that way (a script counts if the path is anywhere in it; the files inside `assets/models` belong to their model and are left out); it's worked out when the chip goes on and after each change to the files. **Rename or Move…** (not on prefabs, which have their own Rename that relinks copies; not during Play) asks for a new name, or a path under `assets/` to move it to, keeping its ending; it moves the file and points every reference above at the new path (a model's `#` pick is kept) as one undo step (`History::record_blobs_and_properties`: the world's properties set, the files rewritten, and the file itself by its bytes), then says how many references changed. Painted foliage isn't rewritten, so a model painted as foliage is refused; a `.gltf` only renames in its folder (it names the files beside it); a taken name is refused. Undo puts the file back and every reference with it; empty folders the move left are removed. Files a model names inside itself aren't references, so moving a model's texture breaks the model.
- **Asset IDs** (roadmap L2; `assets/src/asset_id.rs`): each model, texture, sky, sound and font file under `assets/` has a stable ID, `ax://` and 26 base-32 digits, in a sidecar next to it (`ship.glb.import.json`, `{"format_version": 1, "uid": "ax://…"}`; commit them with the project). Project JSON files (materials, prefabs, clips, tables) don't get one. When a project opens, the background cooking thread gives each file without one an ID (`give_asset_ids`), gives a copy that came with its original's sidecar a new one (the file that had it last time keeps it), and remembers each path's ID in `.axcenity/asset-ids.json`. Rename or Move… takes the sidecar along and Delete… deletes it (both undoable). A file renamed or moved outside the editor with its sidecar is found again by its ID (`moved_assets`: a remembered path that's gone whose ID is somewhere now), and Asset Check suggests it for Use before any file of the same name (`project::moved_suggestion`; a model keeps its `#pick`).
- **References by asset ID** (roadmap L2; `assets/src/references.rs`): anywhere a property, prefab, material or script takes a file's path it also takes the file's ID (`ax://…`, with a model's `#pick` after it as after a path), and the ID keeps naming the file when it's renamed or moved with its sidecar, inside the editor or outside it. `Assets::resolve` turns an ID into the file's path before anything is loaded, so an ID and its path share one load and one cache entry; the IDs come from the sidecars, read once (`Assets::forget_asset_ids` rereads; the editor calls it when the watcher sees a sidecar change and after its own file writes). Paths still work everywhere, so older projects and scripts don't change. The editor writes IDs where it sets a file: a texture, lookup table, palette or sound picked in Properties, a model, sound, image, texture or particle texture dropped from the Assets panel, and each MeshPart an import makes (`EditorApp::reference_to`, which gives a just-imported file its sidecar first, `give_asset_id`). The sky, the textures an import puts in SurfaceAppearances and the project's JSON files are still named by path. Properties shows the file an ID names (its ID on hover), or "No file has this ID" when its sidecar is gone. Asset Check follows an ID to its file and reports an ID no file has as a missing file; Find References lists references by ID under the file they name; Rename or Move… leaves them as they are (the sidecar moves); a script that has a file's ID string uses it. Build Game leaves sidecars out and writes `asset-index.json` (each ID's path) at the top of the game instead, which `read_asset_index` prefers.
- **Built-in props** (`props.rs`): Floor, Wall, Stairs, Ramp, Lamp, Table, Tree and Crate, each prefab text in the source, so they work in any project.
- **Placing**: dragging a tile sets an egui drag-and-drop payload; the viewport reports where it would land (`DropTarget`: the surface under the mouse, else the ground plane, else the camera's focus) with a blue marker, and the app places it on release. Double-clicking a tile places it at the focus point. While the Terrain Studio's Foliage tool is on, clicking a prop or model tile selects it as the paint item instead of placing it (see `docs/terrain.md`). Models, prefabs and props go in the Workspace and are moved as a whole so their world bounding box rests against the surface (snapped to the move grid across it); a model becomes a MeshPart named after its file (no SurfaceAppearances: the file's own materials). A sound becomes a Sound in the part under the mouse, or the Workspace. An image sets the `Image` of the ImageLabel or button under the mouse, otherwise inserts an ImageLabel showing it. A texture sets `ColorMap` on every SurfaceAppearance of the MeshPart under the mouse. A texture set fills every map it has: on a Part (creating a SurfaceAppearance if it has none, and setting the part's `Material` to Plastic and, when the set has a color map, its `Color` to white), on every SurfaceAppearance of a MeshPart (or one new appearance per material name when it has none), or on the top TerrainLayer of a terrain (including `HeightMap`; a selected TerrainLayer is filled itself; and that layer's settings are set to suit its maps, `auto_layer_settings` in `app/texture_set.rs`: roughness 1 with a roughness map and 0.9 without, metalness 1 with a metalness map and 0 without, normal strength 1). Dropping uses the part under the mouse; double-clicking fills the selection. That apply is one undo step. Downloading a set is not. A sky, dropped anywhere in the viewport or double-clicked, asks "Use *name* as the sky?" (`app/sky.rs`) and only then sets Lighting's `SkyImage`, as one undo step with a toast; the box says when the editor's Reflection quality is Low, which shows the sky colors instead. A material file sets the `MaterialVariant` of the Part or MeshPart under the mouse (double-clicking: of every selected one) and a Part's `Color` to white, since the material carries its color (`app/material_files.rs`), as one undo step. Each placement is one undo step, and the result is selected. The maps are set at once; their images load in the background (see `docs/rendering/models.md`), so the window keeps responding and the textures appear as each finishes, with a "Loading textures 2 of 5: …" note and bar in the bottom-right corner (`toast::Busy`) until they are all in.
- **Terrain layers from project textures** (`terrain_studio/layers.rs`): an open layer in the Terrain Studio has **Use texture set**, a menu of the project's texture sets with thumbnails (`AssetBrowser::textures`; a search box from 7), which fills every map of that layer as one undo step (`TerrainAction::UseTextureSet`, the same apply as a drop). Each map's folder button is a menu of the project's textures, with **Browse files…** at the bottom for a file outside the project. Dragging a texture set from the Assets panel onto a layer's row or its open card fills that layer, and dragging a texture onto one map's row sets that map; the target is outlined while one is held over it. The project's textures are only looked up while a layer is open. Each layer in the list shows its color map's thumbnail, tinted by its `Color` (the color with an image icon until the thumbnail is read), and the open layer shows each map's thumbnail beside its file name (`StudioContext::pictures`). A layer's Roughness and Metalness scale its map when it has one (the slider says "× map"; 1 is the map as it is), as the terrain shader multiplies them, and are the value itself without one. **Auto settings** puts back what suits the layer's maps, as one undo step (`TerrainAction::AutoLayerSettings`).
- **The Toolbox tab** (`toolbox_panel.rs` and `toolbox_panel/`, its actions in `app/toolbox.rs`; the requests, records, downloads and database are the `toolbox` crate, `docs/research/asset-sources/`) finds assets online and gets them into the project. It is a dock tab beside Assets and Output, opened by the Assets panel's **Toolbox** button, the Ctrl+K search, or Terrain Studio's **From Toolbox…** (Use texture set menu), which aims it at that layer so the next texture got fills it. Kind tabs pick **Textures**, **Skies**, **Models** or **Sounds**; the **view** menu shows search results or the library's own lists, read from the metadata database so they work offline: **Favourites**, **Recent**, **Downloaded** (everything in the asset directory), **This project** (what the project's files came from, from `.axcenity/asset-sources.json`, so a project made on another computer lists them too) and each **collection**. Sources: ambientCG (v3 API, no key), Poly Haven (its catalogue searched locally; "Powered by Poly Haven" under the results, as its API terms ask) and, for sounds, Openverse (CC0, public domain and CC BY by default; **Show restricted** also lists non-commercial, no-derivatives, share-alike and unknown licences, each marked). The source menu's **All sources** (the default for Textures and Skies, which two sources have) asks every source at once, each on its own thread: their results take turns in the grid so neither buries the other, every card names its source, a result already shown isn't shown twice (assets are the same only when their source and id are, since two sources' files and licences differ), **More** asks only the sources that said they have more, and a source that fails or times out is named above the results while the others' still show (the search fails only when every source does). Chips above the results show each source's count and narrow the grid to one without searching again. The **Sounds** tab shows a licence notice above its results ("Sound assets obtained through this provider are not licensed for commercial use unless their individual source licenses explicitly permit it…"); each card still shows its own licence, so a CC0 sound isn't marked non-commercial. Its caret folds the notice to one line, remembered across restarts. A resolution (1K to 8K) and format (JPG or PNG; GLTF or FBX for models; MP3, OGG, WAV or FLAC for sounds) pick the package; if it's missing, Get takes the nearest (`toolbox::variants::choose`: the other format first, then the nearest resolution below, else above) and says why. Results show as a grid of cards as soon as the source answers; previews arrive afterwards, fetched six at a time, and a hovered card shows its preview larger. Clicking a card opens its **details drawer** (beside the results from 620 points wide, below them narrower): preview, authors and source link, the licence badge in plain words with a warning when it isn't cleared for a commercial game, size (physical size for textures, polycount for models), maps, each package with its size and whether it's already in the library, and whether the project has it; with **Get**, a **Favourite** star, **Add to collection** (or a new one), **Copy credit line** and, for a texture in the project, **Make material** (writes `assets/materials/<name>.material.json` with every map of the set and opens it in the Material tab). Get fetches the package once into the central Axcenity asset directory (`AXCENITY_ASSET_DIR`, else `%LOCALAPPDATA%\Axcenity\Assets` on Windows and `~/.local/share/axcenity/assets` on Linux; `toolbox::directory`) under `<kind>/<provider>/<id>/<package>/`, each file through a `.part` checked against its size and, when the source gives one, its MD5, and records the asset with its source and licence in `metadata.db`; any later Get of that package, from any project, copies it from there without downloading. Then: a texture goes into `assets/textures/<id>/` with `<id>.texture.json` (map files classified by the same name rules as model textures; when both normal maps are there the set uses the OpenGL one); a sky into `assets/sky/<id>_<resolution>.<ext>`, asking whether to use it; a sound into `assets/audio/<title>-<id start>.<ext>`, saying its licence in Output; a model (Poly Haven glTF with its textures, ambientCG glTF or FBX) opens the Import dialog on its file, after a check that a `.glb` is glTF and a `.gltf` names only files inside its folder. Each install gets its `ax://` ID and is recorded in the database and the project's `.axcenity/asset-sources.json`, which the Assets panel's tooltips ("From Poly Haven · CC0 · by …") and Build Game's `CREDITS.txt` read. The download runs on a background thread; **Cancel** leaves the project as it was. Failures (offline, no such package, disk) are reported in Output. **Packs** > **Import pack…** reads an `*.axcenity-pack.json` from the Toolbox website, keeps it as a collection and lists each item with its licence, size and whether it can come in; **Get all** gets its textures, skies and sounds one after another, each looked up again at its own source (a pack's addresses are never downloaded), and models one at a time from their details. **Export collection…** writes the shown collection as a pack. The asset directory is the editor's only: nothing in a built game reads it, and the player doesn't depend on the `toolbox` crate.
- **Export Package…** (unified Phase 6; `app/files/packages.rs`, format in `docs/project/packages.md`): a click picks a tile and Ctrl/Cmd+click adds or removes one (picked tiles are filled and outlined). A project tile's right-click menu has Export Package…, for the picked assets if it's one of them ("Export Package… (3 assets)", named Package) or else just that one (named after it); a model folder's menu exports every file in it. It asks where to save `<name>.axpkg`, writes the files and everything they need, and says in the Console how many went in and what they needed that isn't in the project. Global assets not copied into the project have no Export Package…. Explorer rows have Export Package… too, for parts, Models, Folders and UI in the Workspace (`tree::can_be_prefab`): the object goes in as a prefab.
- **Deleting assets**: a project tile's or folder tile's right-click menu has **Delete…** (not during Play, not on built-in props or global assets the project hasn't got). Like Export Package…, it's for the picked tiles if this is one of them ("Delete… (3 assets)"). It deletes each asset's own files, the same as Global asset uses (`global_assets::own_files`, gathered by `AssetBrowser::files_to_delete`): an imported model's folder and its `assets/animations/<name>/` folder, a texture set's folder, or the one file. A dialog names the files first, and says the library's copy of a global asset stays. `EditorApp::delete_assets` removes them, and the folders they leave empty below `assets/<kind>`, as one undo step that keeps their bytes (`BlobChange`, as an asset package import does), so undo puts models and pictures back too. Saving does not clear the step. What used the asset shows it missing; Asset Check lists those.
- **Save as Material** (graphics Phase 7): a Part's Explorer row menu saves its look (color, Material preset, Metalness, Roughness, glow and SurfaceAppearance; `scene::part_material_file`) as `assets/materials/<name>.material.json` (a number is added if taken), as one undo step. A part that already uses a material file saves an instance of it (`base`), with its tint as the color. It doesn't assign the file: drag it onto parts, or edit it in the Material tab. A material file changed outside the editor is read again (the watcher, `docs/editor/scripts.md`), redrawing every part using it or a material built on it; an open Material tab reads it again too, unless it has unsaved edits, which are kept.
- **The Material tab** (graphics Phase 21; `material_editor.rs`, `app/material_tab.rs`): a material tile's right-click menu has **Edit material**, which opens the file in the tab (a tab beside the Scene, which starts closed). Its list picks another of the project's materials, and **New material** makes `assets/materials/<name>.material.json` with the default material's color, metalness and roughness written out. The tab shows every value of the file and every map (image, and as each map has them its channel and inversion, strength, and DirectX switch). **Builds on** picks the `base`, and the chain under it (`Mossy → Stone → default`) says where each left-out value comes from; a base that can't be read, or bases that go around, are warned about. A value the file sets is marked (an accent dot) and has a reset button that leaves it to the base again (or the default material); a value it leaves out shows the base's, dimmed. Changing one value of a map sets only that value, keeping the base's others. **Presets** (Plastic, Metal, Glass, Wood, Stone, Fabric) set the color, metalness, roughness and opacity and keep the maps. The **Shading** section picks Standard, Unlit or Toon, and for Toon sets its bands, ramp image, softness, rim light and highlight, each resettable to the base (`docs/rendering/stylized.md`). The **Water** section's switch makes it a water material, and its rows set the water's deep color, clarity, waves, foam and refraction, each resettable to the base (`docs/rendering/water.md`). The live preview draws the material on a sphere, a cube, or the first selected Part or MeshPart (its shape, size and `Color`), on a checkered floor, through a renderer of its own (`animation::preview::Canvas`): a small world of its own run through `scene` like the viewport's, so it draws what the viewport and Play draw; dragging turns it and the wheel zooms. **Apply to selected parts** sets their `MaterialVariant` as a dropped material does (one undo step; not during Play). Each edit is one step of the material's own undo, used while the pointer is over the tab (a slider drag or typing is one step), and is handed to `Assets` at once (`Assets::put_material_file`), so every part using the material, or a material built on it, is drawn with it in the viewport and in Play. Materials are written with the project's Save; unsaved ones count as unsaved changes.
- **The Material tab's Shader section** (graphics Phase 22): **Add shader** gives the material a surface shader, starting from `STARTER_SHADER` (its own look, scrolling); **Remove shader** goes back to the standard surface (writing `""` when the base has one), and the reset button leaves it to the base. The code box numbers its lines. Typing goes into a draft that becomes the material's `shader` once typing pauses for 0.6 s or the box loses focus, so the viewport and Play compile it once rather than on every key (each use joins the same undo step while the box keeps focus). The code is checked with `naga` as it's used (`SurfaceShader::check`), and its first error is shown under the box with its line, whose number turns red; the parts using it draw in glowing magenta checks until it's fixed. A shader from the base is shown with a note; typing in it makes it the material's own. The viewport hands each shader error to the Output window once (`ViewportOutput::shader_errors`), and keeps drawing frames while a surface shader is on screen, since it may move with time. The surface shader format is in `docs/rendering/models.md`.
- **The Material tab's Graph view** (graphics Phase 23; `material_editor/graph.rs`, compiler in `material_graph.rs`): **Values** and **Graph** switch the tab's views. The Graph view shows the material's graph on the node-graph editor (the UI Event Graph's: wire, box-select, copy, comments, the searchable node menu) beside the preview; a material with none has **Make a graph**, which starts from its color (times its color map, if it has one) into the Material Output. A graph edit is a step of the material's undo like any value. What the graph makes is put into the file as it changes, without an undo step of its own (`MaterialStudio::sync_graphs`): new maps and parameters at once, new shader code once the graph has been still for 0.6 s, so dragging a value doesn't compile the scene's pipelines every frame; Save puts the newest code in first. Errors show on their nodes (the graph's own above it), and until they're fixed the material keeps the shader it last made; the made code is also checked with `naga`. **Remove graph** keeps the shader it made as code to edit by hand. With a graph, the Values view shows its code read-only in place of the Shader section, and only its occlusion and specular maps (the others are its graph's images). The Values view's **Parameters** section lists the parameters the material's shader reads, each marked when the material sets it: on a material with a graph, a change goes to its parameter node; on an instance, it overrides the base's value, with a reset button.
- **Prefabs**: Save prefab writes the selected Workspace parts, Models, Folders and UI (not a script on its own) to `assets/prefabs/<name>.prefab.json` (`project::write_prefab`; a number is added if taken), with the scripts inside them that have a `SourceFile`, and makes what was saved a linked copy of it, as one undo step. Placing a project prefab makes a **linked copy** (Phase 49; `EditorApp::instantiate_prefab`); built-in props aren't linked. **UI prefabs** (G5): a ScreenGui, or elements inside one, saves the same way, with its LocalScripts. A ScreenGui prefab is placed in the Workspace as a layer of its own; a prefab of screen elements (a button, a panel) goes where an inserted element would, into the Frame, PageLayout, Table or ScrollingFrame under the pointer (else the ScreenGui around it or the selection, else the first), or, with no ScreenGui at all, into a new one made in the same undo step; the element is selected. Copies keep the prefab's `Id`s, so its `#Id` rules style every copy; the rules stay in the project's stylesheets (a package doesn't carry them). A copy's own `Position`, `Size`, `Text` and the like are overrides like any other. A copy's overrides show in Properties in bold with a ↺ that reverts that one (right-click it to apply it to the prefab), and its Explorer row has **Prefab · Name ▸**: **Apply overrides to prefab (N)**, **Apply one ▸** (each overridden property), **Revert all** (keeps where its parts are: `Position` and `Orientation`), and **Unpack** (`prefab_menu.rs`, `app/prefabs.rs`). Applying writes the prefab file and brings every copy in the world up to date (`EditorApp::refresh_prefab_copies`), as one undo step that keeps the world and the file (`History::record_world_and_files`); so does each Revert and Unpack. A prefab tile's menu has **New variant**, which writes `<name> Variant.prefab.json` built on it (one undo step). Renaming a prefab relinks its copies in the open world (other levels and prefabs that nest it then show in Asset Check). Asset Check reports a copy, variant base or nested prefab whose file is missing, and a prefab that holds itself; Export Package brings a prefab's base and nested prefabs. File format: `docs/project/world.md`. A prefab tile's right-click menu also renames or duplicates that file, each as one undo step; undo restores the file and the tile without reopening the project. Saving does not clear these steps. Import is the one Import… (see `docs/editor/import.md`): it copies models (through the Import dialog), sounds (`assets/audio`), skies (`.exr` or `.hdr`, into `assets/sky`, then asks whether to use it as the sky, also when dropped on the window from the system), images (into the folder of the shown category: `assets/textures`, `assets/particles` or `assets/images`) and prefab files (checked first) into the project.
- **Multi-Instance undo**: `History::record_many` (through `EditorApp::change_many`) records changes to several Instances as one step, merging while the same field of the same Instances is edited.
