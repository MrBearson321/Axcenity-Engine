# Phase 2 Engine Benchmarking: Primary-Source Facts

Compiled 2026-11-10 for benchmarking Axcenity (Rust; Instance tree in generational arena with dynamic typed
properties; Luau via mlua; rapier3d; wgpu renderer fed by a draw list; egui editor; renet; glTF/FBX; kira).

**Provenance markers**
- `[F]` = page fetched and read during this research; claim taken from it.
- `[S]` = official URL found via search (title/snippet confirmed) but body not read; claim from established knowledge.
- `[K]` = from knowledge, not fetched. Treat as reliable-but-unverified.

## Pillar 1: Scene hierarchy and ECS

### Unreal Engine 5
- `[K]` Object model: everything reflectable derives from `UObject`; `AActor` is a placeable UObject in a `ULevel`/`UWorld`;
  behavior/data is composed via `UActorComponent` / `USceneComponent` (transform hierarchy lives in SceneComponents' attach
  tree, not Actors). Reflection is generated by UnrealHeaderTool from `UCLASS`/`UPROPERTY`/`UFUNCTION` macros, which drives
  serialization, GC, replication, Blueprint exposure, and the Details panel. https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-reflection-system
- `[K]` UObjects are garbage-collected (mark-and-sweep reachability from roots via UPROPERTY references; incremental
  reachability analysis added in UE 5.4). https://dev.epicgames.com/documentation/en-us/unreal-engine/objects-in-unreal-engine
- `[F]` **Mass Entity** (UE's ECS): Entities are lightweight IDs composing Fragments; Fragments are data-only (Transform,
  Velocity, LOD index); Tags are data-less fragments whose presence is the information; ChunkFragments attach to a chunk not
  an entity; Archetypes group entities with identical fragment composition and store them in Chunks; Processors are stateless
  logic classes; EntityQuery declares needed fragment types and yields batches; structural changes are queued in
  `MassCommandBuffer` and flushed at the end of the processing batch to avoid moving entities between archetypes mid-process;
  EntityView reads entities outside the current batch.
  https://dev.epicgames.com/documentation/unreal-engine/overview-of-mass-entity-in-unreal-engine
- `[K]` Mass is a plugin used alongside (not replacing) Actors, e.g. City Sample crowds/traffic; Mass Representation
  switches entities between ISM instances and full Actors by LOD. https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-mass-gameplay-in-unreal-engine `[S]`

**Axcenity mapping:** UPROPERTY reflection ~ Axcenity's dynamic typed properties; Unreal generates it statically at build
time (UHT), Axcenity resolves at runtime. Mass's deferred command buffer is the pattern to copy if Axcenity ever adds a
bulk-simulation layer beside the Instance tree.

### Godot 4
- `[K]` Scene graph of `Node`s owned by a `SceneTree`; a "scene" is a saved subtree (PackedScene) that can be instanced.
  Composition is by child nodes, not components. Godot explicitly does not use ECS for the scene layer.
  https://godotengine.org/article/why-isnt-godot-ecs-based-game-engine/ `[K]`
- `[K]` `Object` reflection via `ClassDB` (`_bind_methods`, `ADD_PROPERTY`), `Variant` is the dynamic value type; properties
  carry `PropertyInfo` hints used by the inspector and serializers. Very close analogue to Axcenity's dynamic properties.
  https://docs.godotengine.org/en/stable/engine_details/architecture/object_class.html `[K]`
- `[F]` **Servers architecture**: low-level servers (RenderingServer, PhysicsServer2D/3D, AudioServer). RIDs are "opaque
  handles to the server implementation", "allocated and freed manually"; RID references do not count toward resource
  refcounts. "The scene system is built on top of servers"; nodes/resources hold RIDs internally (retrievable from
  CanvasItem, Viewport, VisualInstance3D, World2D/World3D). Bypassing the scene layer helps for "tens of thousands" of
  per-frame instances because the scene layer adds overhead and memory. Servers often run asynchronously; calling a
  server function that returns a value forces a sync and can severely hurt performance if done every frame.
  https://godot-es.readthedocs.io/es/4.x/_sources/tutorials/performance/using_servers.rst.txt
  (canonical: https://docs.godotengine.org/en/stable/tutorials/performance/using_servers.html)
- `[K]` `Resource` = refcounted, serializable data object (meshes, materials, scripts, custom data) shared between nodes,
  cached by path in ResourceLoader. https://docs.godotengine.org/en/stable/tutorials/scripting/resources.html

**Axcenity mapping:** Godot's node-front-end / server-back-end split with RIDs is the closest precedent to "Instance tree ->
draw list -> wgpu" and "Instance -> rapier handle". The key Godot lesson: back-end handles are opaque, servers may be
async, and readbacks force syncs.

### Unity 6 (GameObjects)
- `[K]` `GameObject` is a container of `Component`s (always a `Transform`); scripts are `MonoBehaviour` components with
  message methods (`Awake`, `Start`, `Update`, `FixedUpdate`, `LateUpdate`) invoked via reflection-discovered callbacks.
  Serialization uses `[SerializeField]`/public fields into YAML. https://docs.unity3d.com/Manual/class-MonoBehaviour.html
- `[K]` Execution order of event functions is fixed per frame; documented in https://docs.unity3d.com/Manual/execution-order.html

### Unity 6 (DOTS / Entities)
- `[F]` Chunks are 16 KiB; components stored contiguously per chunk; each archetype has its own chunks; a chunk holds at most
  128 entities; each prefab has its own archetype; each tag component doubles possible archetype permutations;
  fragmentation example: 100,000 single-entity archetypes need >1.5 GB chunk memory "most of it empty".
  https://docs.unity3d.com/Packages/com.unity.entities@1.4/manual/performance-chunk-allocations.html
- `[K]` Systems (`ISystem` burst-compatible struct or `SystemBase`) run in `SystemGroup`s; `EntityCommandBuffer` defers
  structural changes; Baking converts authoring GameObjects in subscenes into entity data at edit time.
  https://docs.unity3d.com/Packages/com.unity.entities@1.4/manual/index.html

### Roblox
- `[K]` `DataModel` (`game`) root of an `Instance` tree; every object is an Instance with typed, reflected properties,
  `Parent`/`Children`, `Name`, `ClassName`. Services (Workspace, Players, ReplicatedStorage, ServerScriptService…) are
  top-level children. https://create.roblox.com/docs/reference/engine/classes/Instance
- `[K]` Change notification: `Instance.Changed`, `Instance:GetPropertyChangedSignal(name)`, `ChildAdded`/`DescendantAdded`,
  `AncestryChanged`, `Destroying`. Custom data via Attributes (`SetAttribute`, `GetAttributeChangedSignal`) and
  CollectionService tags. https://create.roblox.com/docs/reference/engine/classes/Instance
- `[F]` **Deferred engine events** (`Workspace.SignalBehavior`): handlers are queued and resumed at the next resumption point
  (input processing, RunService PreRender/PreAnimation/PreSimulation/PostSimulation/Heartbeat, task.wait/spawn/delay,
  BindToClose). Deferred is recommended; template places default to Deferred; re-entrancy depth limit is 10. Rationale:
  Immediate mode forces Luau to run after many small engine changes (bulk operations trigger a lot of code) and causes bugs
  like a removal event firing before the matching add; Deferred lets the engine assume the place only changes at
  resumption points. https://create.roblox.com/docs/en-us/scripting/events/deferred.md
- `[F]` **Parallel Luau Actors**: `Actor` instances are units of execution isolation; scripts under the same actor run
  sequentially, so parallelism needs multiple actors; `task.desynchronize()` / `task.synchronize()`;
  `RBXScriptSignal:ConnectParallel()`. API thread-safety levels: Unsafe, Read Parallel, Local Safe, Safe (unspecified =
  Unsafe). Cross-actor comms: `Actor:SendMessage` + `BindToMessage`/`BindToMessageParallel`; `SharedTable` (atomic updates,
  structural-sharing clones). `require()` is not allowed in a desynchronized phase. Instance writes must happen serially.
  https://create.roblox.com/docs/en-us/scripting/multithreading.md

**Axcenity mapping:** Roblox is the direct model. The deferred-events design is the most important fact here: if Axcenity
fires property-changed signals synchronously from the arena setter, it inherits the Immediate-mode problems Roblox moved
away from. Queue signals and drain them at fixed resumption points. Parallel Luau's "compute in parallel, write in serial"
plus per-API safety tags is a cheap template for mlua parallelism (separate Lua states per actor).

## Pillar 2: Asset management and streaming

### Unreal Engine 5
- `[K]` Assets are `.uasset`/`.umap` packages (serialized UObjects, editor format). Cooking converts to platform-specific
  formats; packaged builds use `.pak` or IoStore containers (`.utoc/.ucas`). https://dev.epicgames.com/documentation/en-us/unreal-engine/cooking-content-in-unreal-engine
- `[K]` Asset references: hard (`UPROPERTY` pointer, loads with owner) vs soft (`TSoftObjectPtr`/`FSoftObjectPath`, loaded
  on demand via `FStreamableManager` / `AsyncLoadPackage`); Asset Manager + Primary Asset IDs for chunking.
  https://dev.epicgames.com/documentation/en-us/unreal-engine/asynchronous-asset-loading-in-unreal-engine
- `[K]` Zen Loader / async loading thread (EDL) loads packages off the game thread. https://dev.epicgames.com/documentation/en-us/unreal-engine/zen-loader-in-unreal-engine `[S-ish]`
- `[F]` **World Partition**: single persistent level; configurable runtime grid of streamable cells (default 2D Runtime
  Hash; multiple grids can hurt performance); cells load/unload by distance from streaming sources (PlayerControllers by
  default, plus the World Partition Streaming Source component); **One File Per Actor** saves each actor to its own file so
  editing doesn't require checking out the level; Data Layers gate loading; HLOD actors built per cell; Level Instances.
  https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine
- `[K]` Hot reload: Live Coding patches C++ at runtime (see Pillar 4); assets reimport from source via the Content Browser.

### Godot 4
- `[K]` Text formats `.tscn` (scene) / `.tres` (resource), binary `.scn`/`.res`; all human-diffable text by default.
  https://docs.godotengine.org/en/stable/engine_details/file_formats/tscn.html
- `[K]` Import system: source files (PNG, glTF, WAV…) are imported into engine-native resources stored in `.godot/imported/`;
  each source gets a sidecar `<file>.import` (importer name, params, UID). Scenes reference resources by `uid://` (Godot 4.0+)
  with a path fallback, so moves don't break refs. https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/import_process.html
- `[K]` glTF 2.0 is the recommended 3D interchange format; FBX is imported natively via ufbx since Godot 4.3.
  https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html
- `[S]` Threaded loading: `ResourceLoader.load_threaded_request(path, type_hint, use_sub_threads, cache_mode)`,
  `load_threaded_get_status(path, progress)`, `load_threaded_get(path)`. https://docs.godotengine.org/en/latest/tutorials/io/background_loading.html
  and https://docs.godotengine.org/en/latest/classes/class_resourceloader.html
- `[F]` Building node subtrees off the active tree in a thread is fine; "Modifying a unique resource from multiple threads is
  not supported"; load on one thread then add on the main thread via `call_deferred`.
  https://godot-es.readthedocs.io/es/4.x/_sources/tutorials/performance/thread_safe_apis.rst.txt
- `[K]` No built-in open-world streaming system; users stream with threaded loading + VisibleOnScreenNotifier or plugins.

### Unity 6
- `[K]` AssetDatabase: every asset has a `.meta` sidecar holding a GUID + importer settings; references are GUID+fileID, so
  renames/moves don't break refs. Imported artifacts cached in `Library/`. https://docs.unity3d.com/Manual/AssetDatabase.html
- `[K]` Serialization: scenes/prefabs as YAML (Force Text); prefab variants and nested prefabs.
- `[K]` Addressables: assets addressed by key/label, packed into AssetBundles, async-loaded with `AsyncOperationHandle`,
  refcounted release, remote catalogs for content updates. https://docs.unity3d.com/Packages/com.unity.addressables@2.3/manual/index.html
- `[K]` Entities: SubScenes are baked to entity scene files and streamed asynchronously.
  https://docs.unity3d.com/Packages/com.unity.entities@1.4/manual/conversion-subscenes.html

### Roblox
- `[K]` Assets are uploaded to the Roblox cloud and referenced by numeric asset IDs (`rbxassetid://123`), moderated server
  side; places saved as `.rbxl`/`.rbxlx` (binary/XML). Packages = reusable model assets with versioning and auto-update.
  https://create.roblox.com/docs/projects/assets/packages
- `[K]` `ContentProvider:PreloadAsync` for async asset preload; meshes/textures streamed and LOD'd by the client.
- `[F]` **Instance streaming** (`Workspace.StreamingEnabled`, default on for new places, not script-settable):
  `StreamingTargetRadius` default 1024, `StreamingMinRadius` default 64 (never streams out); `ModelStreamingMode`
  Atomic (all descendants stream together) and Persistent (sent before `PersistentLoaded`, never streams out);
  `StreamOutBehavior` LowMemory (default) vs Opportunistic (recommended); `Player:RequestStreamAroundAsync()` pre-fetch.
  Physical assemblies stream in as complete units; streamed-out instances are parented to `nil` (ancestry signals fire).
  On join, Workspace instances replicate except BaseParts and atomic/persistent models.
  https://create.roblox.com/docs/en-us/workspace/streaming.md

**Axcenity mapping:** for asset identity, Godot `.import`+UID and Unity `.meta`+GUID both solve "path-based refs break on
rename" - worth adopting for glTF/FBX imports. Roblox StreamingEnabled shows that streaming should be a per-client
replication policy on the same Instance tree (renet replication + interest radius), not a separate level system.

## Pillar 3: Runtime performance and execution

### Unreal Engine 5
- `[F]` **Tasks System** (`UE::Tasks`): successor to TaskGraph, same backend scheduler and worker threads; launch returns
  `FTask`/`TTask<T>`; prerequisites (execution deps), nested tasks (completion deps), **Pipes** (serialize tasks touching a
  thread-unsafe resource without locks; cheap, usable in large numbers), task events; busy-waiting deprecated in 5.5 in
  favor of oversubscription; Insights trace channel. https://dev.epicgames.com/documentation/en-us/unreal-engine/tasks-systems-in-unreal-engine
- `[K]` Threads: Game thread, Render thread (enqueues via `ENQUEUE_RENDER_COMMAND`, runs up to one frame behind), RHI thread
  (translates to API calls), plus worker pool. https://dev.epicgames.com/documentation/en-us/unreal-engine/threaded-rendering-in-unreal-engine
- `[K]` Tick groups: `TG_PrePhysics`, `TG_StartPhysics`, `TG_DuringPhysics`, `TG_EndPhysics`, `TG_PostPhysics`,
  `TG_PostUpdateWork`; tick dependencies between actors/components; ticks can run in parallel where marked.
  https://dev.epicgames.com/documentation/en-us/unreal-engine/actor-ticking-in-unreal-engine
- `[K]` Memory: `FMalloc` abstraction with binned allocators (`FMallocBinned2/3`, mimalloc option), `FMemStack`/`TMemStackAllocator`
  frame-style allocators, `TInlineAllocator` for small containers. https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FMalloc `[K]`
- `[K]` Physics: Chaos (Epic's in-house), optional async physics with fixed timestep.

### Godot 4
- `[K]` `WorkerThreadPool` singleton: `add_task`, `add_group_task` (parallel-for), `wait_for_task_completion`; used by engine
  internally (culling, resource loading). https://docs.godotengine.org/en/stable/classes/class_workerthreadpool.html
- `[F]` Rendering thread model: Project Settings > Rendering > Driver > Thread Model = Separate runs the renderer on its own
  thread (doc warns of known bugs); physics "Run on Separate Thread" is off by default; most global singletons are
  thread-safe; "Interacting with the active scene tree is not thread-safe"; use `call_deferred`/`set_deferred`.
  https://godot-es.readthedocs.io/es/4.x/_sources/tutorials/performance/thread_safe_apis.rst.txt
- `[K]` Main loop: `_process` (per frame) and `_physics_process` (fixed, default 60 Hz `physics_ticks_per_second`).
  https://docs.godotengine.org/en/stable/tutorials/scripting/idle_and_physics_processing.html
- `[K]` Physics: Godot Physics by default; Jolt integrated as a built-in option in Godot 4.4 and made the default 3D engine
  for new projects in 4.6. https://docs.godotengine.org/en/stable/tutorials/physics/using_jolt_physics.html `[K]`
- `[K]` Memory: `Ref<>` refcounting for RefCounted/Resources; manual `free()` / `queue_free()` for Nodes; `RID_Owner`
  allocators (chunked) for server objects; no tracing GC for engine objects. GDScript uses refcounting.

### Unity 6
- `[K]` C# Job System: `IJob`, `IJobParallelFor`, `IJobChunk`/`IJobEntity`; safety system detects races on
  `NativeContainer`s at edit time; jobs scheduled with dependencies (`JobHandle`). https://docs.unity3d.com/Manual/job-system.html
- `[K]` Burst compiles a subset of C# (HPC#) via LLVM to SIMD native code. https://docs.unity3d.com/Packages/com.unity.burst@1.8/manual/index.html
- `[K]` NativeContainers with allocators `Allocator.Temp` (frame/scope, fastest), `TempJob` (≤4 frames), `Persistent`;
  Entities adds `World.UpdateAllocator` (double-rewindable). https://docs.unity3d.com/Manual/job-system-native-container.html
- `[K]` `PlayerLoop` is customizable: `PlayerLoop.GetCurrentPlayerLoop()` / `SetPlayerLoop()` to insert/remove subsystems
  (Initialization, EarlyUpdate, FixedUpdate, PreUpdate, Update, PreLateUpdate, PostLateUpdate).
  https://docs.unity3d.com/ScriptReference/LowLevel.PlayerLoop.html
- `[K]` Managed heap uses Boehm GC, incremental mode on by default. https://docs.unity3d.com/Manual/performance-incremental-garbage-collection.html

### Roblox
- `[F]` Task scheduler runs per-frame work (input, animation, physics, resuming `task.wait()`); RunService events PreRender,
  PreAnimation, PreSimulation (before physics), PostSimulation (after physics), Heartbeat; `BindToRenderStep` for strict
  ordering before render; Motor6D transform changes belong in PreSimulation.
  https://create.roblox.com/docs/en-us/performance-optimization/microprofiler/task-scheduler.md
- `[K]` Physics simulates at 240 Hz internally with adaptive timestepping (60/120/240 Hz per assembly); network ownership
  lets clients simulate their own assemblies. https://create.roblox.com/docs/physics/adaptive-timestepping `[K]`
  and https://create.roblox.com/docs/physics/network-ownership `[K]`
- `[F]` **Luau native codegen**: `--!native` (whole script) or `@native` (per function) compiles to machine code; best for
  numeric/table/buffer math with few engine API calls; type annotations (esp. `Vector3` args) enable specialization;
  getfenv/setfenv deoptimize; per-game native code memory limit; server-side and Android clients only; breakpoints
  disable native execution. https://create.roblox.com/docs/luau/native-code-gen
- `[F]` Parallel Luau (see Pillar 1). https://create.roblox.com/docs/en-us/scripting/multithreading.md
- `[K]` Luau GC: incremental mark-sweep with a pacer tuned for low pause times; no generational mode; `buffer` type for raw
  bytes. https://luau.org/performance `[K]` (Luau performance page describes the GC and interpreter optimizations)
- `[K]` Luau interpreter: hand-tuned bytecode interpreter, inline caching for table field access, fastcalls for builtins,
  `vector` value type (no allocation for Vector3). https://luau.org/performance and https://github.com/luau-lang/luau

**Axcenity mapping:** mlua can enable Luau codegen (`luau-jit` feature) - Roblox's own guidance (selective, typed,
numeric-heavy) applies. UE Pipes ~ a rayon-scoped per-resource queue. Fixed-step physics with interpolated render
(Godot/Unity/Roblox all separate physics tick from frame) is table stakes for rapier.

## Pillar 4: Developer usability and extensibility

### Unreal Engine 5
- `[K]` Modules (`.Build.cs`, UnrealBuildTool) and Plugins (`.uplugin`, can contain modules + content; loading phases).
  https://dev.epicgames.com/documentation/en-us/unreal-engine/plugins-in-unreal-engine
- `[K]` Blueprints: visual scripting compiled to bytecode on the Blueprint VM; nativization removed in UE5.
- `[K]` Live Coding: patches C++ in a running editor/game via Live++ (Ctrl+Alt+F11); limited for class layout changes.
  https://dev.epicgames.com/documentation/en-us/unreal-engine/using-live-coding-to-recompile-unreal-engine-applications-at-runtime
- `[K]` Editor extension via Slate (C++ UI), Editor Utility Widgets/Blueprints, Python editor scripting.
- `[K]` Verse (UEFN) is Epic's newer scripting language, currently Fortnite-only.

### Godot 4
- `[F]` **GDExtension**: native shared libraries loaded at runtime without recompiling the engine; same library works in editor
  and export; officially supported language is C++ (godot-cpp); community bindings include Rust (godot-rust/gdext);
  marked experimental, forward-compatible within minor versions only (4.0 extensions don't work in 4.1); must match
  engine float precision. https://docs.godotengine.org/de/4.4/_sources/tutorials/scripting/gdextension/what_is_gdextension.rst.txt
  (canonical: https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/what_is_gdextension.html)
- `[K]` `EditorPlugin` + `@tool` scripts extend the editor in GDScript; editor UI is built from the same Control nodes as
  games (editor dogfoods the engine UI). https://docs.godotengine.org/en/stable/tutorials/plugins/editor/making_plugins.html
- `[K]` GDScript: Python-like, optional static typing (typed code compiles to faster typed opcodes), script hot reload
  into running game from the editor. https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/static_typing.html

### Unity 6
- `[K]` Unity Package Manager (UPM) with `package.json`, registries, git URLs. https://docs.unity3d.com/Manual/Packages.html
- `[K]` Assembly Definitions (`.asmdef`) split scripts into assemblies to cut recompile time and enforce dependencies.
  https://docs.unity3d.com/Manual/assembly-definition-files.html
- `[K]` Editor scripting: `Editor`/`EditorWindow`/`PropertyDrawer`, UI Toolkit; domain reload on script change
  (can be disabled for faster Enter Play Mode). https://docs.unity3d.com/Manual/configurable-enter-play-mode.html

### Roblox
- `[K]` Studio plugins are Luau scripts with `plugin` global (toolbars, DockWidgetPluginGui, ChangeHistoryService for undo).
  https://create.roblox.com/docs/studio/plugins
- `[K]` Luau gradual type system (`--!strict`, `--!nonstrict`, `--!nocheck`), new type solver; types also feed native
  codegen. https://luau.org/typecheck and https://create.roblox.com/docs/luau/type-checking
- `[K]` Packages (versioned reusable assets with auto-update) and Open Cloud REST APIs (place publishing, DataStores,
  MessagingService, assets) for CI/external tooling. https://create.roblox.com/docs/cloud/open-cloud
- `[K]` Team Create collaborative editing; Script Drafts / collaborative editing for scripts.

**Axcenity mapping:** Roblox's ChangeHistoryService (plugins must record waypoints for undo) is directly relevant if
the egui editor exposes a Luau plugin API. Godot's "editor built with engine UI" mirrors egui-in-engine.

## Renderer architecture and GPU-driven rendering

### Render graphs
- **UE RDG** `[F]`: immediate-mode recording into a graph compiled/executed at `FRDGBuilder::Execute`; setup vs execute
  (pass lambdas should be side-effect-free since passes may run in parallel); transient resources allocated only for
  passes that use them; transient allocator aliases non-overlapping lifetimes (`r.RDG.TransientAllocator`); automatic
  split barriers; unused pass culling (`r.RDG.CullPasses`); async compute with auto fences; parallel command list
  recording; immediate mode for debugging. https://dev.epicgames.com/documentation/en-us/unreal-engine/render-dependency-graph-in-unreal-engine
- **Unity SRP Render Graph** `[F]`: recording stage declares texture handles, execution stage issues commands; avoids
  allocating unused resources, removes passes whose output is unused, reuses memory for compatible textures, syncs
  compute/graphics queues; on TBDR mobile merges passes into native render passes kept in tile memory; resources
  allocated just before first writer, released after last reader; internal vs imported resources. Mandatory in URP for
  Unity 6 custom passes. https://docs.unity.com/en-us/engine/6000.3/manual/render-pipelines/universal-render-pipeline/customizing-urp/render-graph/introduction.md
- **Godot** `[F]`: renderers Forward+ (clustered forward, compute-binned lights in a 3D frustum grid), Mobile (single-pass
  forward, R10G10B10A2), Compatibility (OpenGL ES 3.0 / WebGL2, no HDR). **RenderingDevice** is Godot's abstraction over
  Vulkan/D3D12/Metal at "a level similar to WebGPU" (OpenGL path does not use it). Vulkan 1.0 baseline with VMA.
  CPU occlusion culling via Embree raster in parallel. Forward+ instances identical opaque/alpha-tested objects; LODs
  generated with meshoptimizer. https://docs.godotengine.org/fr/4.5/_sources/engine_details/architecture/internal_rendering_architecture.rst.txt
- `[K]` Godot 4.x added an internal acyclic render graph in RenderingDevice (4.3) that reorders commands and auto-inserts
  barriers. https://godotengine.org/article/rendering-acyclic-graph/ `[K]`

### GPU-driven / instancing
- **UE** `[K]`: Nanite virtualized geometry (cluster hierarchy, GPU culling, software+hardware rasterization), ISM /
  HISM (instanced static mesh, hierarchical culling), GPU Scene. https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine
- **Unity** `[F]`: **GPU Resident Drawer** auto-uses BatchRendererGroup to GPU-instance GameObjects with MeshRenderer; needs
  Forward+ and compute (not GLES); SRP Batcher on; its own GPU occlusion culling; longer builds (all BRG variants kept);
  best for many objects sharing a mesh; shows as "Hybrid Batch Group". https://docs.unity3d.com/6/Documentation/Manual/urp/gpu-resident-drawer.html
  BRG manual: https://docs.unity3d.com/6/Documentation/Manual/batch-renderer-group `[S]`
- **Godot** `[K]`: `MultiMesh` / `MultiMeshInstance3D` draws many instances in one call with per-instance transform/color/
  custom data buffer; GPUParticles. https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html

### Roblox rendering and replication
- `[K]` Rendering is engine-internal (not scriptable); multiple backends (D3D11, Vulkan, Metal, OpenGL ES); automatic mesh
  LOD and instancing of identical parts; graphics quality auto-scales per device. Roblox publishes little official
  architecture docs here. Performance guidance: https://create.roblox.com/docs/performance-optimization/improve `[K]`
- `[K]` Replication: server authoritative DataModel; property changes on replicated Instances (under Workspace,
  ReplicatedStorage, etc.) are sent to clients automatically; RemoteEvent/RemoteFunction/UnreliableRemoteEvent for custom
  messages; FilteringEnabled forced (client changes don't replicate except owned physics and some character props).
  https://create.roblox.com/docs/scripting/events/remote
- `[F]` Streaming/interest management: see Pillar 2 (StreamingEnabled).

**Axcenity mapping:** a wgpu renderer fed by a draw list is roughly where Godot's RenderingServer sits; adding a small
render graph (transient textures, pass culling, auto barriers) is what all three non-Roblox engines converged on. Cheapest
GPU-driven win analogous to MultiMesh/GPU Resident Drawer: group identical mesh+material draw items into instanced draws.
