# Axcenity documentation

These pages describe the engine as it is today. The **Learn** chapters teach each part of the editor step by step; the pages under the other headings are the reference you come back to.

## Where to start

- New to Axcenity? Start with [Getting started](learn/getting-started.md), then follow the chapters in order.
- Writing code? Read [Scripting reference](reference/scripting.md), then look things up in the **API Reference**, which lists every class, property, method, event, data type and enum the engine has.
- Want to know how the engine fits together? Read [Engine architecture](reference/architecture.md).

## What the badges mean

Every page says how finished the part it describes is:

| Badge | Meaning |
|---|---|
| (none) | **Stable**: built, tested and on by default. |
| Partly built | Works, but a known part is missing, or it's off until you turn it on. The page says what's missing. |
| Experimental | Built but opt-in or still changing; expect rough edges. |

Features that don't exist aren't described as if they did: when something is planned but not built, the page says so in a **Known limits** note.

## Finding things

- **Search** at the top of the Documentation page looks through every page's titles, headings and text, and counts matches in the API Reference.
- Names in `code` such as `Part.Touched` or `task.wait()` link to their API Reference entry. Code examples have a **Copy** button.
- The same pages are on the web, and the engineering wiki in the source repository goes deeper into how each system is built.
